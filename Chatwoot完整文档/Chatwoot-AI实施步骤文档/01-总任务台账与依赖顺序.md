# 总任务台账与依赖顺序

## 1. 台账使用规则

本表是全系统的批次进度入口。AI 每完成一个任务，应更新对应批次的状态和数量；逐任务状态、证据和更新时间统一保存在 [28-AI全任务状态记录](28-AI全任务状态记录.md)。

[29-实际基线参数与量化目标冻结表](29-实际基线参数与量化目标冻结表.md)、[30-第三方真实环境与最终接口冻结表](30-第三方真实环境与最终接口冻结表.md)、[31-模块运行拓扑拆分合并灰度回退演练表](31-模块运行拓扑拆分合并灰度回退演练表.md)和[32-全局证据包索引量化评分与完成台账](32-全局证据包索引量化评分与完成台账.md)是跨批次执行附件，不增加任务数量；适用任务只有填写对应实际结果后才能计入完成。

[全系统基础层规范](../Chatwoot全系统基础层规范/README.md)是所有批次的共同前置规则，但不新增重复任务批次。ARCH、BAS、LOG、API、DATA、CONS 和 QA 分别承载基础层的设计、落地与验收证据。

统计规则：

- `总数` 是分册内必须逐项判断的任务数；
- `完成` 只统计 `DONE`；
- `排除` 只统计已批准的 `N/A`；
- `阻断` 统计当前 `BLOCKED`；
- `完成率 = (完成 + 排除) / 总数`；
- 任何 `REWORK` 或 `REOPENED` 都从完成数中移出。

## 3. 关键依赖链

### 3.1 网站客服最短闭环

FND 基础规范 → ARCH → BAS + 29 量化基线 → LOG → API → DATA → ACC → AUTH → INB → CRM → CONV → ROUTE → OPS-通知 → RPT-基础 → CONS-核心 → 32 证据登记。

### 3.2 国际渠道闭环

网站客服最短闭环 → CHAN-通用授权 → 30 Provider 实例与合同冻结 → 入站 → 出站 → 状态回调 → 失败重试 → 重新授权 → 渠道报表 → 真实回执登记。

### 3.3 AI 闭环

LOG → API → AUTH → CONV → HELP-知识内容 → AI-Provider → AI-Model → Assistant → 知识同步 → Inbox 绑定 → 回答或 Copilot → Tool → 额度、安全与失败回退。

### 3.4 插件闭环

LOG → API → AUTH → EXT-App → EXT-Hook → 授权生命周期 → 事件订阅 → 业务动作 → Webhook 投递 → 重试与停用 → 审计。

### 3.5 完整迁移闭环

LOG → DATA-映射 → 功能域可用 → 历史数据演练 → 增量同步 → 31 影子与拓扑演练 → 灰度入口 → 新旧结果对账 → 全量切换 → 回退演练 → 重新合并 → 长周期观察 → 32 证据关门。

## 4. 优先级

| 优先级 | 必须先关闭的范围 | 阻断后处理 |
|---|---|---|
| P0 | 模块边界、日志基础层、租户隔离、统一对象、核心接口、客户、会话、消息、分配、实时和迁移安全 | 立即记录阻断，继续其他无依赖 P0 |
| P1 | 国际渠道、自动化、SLA、AI、Webhook、插件和安全 | P0 关门后按依赖执行 |
| P2 | 帮助中心、Platform、企业能力、移动端和高级集成 | 不得影响 P0/P1 回归 |
| P3 | Cloud 计费、套餐、长期规模和增强能力 | 最终声明前关闭或批准排除 |

## 5. 任务选择算法

AI 每轮按以下规则选择任务：

1. 先选依赖全部完成的 P0；
2. 同优先级中选任务编号最小者；
3. 同一对象的创建、查询、更新、状态和删除应连续实施；
4. 真实第三方条件暂缺时，把实测项标为 BLOCKED，继续其合同和模拟异常项；
5. 任一基础任务重开时，暂停依赖它的未开始任务，并标记已完成依赖任务需要复验；
6. 不以任务数量最大化为目标，以形成可验收闭环为目标。

## 7. 续跑规则

AI 重新进入任务时：

1. 先读取本台账最近状态；
2. 查找 `RUNNING`，若存在先确认其实际结果；
3. 查找 `REWORK` 和 `REOPENED`，它们优先于新的 READY；
4. 复查 BLOCKED 是否已解除；
5. 核对上次完成后基线、Feature、配置和 Provider 是否变化；
6. 继续首个可执行任务，不重新实施已经有完整证据且未受影响的 DONE。

## 8. 台账禁止项

- 不允许用“基本完成”“大部分完成”替代状态；
- 不允许一个任务同时有两个状态；
- 不允许删除失败记录来提高完成率；
- 不允许把 BLOCKED 计入完成率；
- 不允许只修改总表而不更新分册任务；
- 不允许在存在未批准差异时生成 100% 完成结论。
