# 公共接口合同与统一错误实施

> 批次：API，共 15 项。基线来源：02、12、30、35、36、38、39 分册，以及[统一上下文规范](../Chatwoot全系统基础层规范/01-统一上下文身份租户权限与可用性.md)、[命令事件流程合同](../Chatwoot全系统基础层规范/03-命令查询事件流程幂等与因果合同.md)、[API 公共合同](../Chatwoot全系统基础层规范/04-API入口认证字段分页错误与兼容合同.md)、[动作能力合同](../Chatwoot全系统基础层规范/10-自动化规则宏与统一动作能力合同.md)和[目标架构](../Chatwoot模块化架构设计文档/10-可扩展简单实用可跟踪可量化可分可合目标架构.md)。

## 1. 目标

在所有业务模块之前统一身份、路径、字段、分页、错误、幂等、版本和敏感信息规则，使 Account、Widget、Public、Platform、Webhook、Provider Callback、Realtime、内部模块合同、Action Capability 和 Process Intent 不产生互相冲突的合同。任何入口进入系统后都必须形成统一上下文，并能沿请求、命令、流程、变更、事件和投递链路追踪。

## 2. 任务清单

| 编号 | 功能 | 实施步骤 | 接口与字段重点 | 完成判定 |
|---|---|---|---|---|
| API-01 | 接口类型 | 明确十类接口或能力合同的用途、身份、资源范围和调用方向 | Account、Widget、Public、Platform、Webhook、Callback、Realtime、内部模块合同、Action Capability、Process Intent | 不同身份不能混用，外部入口不能绕过模块合同 |
| API-02 | 路径版本 | 固定 `/api/v1`、`/api/v2`、`/public/api/v1`、`/platform/api/v1` 和旧入口别名 | 版本前缀、资源 ID | 路径与 30 分册逐动作索引一致 |
| API-03 | 认证与统一上下文 | 统一每类接口必需认证信息、过期和撤销行为；在入口生成并向后传递统一上下文 | api_access_token、access-token、client、uid、pubsub_token、account_id、actor、request_id、correlation_id、foundation_version、contract_version | 缺失、错误、过期、撤销均返回确定结果；上下文不在模块间丢失 |
| API-04 | Account 隔离 | 在所有资源入口校验 account_id 和对象归属 | account_id、inbox_id、contact_id 等 | 跨 Account 查询和修改均被拒绝且不泄露存在性 |

| API-06 | Query 合同 | 统一查询、筛选、排序、时间范围和布尔值表达 | page、per_page、sort、since、until、status | 未知和冲突参数处理一致 |

| API-13 | 限流 | 按身份、Account、入口和 Provider 表达容量限制 | status、retry_after、limit 相关信息 | 限流可识别、可恢复且不影响已受理任务 |

## 3. 统一上下文合同

统一上下文不是业务数据，而是每次调用都必须携带的身份、范围、版本和追踪信息。外部入口负责建立上下文，后续模块只能补充不能改写既有身份和因果关系。

| 字段 | 含义 | 产生位置 | 传递与校验规则 |
|---|---|---|---|
| foundation_version | 本次调用采用的基础层规范版本 | 系统入口或受信调用方 | 必填；不支持的版本应在进入业务前拒绝 |
| contract_version | 当前接口、能力或流程合同版本 | 调用方与入口协商 | 必填；按兼容策略处理版本差异 |
| request_id | 一次入口请求的唯一标识 | 最外层入口 | 全链路不变；重试可产生新 request_id |
| command_id | 一次业务命令的唯一标识 | 接受命令的权威模块 | 同一幂等命令复用原 command_id |
| correlation_id | 同一业务链路的关联标识 | 首个业务入口 | 子命令、事件、变更和投递全部继承 |
| causation_id | 直接触发当前动作的上一步标识 | 当前动作发起方 | 指向 request、command、intent、event 或 step |
| account_id | 数据与权限所属租户 | 认证和资源入口 | 后续模块不得通过参数覆盖 |
| actor_type、actor_id | 实际行为主体类型与标识 | 认证入口或受信系统入口 | 人员、访客、系统、自动化、宏、Provider 必须可区分 |
| source_type、source_id | 动作来源和来源实例 | 动作入口 | 区分 API、Widget、Automation、Macro、Webhook、Provider 等 |
| idempotency_key | 业务去重键 | 调用方或入口补齐 | 在规定作用域和有效期内稳定 |
| object_version | 调用方已知的对象版本 | 读取结果或前一步动作 | 用于并发校验；不适用时可为空 |
| occurred_at、deadline_at | 请求发生时间与允许完成期限 | 调用方或入口 | 使用统一时区和精度；超期不得伪装为成功 |

禁止把权限、租户或追踪信息只放在自由格式参数中。模块收到上下文后必须验证 account_id、actor、contract_version 和 deadline，并在响应、变更、事件和错误中保留 request_id 与 correlation_id。

## 4. Action Capability 合同

Action Capability 是目标模块对自动化、宏、插件、AI 和其他模块开放动作的统一目录。能力定义归目标模块所有；AUT、OPS、AIC、EXT 只查询目录并发起调用，不复制目标模块的业务规则。

### 4.1 能力定义

| 字段 | 说明 |
|---|---|
| capability_id、capability_version | 能力稳定标识与合同版本 |
| owner_module | 拥有并执行该能力的逻辑模块 |
| name、description | 面向配置者的名称和动作结果说明 |
| target_types | 允许作用的对象类型 |
| input_schema、result_schema | 输入和结果的字段、必填、可空、枚举和限制 |
| permission_requirements | 所需角色、范围、Feature、套餐和对象状态 |
| idempotency_scope | 去重键作用域、有效期和重复结果规则 |
| execution_mode | 同步命令、异步命令或多模块流程 |
| side_effects | 预期变更、事件、通知、外部调用和可补偿性 |
| availability | 启用条件、停用状态、替代版本和弃用期限 |

### 4.2 调用与结果

| 调用字段 | 说明 |
|---|---|
| capability_id、capability_version | 指定要执行的能力和合同版本 |
| invocation_id | 一次动作调用的稳定标识，供去重和跟踪 |
| target_type、target_id | 目标对象类型与标识 |
| parameters | 只包含能力合同允许的参数 |
| dry_run | 是否只执行权限、条件和影响预检 |
| idempotency_key | 防止重复执行动作和副作用 |
| context | 完整统一上下文，不允许删减身份和追踪字段 |

结果至少表达 status、request_id、command_id 或 process_id、已产生的 change_id、result、error、retryable 和 next_query_at。单模块能力直接形成目标模块命令；涉及多个权威模块时只提交 Process Intent，由 ORC 编排，不允许能力调用方直接连续修改多个模块的数据。

## 5. Process Intent 合同

Process Intent 表达“希望达成的跨模块业务结果”，而不是指定模块内部步骤。它由发起模块提交给 ORC，ORC 根据已登记流程版本执行、追踪、补偿和恢复。

| 字段 | 说明 |
|---|---|
| intent_id | 跨模块流程意图的稳定唯一标识 |
| process_type、process_version | 流程类型与合同版本 |
| account_id、actor、source | 租户、行为主体与来源 |
| goal | 要达成的业务结果，不包含内部存储动作 |
| targets | 涉及的业务对象引用 |
| parameters | 流程合同允许的业务参数 |
| correlation_id、causation_id | 全链路关联与直接原因 |
| idempotency_key | 防止重复创建同一流程实例 |
| failure_policy | 失败时停止、补偿、人工确认或部分完成规则 |
| deadline_at | 最迟完成或转入超时处理的时间 |
| required_result | 调用方必须获得的结果摘要和查询方式 |

Process Intent 受理结果返回 process_id、status 和查询入口。流程每一步只调用对应权威模块的命令或 Action Capability；AUT、OPS、AIC 和 EXT 不读取 ORC 内部状态，只读取公开流程摘要。

## 6. 跟踪字段闭环

所有改变状态的入口都必须形成以下关联链：

`request_id → command_id → process_id/step_id（如适用）→ change_id → event_id → delivery_id/invocation_id`

每个节点必须保存 correlation_id；每个下游节点必须保存 causation_id；对象结果必须保存最新 object_version。允许没有流程或外部投递，但不允许已发生的数据变更没有 command_id、change_id 和 correlation_id。查询入口必须能从任一标识返回其可见的上游原因、当前状态和下游结果。

## 7. 单接口实施顺序

每个业务接口都必须按以下顺序落地：

1. 确认接口类型和身份；
2. 校验路径资源是否存在且属于当前范围；
3. 校验角色、Inbox 成员、Feature、套餐和对象状态；
4. 解析 Query、Body、Header，区分缺失与空值；
5. 执行业务动作并建立幂等判断；
6. 返回与基线一致的字段、枚举和状态；
7. 生成本地原子 Change，并触发约定的事件、通知、报表、审计和异步任务；
8. 对失败、冲突、超时和限流返回统一错误；
9. 用列表、详情和事件验证同一结果；
10. 用无权身份和跨 Account 资源验证拒绝结果。

## 8. 必测公共场景

| 场景 | 预期 |
|---|---|
| 认证信息缺失 | 返回认证错误，不返回资源内容 |
| Token 已撤销 | 所有后续请求失效，历史会话按规则处理 |
| Account A 请求 Account B 资源 | 拒绝且不泄露资源详情 |
| ID 与 display_id 混用 | 返回明确校验或未找到结果 |
| 创建请求重复提交 | 返回同一业务结果或冲突，不重复创建 |
| 请求超时但实际已受理 | 可通过请求标识或业务标识查到最终状态 |
| 分页期间新增数据 | 无无限循环，排序和重复规则明确 |
| 响应出现未知字段 | 使用方仍能处理已知字段 |
| 状态出现未知枚举 | 不把未知状态误判为成功或失败 |
| 敏感字段校验失败 | 错误内容不回显完整敏感值 |
| Action Capability 重复调用 | 复用原命令或流程结果，不重复副作用 |
| Process Intent 已受理后超时 | 可按 intent_id 或 process_id 查询，不创建第二条流程 |
| 上下文在模块间传递 | account、actor、correlation 和 causation 不丢失、不被覆盖 |
| 从 change_id 反查 | 能定位命令、流程步骤、对象版本、事件和投递结果 |
