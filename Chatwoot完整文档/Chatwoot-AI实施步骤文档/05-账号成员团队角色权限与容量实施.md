# 账号、成员、团队、角色、权限与容量实施

> 批次：ACC，共 15 项。基线来源：[03](../Chatwoot产品与API文档/03-账号成员团队与权限API.md)、[21](../Chatwoot产品与API文档/21-角色权限与接口可用性矩阵.md)、[35](../Chatwoot产品与API文档/35-权限Feature套餐配置与兼容优先级.md)、[47](../Chatwoot产品与API文档/47-webchat开放平台安全审计与企业能力补齐规范.md)。

## 1. 目标

以 Account 作为统一数据和权限边界，完成成员、团队、角色、Inbox 范围、可用状态、容量策略和跨账号隔离，并保留 webchat 现有组织、部门、技能组和客服账号能力。

## 2. 任务清单

| 编号 | 功能 | 逐步实施 | API 与字段 | 完成判定 |
|---|---|---|---|---|
| ACC-01 | Account 查询 | 建立列表或当前账号入口；返回语言、时区、设置、状态和 Feature 摘要 | `/api/v1/accounts/{account_id}`；id、name、locale、timezone、settings | 成员只能看到加入的账号 |
| ACC-02 | Account 更新 | 校验管理权限；按可写字段更新；触发配置刷新和审计 | name、locale、timezone、settings | 更新后详情、事件和界面一致 |
| ACC-03 | Account 状态 | 定义启用、暂停、计划删除和删除完成对业务入口的影响 | status、deletion_status | 暂停账号不能继续产生未允许业务 |
| ACC-04 | 成员列表 | 返回账号内成员、角色、在线状态和可分配状态 | `/agents`；id、name、email、role、availability | 跨账号成员不混入 |
| ACC-05 | 邀请或创建成员 | 验证邮箱、角色、账号容量和重复关系；建立成员关系；发出通知 | email、name、role | 重复邀请和已有 User 行为明确 |
| ACC-06 | 更新成员 | 调整角色、可用状态和账号范围；保留变更审计 | role、availability | 权限变化立即影响后续请求 |
| ACC-07 | 移除成员 | 处理未结会话、Team、Inbox、容量和参与者关系后移除 | user_id | 历史消息保留，不能继续访问账号 |
| ACC-08 | 可分配成员 | 按账号、Inbox 成员、角色、在线状态和容量筛选 | `/assignable_agents` | 不可分配成员不会出现在候选结果 |
| ACC-09 | Team 管理 | 完成创建、列表、详情、更新、删除和自动分配开关 | `/teams`；name、description、allow_auto_assign | Team 生命周期和归属正确 |
| ACC-10 | Team 成员 | 完成成员添加、移除、批量替换和重复处理 | team_id、user_ids | 成员集合无重复，跨账号 ID 被拒绝 |
| ACC-11 | Inbox 成员 | 完成 Inbox 与成员绑定、移除和列表 | `/inbox_members`；inbox_id、user_ids | 会话可见性和分配候选同步变化 |
| ACC-12 | 标准角色 | 固定 Administrator 与 Agent 的允许范围 | role | 21 分册权限矩阵全部通过 |
| ACC-13 | 自定义角色 | 管理角色名称、权限集合、成员引用和删除限制 | `/custom_roles`；name、permissions | 未授予权限不能通过其他入口绕过 |
| ACC-14 | 容量策略 | 管理策略、成员、Inbox、会话上限和启停 | `/agent_capacity_policies`；conversation_limit | 达到上限后不再自动分配，手动动作按规则处理 |
| ACC-15 | 联合可用性 | 按身份→账号→角色→Inbox→对象→Feature→套餐→状态顺序判断 | 35 分册十二层判定 | 相同限制在所有入口返回一致结果 |

## 3. 实施顺序

1. ACC-01 至 ACC-03 建立 Account 生命周期；
2. ACC-04 至 ACC-07 建立成员关系；
3. ACC-09 至 ACC-11 建立 Team 和 Inbox 范围；
4. ACC-12、ACC-13 建立角色权限；
5. ACC-14 建立容量限制；
6. ACC-08 使用前述结果生成可分配候选；
7. ACC-15 对全部入口做联合权限收口。

## 4. 必测场景

- 同一个 User 加入两个 Account，在两个账号中拥有不同角色；
- Agent 请求管理成员、角色、Feature 和安装配置时被拒绝；
- 自定义角色只允许查看会话但不允许修改客户；
- 移除 Inbox 成员后，既有会话可见性和新分配按规则变化；
- 成员达到容量上限后自动分配跳过；
- Team 删除前存在会话或成员时按生命周期规则处理；
- Account 暂停后普通业务入口不可继续使用；
- 使用 Account A Token 和 Account B 资源 ID 不泄露资源；
- 角色、Feature 或套餐任一关闭时错误类型可区分。

## 5. 完成条件

- [ ] ACC-01 至 ACC-15 全部关闭；
- [ ] 角色矩阵、Inbox 范围和账号隔离无绕过入口；
- [ ] webchat 原有组织、技能组和客服关系已映射且无丢失；
- [ ] 成员变更能同步影响分配、会话可见性、报表和审计；
- [ ] 容量边界与分配策略能够联合工作。
