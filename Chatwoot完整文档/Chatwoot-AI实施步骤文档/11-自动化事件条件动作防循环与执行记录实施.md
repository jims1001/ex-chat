# 自动化事件、条件、动作、防循环与执行记录实施

> 批次：AUTO，共 18 项。基线来源：[自动化与宏基础合同](../Chatwoot全系统基础层规范/10-自动化规则宏与统一动作能力合同.md)、[07](../Chatwoot产品与API文档/07-自动化活动通知与模板API.md)、[18](../Chatwoot产品与API文档/18-自动化条件操作符与动作字典.md)、[33](../Chatwoot产品与API文档/33-并发原子性幂等与状态竞争规则.md)、[40](../Chatwoot产品与API文档/40-业务动作事件副作用与跨入口一致性.md)、[45](../Chatwoot产品与API文档/45-webchat自动化SLA帮助中心与通知补齐规范.md)。

## 1. 目标

把现有超时规则、机器人规则和定时动作升级为通用 Automation Rule。所有规则都以事件触发、条件树判断、顺序动作执行、幂等、防循环和可追踪结果为核心。

## 2. 任务清单

| 编号 | 功能 | 逐步实施 | 接口与字段 | 完成判定 |
|---|---|---|---|---|
| AUTO-01 | 规则创建 | 选择事件；校验条件和动作；保存为启用或停用 | `/automation_rules`；name、event_name、conditions、actions、active | 非法组合不能启用 |
| AUTO-02 | 规则列表详情 | 按 Account 返回规则、状态、事件和更新时间 | rule id、active | 不泄露跨账号规则 |
| AUTO-03 | 规则更新复制删除 | 更新时重新校验；复制生成新规则；删除处理运行任务 | conditions、actions | 运行中版本和新版本边界明确 |
| AUTO-04 | 会话创建事件 | 在主对象完成后形成 conversation_created 触发上下文 | conversation、contact、inbox | 同一次创建只触发一次 |
| AUTO-05 | 会话更新事件 | 仅在目标字段变化时触发，提供变化前后值 | changed_attributes | 自动化自身更新不会无限重复 |
| AUTO-06 | 消息创建事件 | 区分 incoming、outgoing、private 和 activity | message_type、content_type | 私有和活动消息按规则参与 |
| AUTO-07 | 时间事件 | 按等待时长、最后活动、SLA 或延后到期产生触发 | timestamps、timezone | 时区、重启和重复扫描不重复执行 |
| AUTO-08 | 条件树 | 支持全部满足、任一满足和嵌套限制 | conditions、logical_operator | 顺序不改变判断结果 |
| AUTO-09 | 内置字段条件 | 支持状态、Inbox、Team、成员、标签、优先级、语言等 | attribute_key、values | 字段与事件类型匹配 |
| AUTO-10 | 自定义字段条件 | 读取 Contact 或 Conversation 自定义定义并按类型比较 | attribute_model、attribute_key | 未定义、停用和类型错误明确 |
| AUTO-11 | 操作符 | 实施等于、不等于、包含、不包含、存在、范围和时间类操作符 | filter_operator | null、空值和集合语义符合 18 分册 |
| AUTO-12 | 统一动作能力 | 把状态、优先级、分配、Team、标签、静音等映射到目标模块 Action Capability 和同一业务 Command | capability_id、version、action_params | 不在 AUT 重复业务规则，权限和状态与手工入口一致 |

| AUTO-14 | 延迟和外部动作 | 执行延迟、HTTP 调用、Bot 或集成动作 | delay、endpoint、hook | 超时、重试和最终状态可追踪 |

| AUTO-16 | 幂等与防循环 | 用规则、事件、对象和版本形成执行键；限制递归深度 | execution_key、depth | 自身副作用不会无限触发 |
| AUTO-17 | 执行记录 | 记录匹配结果、每个动作、耗时、失败和重试 | execution_id、status、errors | 可从业务对象定位规则执行 |
| AUTO-18 | 启停与回放 | 启用前验证；停用阻止新执行；按授权范围回放历史事件 | active、event_id | 回放不会重复已成功的不可逆动作 |

## 3. 单次规则执行流程

1. 接收标准业务事件；
2. 确认规则启用、版本和 Account；
3. 计算执行幂等键并检查是否已处理；
4. 建立只读触发上下文；
5. 按条件树求值并保存匹配明细；
6. 不匹配则以 skipped 终止；
7. 按顺序执行动作，每项记录开始、结果和副作用；
8. 对可重试失败按规则重试，不可重试失败立即记录；
9. 检查递归深度和重复事件，阻止循环；
10. 形成成功、部分成功、失败或取消终态；
11. 更新审计、指标和诊断信息；
12. 向后续相同事件提供执行来源，继续防循环。

## 4. 必测规则

- 新会话来自指定 Inbox 时自动分配 Team；
- 客户消息包含指定内容时添加标签；
- 高优先级会话超过等待时间后通知管理者；
- 状态变更为 resolved 后发送 CSAT；
- 自定义字段为空、缺失、空字符串和不同类型；
- 一个动作修改的字段再次满足同一规则；
- 两条规则互相修改状态形成潜在循环；
- 时间扫描重启、重复和跨时区；
- 外部动作超时但实际已经成功；
- 规则停用、更新和删除与运行任务并发。

## 5. 完成条件

- [ ] AUTO-01 至 AUTO-18 全部关闭；
- [ ] 18 分册全部适用事件、条件、操作符和动作有对应能力；
- [ ] 规则执行有幂等、防循环、顺序和失败记录；
- [ ] 所有动作均进入 Action Capability Registry，并与 Macro、AI、插件和手工入口复用相同 Command；
- [ ] 自动化动作与手工入口产生相同主对象和副作用；
- [ ] webchat 既有超时和机器人规则已迁移且结果无回退。
