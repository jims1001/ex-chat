## 1. 目标

让故障行为和并发结果成为所有功能的一部分，而不是验收末期补丁。每项业务都必须区分受理与完成、重复与重试、暂时失败与永久失败，并保证主对象和全部副作用最终一致。相同业务必须在 U1 至 U5 组合运行和逻辑模块独立拆分运行时产生一致结果。

## 2. 异步与幂等任务

| 编号 | 功能 | 逐步实施 | 完成判定 |
|---|---|---|---|
| CONS-01 | 异步任务公共状态 | 统一 queued、running、succeeded、failed、cancelled 等摘要和时间 | 所有异步入口终态可查询 |
| CONS-02 | 任务进度 | 记录总量、已处理、成功、失败、跳过和当前阶段 | 进度单调且不超过总量 |
| CONS-03 | 失败明细 | 记录对象、步骤、错误、是否可重试和补偿结果 | 单条失败可定位，不只给总错误 |
| CONS-04 | 重启与取消 | 定义从何处继续、哪些动作复用、取消影响哪些未开始项 | 已成功不可逆动作不重复 |
| CONS-05 | 创建幂等 | 客户、会话、消息、任务、支付和回调使用稳定去重键 | 重复请求不重复主对象 |
| CONS-06 | 结果未知 | 超时后先按请求或业务标识查询，再决定补偿 | 不盲目重复创建和发送 |
| CONS-07 | Webhook 幂等 | 入站和出站都记录 event/delivery 标识和尝试次数 | 重复事件不重复业务动作 |

## 4. 异常、限流与副作用任务

| 编号 | 功能 | 逐步实施 | 完成判定 |
|---|---|---|---|
| CONS-16 | 错误分类 | 区分认证、权限、校验、冲突、限流、外部、暂时和永久失败 | 同类错误跨模块表达一致 |
| CONS-17 | 重试策略 | 只对允许错误重试；采用延迟、上限和随机偏移 | 不形成重试风暴 |
| CONS-18 | 限流 | 按身份、Account、入口和 Provider 限制并返回恢复提示 | 已受理任务不因后续限流丢失 |
| CONS-19 | 故障隔离 | 通知、Webhook、Bot、报表等副作用失败不错误回滚主消息；分别验证组合运行单元故障和独立模块故障 | 主对象和失败副作用均可追踪，故障边界不因部署形态改变 |
| CONS-20 | 补偿入口 | 为导入、发送、同步、迁移、支付和删除提供安全补偿 | 补偿不制造第二次副作用 |
| CONS-21 | 副作用字典 | 按 40 分册落实每个动作的事件、通知、Webhook、报表和审计；数据变化必须先产生本地原子 Change | 主动作完成后可观察集合完整，每次变化能由 change_id 关联 |
| CONS-22 | 副作用顺序 | 冻结主对象、事件、通知和外部投递的可观察顺序 | 使用方不见到永久悬空引用 |
| CONS-23 | 跨入口与部署一致性 | Account、Widget、Public、Provider、Bot、Automation、Macro 执行同动作，并在组合部署与拆分部署重复执行 | 最终对象、权限、Change、事件和副作用相同 |
| CONS-24 | 列表详情导出一致 | 在两种部署形态下核对同一字段在列表、详情、搜索、事件、报表和导出的含义 | 允许延迟后可对账，拓扑变化不改变字段语义 |
| CONS-25 | 故障演练 | 覆盖网络、Provider、存储、Local Journal、集中账本、异步任务、缓存、模块拆分或合并切换和节点重启 | 恢复后无丢失、重复、日志缺口、拓扑差异和永久错误状态 |

## 5. 横切实施方式

CONS 任务不是一次性完成。AI 应对每个业务任务执行：

1. 正常单请求；
2. 完全相同请求重复；
3. 同一对象并发冲突；
4. 主动作前失败；
5. 主动作完成后响应超时；
6. 外部系统接受后回调延迟；
7. 状态回调重复和乱序；
8. 异步任务运行中重启；
9. 副作用单独失败；
10. 恢复后列表、详情、事件、报表、本地待投递和集中账本对账。

## 6. 组合部署与拆分部署一致性验证

同一验收数据集必须先在默认 U1 至 U5 组合运行单元执行，再把选定逻辑模块独立拆分后重复执行。除地址、运行单元标识和允许的时延差异外，业务合同与结果不得变化。

| 验证面 | 组合部署证据 | 拆分部署证据 | 一致性判定 |
|---|---|---|---|
| 单模块命令 | 请求、命令、对象版本、Change 和响应 | 使用同一合同重复执行 | 字段、状态、权限和副作用一致 |
| 跨模块 Process Intent | 流程步骤、命令、补偿与终态 | ORC 通过远程模块合同执行 | 流程语义、步骤结果和终态一致 |
| 事件投递 | event_id、顺序、重试和投递结果 | 拆分后重新取证 | 事件类型、因果链和最终投递一致 |
| 幂等 | 重复请求、重复回调、重复动作调用 | 使用相同去重条件重复 | 主对象、命令、流程和副作用均不重复 |
| 对象与 Change | object_version、change_id、source_sequence | 拆分后连续记录 | 不丢失、不倒退、无不可解释重复 |
| 权限与租户 | 正常、无权和跨 Account 场景 | 同一身份集重复 | 允许和拒绝结果完全一致 |
| 故障隔离 | 停止组合单元内的依赖能力 | 停止独立模块 | 主动作、降级、重试和恢复语义一致 |
| 自动化与宏 | Action Capability 调用和执行记录 | AUT、OPS 或目标模块拆分后重放 | 条件、动作、幂等和执行结果一致 |
| Provider 回调 | 正常、重复、乱序、延迟回调 | EXT 或目标模块拆分后重放 | 对象状态和外部副作用一致 |
| 查询投影 | 列表、搜索、报表、导出版本 | SRH、RPT 拆分后等待约定时效 | 达到同一权威版本且内容一致 |
| 指标 | 业务量、成功率、错误、延迟和积压 | 同场景采集同口径指标 | 指标定义相同，数值差异可由运行开销解释 |
| 迁移切换 | 拆分前对象与 Change 水位 | 影子、灰度、切换和回退记录 | 切换期间单一权威，前后业务差异为零 |

### 6.1 执行顺序

1. 冻结 foundation_version、合同版本、测试身份、输入数据、时钟范围和量化阈值；
2. 在默认 U1 至 U5 部署执行全部场景，保存响应、对象、Change、事件、流程、投影和指标证据；
3. 优先拆分 AIC、EXT、AUT、OPS、ORC、AUD、RPT、SRH 等边界清晰模块，再覆盖一个核心业务模块；
4. 不改变外部请求、Action Capability 或 Process Intent，重复执行同一场景；
5. 按 request_id、command_id、correlation_id、change_id 和业务对象标识逐项比较；
6. 检查模块间只通过公开合同通信，直接跨模块存储访问必须为零；
7. 对差异建立问题记录，修复后从组合部署和拆分部署两侧同时回归；
8. 将独立模块重新合并到默认运行单元，再执行一次核心场景，证明可分也可合。

## 7. 完成条件

- [ ] CONS-01 至 CONS-25 全部关闭；
- [ ] 31、33、36、40 分册适用场景均映射到业务任务证据；
- [ ] 所有异步操作有终态、失败明细和补偿；
- [ ] 所有创建和回调有幂等策略；
- [ ] 核心状态竞争和额度竞争结果确定；
- [ ] 主对象与副作用失败隔离且最终可对账；
- [ ] 故障演练恢复后无丢失、重复或不可解释状态。
- [ ] 默认 U1 至 U5 与选定模块拆分部署使用同一合同和同一验收数据集；
- [ ] 两种部署形态的权限、对象、Change、事件、流程、投影和业务指标语义一致；
- [ ] 组合部署中的直接跨模块存储访问为 0；
- [ ] 拆分、回退和重新合并后的业务结果差异为 0。
