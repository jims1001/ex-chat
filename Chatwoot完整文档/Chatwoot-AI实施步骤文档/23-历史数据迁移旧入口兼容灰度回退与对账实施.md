# 历史数据迁移、旧入口兼容、灰度、回退与对账实施

> 批次：MIG，共 22 项。基线来源：[32](../Chatwoot产品与API文档/32-完整系统一致性还原目标与基线.md)、[34](../Chatwoot产品与API文档/34-字段默认空值唯一约束与数据生命周期.md)、[41](../Chatwoot产品与API文档/41-第三方API版本能力漂移与历史兼容.md)、[48](../Chatwoot产品与API文档/48-webchat迁移兼容与完整验收规范.md)、[数据所有权与变更追踪规范](../Chatwoot全系统基础层规范/05-数据所有权原子一致性与变更追踪.md)、[可靠性规范](../Chatwoot全系统基础层规范/08-可靠性故障隔离限流监控恢复与容量.md)、[模块变更治理规范](../Chatwoot全系统基础层规范/09-模块接入基础清单变更治理与验收.md)、[目标架构](../Chatwoot模块化架构设计文档/10-可扩展简单实用可跟踪可量化可分可合目标架构.md)和[31-模块拓扑演练表](31-模块运行拓扑拆分合并灰度回退演练表.md)。

## 1. 目标

将 webchat 历史账号、客户、会话、消息、工单、质检和配置安全迁移到统一对象；支持 26 个逻辑模块在 U1 至 U5 之间拆分、合并和替换；迁移期间保持旧入口可用。通过影子运行、灰度读取、单一权威写入、Change 对账、切换、回退演练和长周期观察，避免丢失、重复、错链、双主写或业务停顿。

## 2. 迁移准备任务

| 编号 | 功能 | 逐步实施 | 完成判定 |
|---|---|---|---|
| MIG-01 | 范围与拓扑冻结 | 固定迁移 Account、时间范围、对象类型、排除项、停机窗口、源模块、目标模块、源运行单元和目标运行单元 | 每个对象、时间段、写入权威和拓扑变化都有明确范围 |
| MIG-02 | 对象与所有权映射 | 按 48 分册建立旧对象到统一对象的映射，并标明迁移前后 owner_module、权威对象、外部引用和可重建投影 | 没有未解释的一对多、多对一或共同所有权 |
| MIG-03 | 字段映射 | 逐字段确定复制、转换、默认、空值、派生、舍弃和敏感处理 | 每个旧字段都有目标处理 |
| MIG-04 | 状态映射 | 映射客服、会话、消息、工单、质检、渠道和机器人状态 | 未知和历史状态有保留策略 |
| MIG-05 | 标识映射 | 保存 legacy_id、target_id、display_id、source_id 和 external_id 关系 | 旧链接与新对象可相互定位 |
| MIG-06 | 唯一与合并 | 冻结客户、渠道身份、会话和消息去重键及冲突优先级 | 重复数据不被静默覆盖 |
| MIG-07 | 依赖顺序 | 按 Account→成员→Inbox→客户→会话→消息→运营和扩展执行 | 子对象不会早于父对象进入 |
| MIG-08 | 数据、Change 与指标快照 | 记录迁移前总量、关系数、状态分布、附件量、关键哈希、object_version、Change 水位、source_sequence 和业务指标 | 可作为迁移、拆分、合并和回退后的对照基线 |

## 3. 执行与兼容任务

| 编号 | 功能 | 逐步实施 | 完成判定 |
|---|---|---|---|
| MIG-09 | 试迁移与拓扑演练 | 使用代表正常、边界、历史和异常数据的小范围 Account，分别演练对象迁移、模块拆分和重新合并 | 全部问题进入映射、拓扑或差异表 |
| MIG-10 | 全量基础迁移 | 分批迁移冻结时间点之前的对象，记录逐批进度和错误 | 可重启且已成功批次不重复 |
| MIG-11 | 附件迁移 | 校验文件存在、大小、类型、权限、地址和安全状态 | 无孤立附件、错权限或不可读文件 |
| MIG-12 | 关系迁移 | 验证成员、Team、Inbox、ContactInbox、会话、工单和质检关联 | 无跨 Account 错链 |
| MIG-13 | Change 增量与影子同步 | 从冻结水位后按 Change 和 source_sequence 捕获新增及变化，幂等回放到影子目标 | 切换前对象版本、Change 和投影差异收敛到允许窗口 |
| MIG-14 | 旧入口别名 | 旧接口继续使用旧字段和状态，对内映射统一业务动作 | 新旧入口不产生两个主对象 |
| MIG-15 | 旧链接与标识 | 旧会话、客户、工单和附件链接安全跳转或查询 | 历史入口不因 ID 变化失效 |
| MIG-16 | 入口与拓扑对账 | 同一动作从新旧入口、组合部署和拆分部署执行，比较权限、对象、Change、事件、通知、报表、审计和指标 | 未批准业务差异为 0 |
| MIG-17 | 影子运行与灰度读取 | 目标模块先只读影子回放，再按 Account、Inbox、对象范围或流量比例切换查询来源，保留即时回退开关 | 读取切换不丢记录、不重复展示且不改变写入权威 |
| MIG-18 | 灰度写入与单一权威 | 任何时刻只保留一个写入权威；旧入口、影子实例和新入口都路由到该权威，禁止双权威写入 | 任一业务动作只提交一次，写入权威可明确证明 |

## 4. 切换、回退与收口任务

| 编号 | 功能 | 逐步实施 | 完成判定 |
|---|---|---|---|
| MIG-19 | 模块与入口切换 | 收敛增量，确认 Change 水位，切换命令路由和写入权威，再验证核心闭环 | 客户消息和客服处理不中断，切换点可追踪 |
| MIG-20 | 含新增 Change 的回退 | 恢复原路由前，先把切换后产生的 Change 顺序回放到原权威，再切换读取和写入 | 回退不丢失切换后的业务、版本和审计链 |
| MIG-21 | 迁移后多层对账 | 比较总量、关系、状态、内容、附件、object_version、Change、事件、指标、报表、审计和业务闭环 | 差异均已修正、归一化或批准，关键差异为 0 |
| MIG-22 | 旧入口或旧模块退役 | 观察期通过后依次只读、告警、关闭写入、关闭调用和最终停用，保留映射、审计、替代合同和恢复条件 | 无依赖方继续使用，回退期限和恢复条件明确 |

## 5. 模块拆分流程

1. 冻结 foundation_version、模块合同、数据所有权、源目标拓扑和量化目标；
2. 记录源模块的对象总量、版本水位、Change 水位、事件积压和业务指标；
3. 建立目标模块的独立边界，先迁移历史对象、Local Change Journal 和必要凭证引用；
4. 目标模块进入影子模式，只接收 Change 回放和镜像查询，不接受权威写入；
5. 使用同一请求在源结果和影子结果之间持续对比，差异必须可解释并低于切换门槛；
6. 小范围查询先切到目标模块，写入仍由源模块唯一负责；
7. 收敛增量并记录最终水位，短时保护写入，切换命令路由和写入权威；
8. 按 Account、Inbox、对象范围或流量比例扩大灰度，持续核对 Change、事件、投影和指标；
9. 稳定观察期结束后关闭源模块写入能力，但保留限定期限的回退条件；
10. 退役完成后更新模块清单、运行单元清单、依赖矩阵、能力目录和证据索引。

## 6. 模块合并流程

1. 确认被合并模块的外部合同、owner_module 和逻辑边界保持不变；
2. 冻结合并目标运行单元、资源额度、故障边界、限流和容量阈值；
3. 在目标运行单元影子装载模块并同步历史数据与 Change，不承接权威写入；
4. 对比合并前后的命令、Process Intent、事件、查询、指标和审计结果；
5. 以单一写入权威切换模块路由，不因同一运行单元而开放跨模块直接数据访问；
6. 观察故障隔离、资源争用、容量和恢复目标，超过阈值立即回退；
7. 通过后停用原运行位置，保留逻辑模块的独立标识、Journal、指标和再次拆分能力。

## 7. 影子、灰度、切换与回退规则

| 阶段 | 读取 | 写入 | 必须取得的证据 | 退出条件 |
|---|---|---|---|---|
| 影子 | 正式结果来自源；目标只比较 | 仅源权威写入 | 对象版本、查询、事件、指标差异 | 差异达到基线门槛 |
| 灰度读 | 部分范围读取目标，异常即时回源 | 仍仅源权威写入 | 命中范围、读差异、延迟、错误和回退结果 | 读差异为 0 且指标达标 |
| 灰度写 | 部分命令路由到新权威 | 切换范围内仅目标权威写入 | 路由版本、切换 Change 水位、幂等和副作用 | 写入与 Change 对账通过 |
| 全量切换 | 目标为正式读取 | 仅目标权威写入 | 全业务闭环、积压、容量和恢复证据 | 稳定观察期通过 |
| 回退 | 恢复源读取 | 先回放新增 Change，再将源恢复为唯一权威 | 回放水位、对象版本、路由切换和回归结果 | 切换后业务无丢失 |

禁止在迁移中建立“双写后再择优”的两个权威。为验证而产生的镜像调用必须是 dry_run、只读或写入隔离的影子空间，不能触发真实消息、通知、Webhook、计费和其他外部副作用。

## 8. 数据迁移顺序

1. 安装配置、Feature 和 Account；
2. User、AccountUser、Team、Role 和成员；
3. Inbox、渠道配置、成员和工作时间；
4. Company、Label、自定义字段定义；
5. Contact 和 ContactInbox；
6. Conversation、Assignment、Participant 和状态时间线；
7. Message、Attachment、已读位置和发送状态；
8. 快捷回复、Automation、Campaign、Notification、SLA；
9. Portal、Category、Article 和知识；
10. Assistant、Bot、Integration、Webhook；
11. 工单、质检、申诉、报表定义和增强对象；
12. 审计、统计派生信息和旧标识映射。

## 9. 对账层次

| 层次 | 核对内容 |
|---|---|
| 数量 | 每 Account、对象类型、状态和时间段总量 |
| 唯一 | 重复客户、渠道身份、display_id、外部消息 ID |
| 关系 | 父子对象、成员、Team、Inbox、客户、会话和消息链 |
| 内容 | 文本、扩展字段、附件、时间、发送者和方向 |
| 状态 | 会话、消息、渠道、工单、质检和异步终态 |
| 权限 | 角色、Inbox 范围、客户侧身份和安装管理范围 |
| 副作用 | 实时事件、Webhook、通知、报表和审计 |
| 业务 | 客户发消息、客服回复、转接、解决、评价和搜索 |
| Change | change_id、module_id、object_version、source_sequence、correlation_id 连续且唯一 |
| 拓扑 | 组合与拆分部署的合同、权限、对象、事件、指标和审计语义 |

## 10. 完成条件

- [ ] MIG-01 至 MIG-22 全部关闭；
- [ ] 历史对象、字段、状态和标识均有映射；
- [ ] 全量、增量、灰度、切换和回退均完成演练；
- [ ] 总量相等之外，关系、内容、权限和副作用也通过；
- [ ] 新旧入口相同动作结果一致；
- [ ] 旧入口退役不再有实际依赖；
- [ ] 迁移后长周期观察未出现新增差异。
- [ ] 模块拆分、重新合并、影子运行、灰度切换和含新增 Change 的回退均有实际演练证据；
- [ ] 迁移全程任一业务范围只有一个写入权威；
- [ ] 切换前后对象版本、Change、事件、投影、指标和审计均可连续对账；
- [ ] 退役旧模块或旧入口前，替代合同、依赖清零、恢复期限和责任范围均已确认。
