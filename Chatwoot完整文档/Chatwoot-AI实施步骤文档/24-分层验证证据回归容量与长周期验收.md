## 1. 目标

对每个任务执行字段、权限、流程、副作用、并发、异常、兼容、容量和长周期验证，并形成可复核证据包。除功能验收外，必须以实际结果分别证明架构达到可扩展、简单实用、可跟踪、可量化、可分和可合六项目标，而不只是某次请求成功或文档声明完成。

## 3. 六项目标架构验收矩阵

| 架构目标 | 必须执行的验收 | 实际证据 | 量化通过条件 |
|---|---|---|---|
| 可扩展 | 新增一个 Action Capability、一个 Provider 或插件适配，并验证启用、停用、版本升级和失败隔离 | 能力注册、安装配置、调用结果、变更、事件、指标、审计和卸载结果 | 能力和扩展登记覆盖率 100%；未登记私有入口 0；不改变其他模块权威数据 |
| 简单实用 | 使用 U1 至 U5 完成客户发起、客服处理、自动化或宏、通知、报表和审计；验证单模块动作直接执行 | 五个运行单元清单、完整业务证据、实际运行和运维指标 | 5/5 运行单元可完成核心闭环；单模块动作不经过 ORC；BAS 中数值目标全部达标 |
| 可跟踪 | 对正常、自动化、宏、插件和失败流程从任一标识正反向查询 | request_id、command_id、process/step、change_id、event_id、delivery/invocation 和对象版本证据 | 实际数据变化 change_id 覆盖率 100%；correlation_id 覆盖率 100%；断链 0 |
| 可量化 | 对模块、运行单元、能力、流程和外部依赖采集业务、质量、延迟、错误、积压、容量、恢复和成本指标 | 指标目录、仪表板、阈值、告警、容量结果和观察窗口 | 关键指标覆盖率 100%；未处理阈值失败 0；所有环境数值均来自 BAS |
| 可分 | 独立拆分 AIC、EXT、AUT、OPS、ORC、AUD、RPT、SRH，并至少拆分一个核心业务模块，运行同一验收集和故障恢复 | 拆分清单、依赖图、路由、数据迁移、Change 对账、容量和恢复证据 | 直接跨模块存储访问 0；依赖环 0；合同通过率 100%；RTO/RPO 达到 BAS |
| 可合 | 将已拆分模块重新并入 U1 至 U5，在不改外部合同和数据语义的情况下重复验收 | 合并记录、同场景对照、对象、Change、事件、指标和故障结果 | 组合/拆分案例通过率 100%；未批准业务差异 0；逻辑数据所有权不变 |

六项目标必须分别给出“案例—执行时间—环境—实际结果—量化指标—证据位置—结论”。设计文档、空表、模拟结果或尚未执行的计划不能作为通过证据。

## 4. 单个验收案例格式

| 字段 | 内容要求 |
|---|---|
| case_id | 全局唯一 |
| task_id | 对应实施任务编号 |
| baseline | 引用功能基线章节 |
| preconditions | 版本、Feature、角色、Account、对象和外部状态 |
| action | 业务动作、接口、身份和必要字段 |
| expected | 状态、对象、错误、事件和副作用 |
| actual | 实际结果摘要 |
| normalization | 动态时间、ID 等归一化规则 |
| evidence | 请求结果、数据、事件、界面和第三方回执索引 |
| status | pass、fail、blocked 或 approved_difference |
| cleanup | 数据清理或保留说明 |

## 5. 证据包最低组成

- 基线版本与配置快照；
- foundation_version、26 个逻辑模块清单、无循环依赖图和 U1 至 U5 实际运行清单；
- 任务和案例索引；
- 认证身份、角色和资源范围说明；
- 请求字段与响应结果；
- 对象变化前后快照；
- 实时事件和 Webhook 结果；
- 通知、报表和审计结果；
- 异步任务进度与终态；
- 第三方授权、入站、出站和最终回执；
- 并发与故障恢复结果；
- change_id、对象版本、本地待投递、集中账本、摘要链和敏感字段检查结果；
- 迁移前后对账；
- Action Capability、Process Intent、模块拆分、重新合并、影子运行、灰度切换和回退证据；
- 六项目标的量化结果、阈值、观察窗口、差异和最终结论；
- 29 分册全部冻结目标的实际测量结果、30 分册逐 Provider 真实回执、31 分册三种拓扑对照结果；
- 32 分册包含 482 个唯一任务编号的全局证据索引；
- 失败、阻断和批准差异登记；
- 最终汇总和有效日期。

## 6. 结果定义

| 状态 | 定义 |
|---|---|
| pass | 所有预期结果和证据满足 |
| fail | 实际结果与基线不一致，且未获批准 |
| blocked | 外部条件缺失，尚不能得出通过结论 |
| approved_difference | 差异已记录影响、批准和有效期 |

一个案例的主请求成功，但副作用、最终状态或权限验证缺失时，仍不能标为 pass。

## 7. 回归触发

以下变化必须重开受影响的 QA 任务：

- 目标版本或部署形态变化；
- foundation_version、模块边界、U1 至 U5 组合关系或依赖方向变化；
- Feature、安装配置、套餐或权限变化；
- 公共对象、状态、错误或接口字段变化；
- Provider 版本、Scope、Token、Webhook 订阅或模型变化；
- 数据迁移规则和唯一规则变化；
- 自动化、Bot 或插件动作变化；
- Action Capability、Process Intent、拆分、合并、影子或路由切换规则变化；
- 安全、幂等、并发、限流或重试规则变化；
- Change Registry、变更合同、字段分级、保留、完整性或日志查询权限变化；
- 证据超过批准有效期。
