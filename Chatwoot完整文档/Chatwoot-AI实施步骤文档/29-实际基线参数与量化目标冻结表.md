# 实际基线参数与量化目标冻结表

> 本分册是 BAS-01、BAS-04、BAS-08、BAS-11、QA-19、QA-20、QA-21 和 CLOSE-15 的执行附件，不新增任务编号。没有更高目标时采用本文“P1 标准档”作为最低验收目标；实际环境大于 P1 时，必须按真实峰值上调，不能降低目标以换取通过。

## 1. 使用规则

1. 先选择容量档位，再冻结 foundation_version、部署区域、运行单元和验证窗口；
2. 表中的“默认目标”是待实现系统的最低目标，不代表当前系统已经达到；
3. 实际结果必须来自目标部署形态的测量，并登记时间、数据量、持续时间和证据索引；
4. 组合部署、拆分部署和重新合并必须使用同一目标档位；
5. 业务量超过目标档位时，以业务预测峰值乘安全系数后的结果替换默认值；
6. 任一关键目标未测量、未达到或证据缺失时，对应任务不得标记 DONE。

## 5. 延迟与时效目标

| 场景 | P95 | P99 | 起止口径 |
|---|---:|---:|---|
| 认证与权限判断 | ≤ 300 ms | ≤ 800 ms | 入口收到请求至身份与范围确定 |
| 普通详情查询 | ≤ 500 ms | ≤ 1,500 ms | 不含客户端网络时间 |
| 普通列表查询 | ≤ 800 ms | ≤ 2,000 ms | 默认分页和常用筛选 |
| 核心命令受理 | ≤ 800 ms | ≤ 2,000 ms | 请求进入至返回确定受理结果 |
| 消息保存并对账号成员可见 | ≤ 2 秒 | ≤ 5 秒 | 入站或出站受理至实时或补读可见 |
| 会话分配结果可见 | ≤ 3 秒 | ≤ 10 秒 | 触发分配至列表、详情和事件一致 |
| Automation/Macro 开始执行 | ≤ 5 秒 | ≤ 15 秒 | 触发事件至首个动作开始 |
| 领域事件可消费 | ≤ 5 秒 | ≤ 30 秒 | Local Change 提交至事件可用 |
| 集中 AUD 可查询 | ≤ 30 秒 | ≤ 120 秒 | Local Change 提交至集中账本可查询 |
| Webhook 首次投递开始 | ≤ 10 秒 | ≤ 60 秒 | 事件可用至第一次外部调用 |
| 搜索结果达到最新版本 | ≤ 30 秒 | ≤ 120 秒 | 权威对象变化至 SRH 投影可查 |
| 常用报表达到最新版本 | ≤ 5 分钟 | ≤ 15 分钟 | 权威变化至 RPT 指标可查 |
| 普通异步任务进度刷新 | ≤ 5 秒 | ≤ 15 秒 | 状态变化至查询可见 |

Provider 自身异步处理时间必须单独记录，不得计入内部处理并掩盖；但客户可观察的端到端时间仍需单独给出。

## 6. 积压、重试与恢复目标

| 指标 | 默认门槛 | 通过条件 |
|---|---:|---|
| 核心命令队列正常积压 | P95 ≤ 5 秒 | 持续超过 5 分钟必须告警 |
| 事件和 Change 投递正常积压 | P95 ≤ 30 秒 | 不允许无法解释的 sequence 缺口 |
| 通知和 Webhook 正常积压 | P95 ≤ 60 秒 | 超过阈值可降级但不得丢失 |
| 报表与搜索投影积压 | P95 ≤ 5 分钟 | 达到约定版本后差异为 0 |
| 突发结束后积压清空 | ≤ 30 分钟 | 使用 P1 或选定档位的突发负载 |
| 单次自动重试次数 | 默认最多 5 次 | 永久错误不重试；随机退避 |
| 死信或人工处理登记 | 100% | 每项有对象、原因、补偿和复验结果 |
| 恢复后的重复副作用 | 0 | 按幂等键和业务结果核对 |

## 7. RTO、RPO 与数据完整性

| 范围 | RTO | RPO | 额外要求 |
|---|---:|---:|---|
| U1 Edge | ≤ 30 分钟 | 配置 ≤ 15 分钟 | 可重建连接；已受理命令不得丢失 |
| U2 Control | ≤ 30 分钟 | ≤ 5 分钟 | 权限变更和凭证状态不得回退 |
| U3 Core | ≤ 30 分钟 | ≤ 5 分钟 | 已提交业务对象与 Local Journal 原子一致 |
| U4 Capability | ≤ 60 分钟 | ≤ 15 分钟 | 流程、动作、外部调用可查询和补偿 |
| U5 Insight | ≤ 4 小时 | ≤ 60 分钟 | AUD 权威账本按零丢失目标；RPT/SRH 可重建 |
| Local Change Journal | 与业务事务相同 | 0 次已提交 Change | 本地记录失败时业务变化不得提交 |
| Central Audit Ledger | ≤ 4 小时恢复查询 | 0 条已接受 Change | 中断期间保留本地待投递并幂等补投 |
| 模块拆分或合并回退 | ≤ 30 分钟 | 0 条切换后 Change | 先回放新增 Change，再切换写入权威 |

## 8. 拆分、灰度和合并量化门槛

| 阶段 | 默认范围或时间 | 进入下一阶段的条件 |
|---|---|---|
| 历史迁移 | 100% 范围 | 数量、关系、版本、Change 和哈希差异为 0 |
| 影子运行 | 至少 72 小时 | 未批准业务差异 0；P99 Change 延迟 ≤ 120 秒 |
| 1% 灰度读 | 至少 30 分钟且不少于 1,000 次查询 | 权限、内容和版本差异 0 |
| 5% 灰度读写 | 至少 60 分钟且不少于 1,000 次写命令 | 单一权威、重复副作用和 Change 缺口均为 0 |
| 20% 灰度 | 至少 4 小时 | 错误率、延迟和积压不超过基线 |
| 50% 灰度 | 至少 24 小时 | 跨完整业务高峰，未触发回退条件 |
| 100% 切换 | 至少 72 小时观察 | 核心闭环、容量、恢复和长周期对账通过 |
| 重新合并 | 使用同一验收集 | 组合/拆分通过率 100%，未批准业务差异 0 |
| 回退决策 | 发现 P0 差异后 ≤ 10 分钟 | 已停止扩大灰度并保护单一写入权威 |
| 回退执行 | ≤ 30 分钟 | 切换后 Change 全部回放，核心闭环恢复 |

## 9. 成本与资源量化

| 指标 | 默认门槛 | 必填实际值 |
|---|---:|---|
| 无法归属到 Account/模块/能力的成本 | ≤ 2% | 验证窗口总成本与未归属成本 |
| 实际月成本相对冻结预算偏差 | ≤ 10% | 预算币种、预算值、实际值 |
| 单千条消息成本 | 只监测，不设跨环境统一金额 | 基础设施、Provider 和存储分别填写 |
| 单千次 Automation/Macro 动作成本 | 只监测 | 运行、外部调用和失败重试分别填写 |
| 单次 AI 请求成本 | 不超过 Account 配额与模型预算 | 模型、输入、输出、工具和回退分别填写 |
| 空闲资源占比 | ≤ 40% | 按 U1 至 U5 和独立模块填写 |
| 峰值资源使用率 | 目标 50% 至 75%，不得持续超过 85% | 计算、内存、连接、队列和存储分别填写 |

金额无法跨项目预设，但币种、预算和审批值必须在 BAS-08 关闭前填写。没有预算值只能完成技术验收，不能关闭可量化和全局关门。

- [ ] foundation_version、合同版本、容量档位、部署形态和验证窗口已填写；
