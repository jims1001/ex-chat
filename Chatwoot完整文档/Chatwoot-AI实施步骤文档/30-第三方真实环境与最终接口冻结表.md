# 第三方真实环境与最终接口冻结表

> 本分册是 CHAN、AI、EXT、BIL、MOB、CONS、QA 和 CLOSE 批次的执行附件，不新增任务编号。它补齐第三方真实账号、Provider 版本、最终接口合同和真实回执的统一登记方式。

## 1. 目标

把“支持某个第三方”转换为可验证事实：具体使用哪个 Provider、哪个版本、什么授权范围、哪些接口、哪些回调、哪些限制、取得了什么真实结果，以及失败后能否恢复。没有真实授权、真实业务动作和最终回执时，只能标记 blocked 或批准 N/A。

## 2. 第三方范围总表

| 类别 | 必须逐项判断的范围 | 对应任务 |
|---|---|---|
| 客户渠道 | Email、Facebook Messenger、Instagram、WhatsApp Cloud、LINE、Telegram、TikTok、X/Twitter、SMS、Twilio、Voice、Conference、WhatsApp Calling、webchat 既有微信/小程序/短信/语音 | CHAN-13 至 CHAN-30 |
| AI | 每个启用 Provider、Model、Embedding、知识处理、Copilot、Tool 和回退模型 | AI-01 至 AI-25 |
| 插件与集成 | Integration App、Webhook、Dashboard App、Agent Bot、Slack、Linear、Shopify、Notion、Dialogflow、Translate、OpenAI 旧式、LeadSquared、RealtimeKit/Dyte | EXT-01 至 EXT-23 |
| 支付与计费 | 实际支付、订阅、账单、回调和退款 Provider | BIL 适用任务 |
| 推送与移动 | Browser Push、FCM、APNs、深链、Android/iOS 域名关联 | MOB 适用任务 |

范围中未启用的项目仍必须登记 N/A 原因、批准记录、有效期和重开条件，不能直接删除。

## 3. Provider 实例登记

一个 Provider 有多个账号、区域、号码、页面、工作区或模型时，每个实际实例分别登记。

| 字段 | 填写要求 |
|---|---|
| provider_instance_id | 全局唯一，供证据、凭证引用、事件和指标关联 |
| provider_type、provider_name | 类别和正式名称 |
| account_scope | 所属 Account、安装级或平台级范围 |
| environment | 测试、预发布或正式 |
| region、data_location | 服务区域和数据处理位置 |
| api_version | 冻结的 API、协议或模型版本 |
| capability_version | 对应 Action Capability 版本 |
| endpoint | 正式服务入口，只记录非敏感部分 |
| auth_type | OAuth、Token、证书、签名或其他方式 |
| credential_reference | 仅记录安全引用，不记录 Secret 原值 |
| scopes | 实际批准的最小授权范围 |
| external_resources | Page、号码、WABA、Bot、工作区、店铺、模型等标识 |
| callback_endpoint | 回调类型、版本和归属 Inbox/Account |
| signature_rule | 签名方式、时间窗、重放和轮换规则 |
| quotas | 请求、消息、Token、并发、存储和费用限制 |
| token_lifecycle | 到期、刷新、撤销、轮换和重新授权方式 |
| data_policy | 数据发送范围、保留、删除和合规要求 |
| enabled_features | 实际启用的能力，不得用 Provider 理论能力代替 |
| unsupported_features | 明确不支持或未授权的能力及降级结果 |
| owner_scope | 业务归属和运行维护归属 |
| status | planned、connected、verified、degraded、revoked、blocked、N/A |
| evidence_index | 授权、业务、回执、失败和恢复证据 |
| verified_at、expires_at | 最后真实验证时间和证据失效时间 |

## 4. 最终接口合同冻结

每个实际业务动作分别冻结，不允许只记录 Provider 名称。

| 字段 | 内容要求 |
|---|---|
| contract_id、contract_version | 稳定合同标识和版本 |
| provider_instance_id | 指向实际 Provider 实例 |
| business_action | 授权、入站、发送、查询状态、撤销、同步、调用工具等 |
| direction | 系统到 Provider、Provider 到系统或双向 |
| path_or_topic | 对外路径、回调类型或事件主题 |
| method_or_event | 请求动作或事件名称 |
| identity | 使用的认证方式和最小 Scope |
| request_fields | 必填、可选、可空、枚举、大小和敏感等级 |
| response_fields | 受理、最终状态、外部标识、错误和未知字段规则 |
| idempotency | 去重键、作用域、有效期和重复结果 |
| timeout_retry | 超时、可重试错误、次数、退避和结果未知查询 |
| rate_limit | 配额口径、剩余量、恢复时间和降级 |
| callback_contract | 签名、事件、字段、顺序、重复、乱序和版本 |
| status_mapping | Provider 状态到统一状态的映射和不可映射处理 |
| error_mapping | 授权、校验、限流、内容、目标、暂时和永久错误 |
| side_effects | 消息、通知、Webhook、计费、用量、Change 和审计 |
| compatibility | 旧版本、未知字段、未知状态和升级窗口 |
| evidence_cases | 对应真实验收案例编号 |

接口冻结后发生版本、Scope、模型、Endpoint、回调字段或限流变化，必须重开对应功能任务和 QA 案例。

## 5. 每个 Provider 的真实验收集

| 场景 | 必须取得的实际结果 | 通过条件 |
|---|---|---|
| 初次授权或配置 | Provider 成功结果和系统连接状态 | Account、资源和 Scope 正确，不泄露凭证 |
| 最小业务请求 | 最小合法请求与最终结果 | 能确认 Provider 实际可用，不只是保存配置 |
| 入站 | Provider 发起的真实事件、签名校验和统一对象 | 去重正确，Account、Inbox 和客户身份正确 |
| 出站 | 系统发起、Provider 接受和外部标识 | 受理与最终状态分开记录 |
| 最终回执 | delivered、read、completed、failed 或 Provider 最终状态 | 状态映射、对象、事件、指标和审计一致 |
| 媒体或结构化内容 | 每种声明支持的主要内容类型 | 大小、类型、权限、过期和失败规则通过 |
| 重复回调 | 同一事件至少重复两次 | 不重复主对象、计费或外部副作用 |
| 乱序回调 | 最终状态早于中间状态或旧状态晚到 | 对象状态不倒退 |
| 超时结果未知 | 外部可能已接受但内部超时 | 先查状态，不盲目再执行 |
| 限流 | 达到或模拟 Provider 真实限流 | retry_after、退避、积压和恢复可观察 |
| 凭证到期或撤销 | 真实撤销、过期或最接近的受控环境结果 | 健康变更、通知、停止新调用和重新授权通过 |
| Provider 故障 | 受控中断或可证明的错误结果 | 主业务隔离、重试上限和补偿明确 |
| 重新授权或恢复 | 恢复凭证并再次完成业务请求 | 不丢历史关联，不生成重复安装实例 |
| 停用和删除 | 停止新调用，处理延迟回调 | 无越权继续调用，历史证据仍可追踪 |

AI Provider 还必须验证：实际模型标识、输入输出、流式或非流式结果、Token/用量、内容安全、超时、限流、模型下线、回退模型、知识隔离和 Tool 最终结果。

插件还必须验证：安装权限、事件订阅、Action Capability 范围、调用幂等、失败隔离、停用、卸载和历史审计。

## 6. 真实证据登记表

| evidence_id | provider_instance_id | case_id | contract_version | request_id | external_id | started_at | final_at | final_status | redacted_artifact | result |
|---|---|---|---|---|---|---|---|---|---|---|
| 执行时填写 | 实例标识 | 案例编号 | 合同版本 | 请求标识 | Provider 回执标识 | 开始时间 | 最终时间 | 最终状态 | 脱敏证据索引 | pass/fail/blocked |

证据必须保留足以复核的请求摘要、响应摘要、回调、外部标识、时间和系统对象结果。Token、Secret、证书私钥、完整认证头和 restricted 原值不得进入证据包。

## 7. 版本和证据有效期

| 变化 | 必须执行的动作 |
|---|---|
| Provider API 或模型版本变化 | 重开版本、授权、最小请求、主要业务和错误场景 |
| Scope 变化 | 重做授权、权限拒绝、入站、出站和停用 |
| Token 或证书轮换 | 验证旧值失效、新值生效、不中断和不泄露 |
| 回调地址或签名规则变化 | 重做验证、重复、乱序、重放和轮换 |
| 主要限流变化 | 重做容量、积压、恢复和成本测量 |
| Provider 能力下线 | 验证禁用、降级、替代和历史数据 |
| 证据超过有效期 | 重做真实最小闭环和关键失败场景 |

默认有效期为 90 天；安全凭证、Provider 版本或能力变化时立即失效。正式切换前 7 天内必须至少完成一次真实核心闭环。

## 8. 完成条件

- [ ] 每个第三方项目均为 verified、批准 N/A 或明确 blocked；
- [ ] 每个 verified 实例都有版本、Scope、凭证引用、配额、回调和数据政策；
- [ ] 每个适用业务动作都有最终接口合同；
- [ ] 真实授权、真实业务、最终回执、失败和恢复证据齐全；
- [ ] 重复、乱序、超时、限流、撤销和重新授权已验证；
- [ ] 证据已脱敏且在有效期内；
- [ ] 只有配置保存或模拟结果的项目没有被标为完成。
