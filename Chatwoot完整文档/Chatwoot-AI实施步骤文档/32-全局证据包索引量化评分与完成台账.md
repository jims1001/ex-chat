# 全局证据包索引、量化评分与完成台账

> 本分册是 482 项任务、六项目标和 CLOSE-01 至 CLOSE-16 的统一实证出口，不新增任务编号，也不替代 [28-AI全任务状态记录](28-AI全任务状态记录.md)。28 记录任务状态，本文记录“为什么可以得出该状态”。

## 1. 目标

建立一套可复核、可追踪、可量化且不会用文档声明冒充实际结果的证据体系。任一 DONE、架构目标通过或全系统完成结论，都必须能从本台账定位到具体环境、版本、案例、实际结果、Change、外部回执和差异处理。

## 2. 全局证据包信息

| 字段 | 填写要求 |
|---|---|
| evidence_package_id | 全局唯一，建议包含系统、版本和验证窗口 |
| foundation_version | 与实际实施一致 |
| product_version | Chatwoot、webchat 和合同版本 |
| deployment_topology | U1 至 U5 组合关系和独立拆分模块 |
| capacity_profile | 29 分册 P0/P1/P2 或批准的自定义档位 |
| environment | 测试、预发布、正式及区域 |
| validation_window | 起止时间、时区、峰值和长周期范围 |
| account_scope | 参与验证的 Account、Inbox 和数据范围 |
| provider_scope | 30 分册 Provider 实例清单 |
| migration_scope | 历史范围、源目标、Change 水位和切换窗口 |
| evidence_owner_scope | 证据维护与批准责任范围 |
| retention | 保留期限、访问范围和删除规则 |
| integrity | 摘要、签名、不可变存储或其他完整性证明 |
| final_status | collecting、reviewing、pass、fail、blocked、expired |

| 前缀 | 证据类型 | 主要内容 |

## 5. 482 项任务证据最低要求

每一项任务都在 28 分册保留状态，并在本台账登记下列证据。某类确实不适用时，需要 N/A 批准，而不是留空。

| 证据面 | 最低要求 |
|---|---|
| 基线 | foundation_version、任务基线章节、适用范围和依赖状态 |
| 正常 | 至少一个从入口到最终业务结果的完整案例 |
| 权限 | 允许身份、无权身份、跨 Account 和资源范围案例 |
| 字段 | 必填、可选、空值、边界、未知字段、响应和错误 |
| 重复与并发 | 稳定幂等键、至少一次重复；涉及共享状态时执行并发案例 |
| 异常 | 受理前失败、受理后未知、依赖失败、重试和不可重试结果 |
| 最终状态 | 异步、Provider、迁移和长流程必须达到可查询终态 |
| 副作用 | 实时、Webhook、通知、报表、搜索、审计和外部调用的适用集合 |
| Change | 写任务必须有 change_id、object_version、Local Journal 和 AUD 对账 |
| 兼容 | 旧字段、旧入口、历史对象或 Provider 版本适用时验证 |
| 量化 | 延迟、错误、积压、容量或业务指标至少关联一个冻结目标 |
| 差异 | 实际与目标不同的每一项均有差异编号、影响、期限和批准状态 |

“请求返回成功”只能证明入口受理，不能替代权限、终态、副作用、Change 和外部回执证据。

## 10. 实施完成量化评分

本评分用于判断实际实施完成度，不评价文档篇幅。

| 评分域 | 分值 | 得分规则 |
|---|---:|---|
| 482 项任务关闭 | 40 | `40 × (DONE + 已批准 N/A) / 482`，有无证据 DONE 时该项按 0 计 |
| 功能与公共合同 | 20 | API、对象、权限、状态、异常、副作用和兼容全部通过得满分 |
| 六项目标 | 20 | 每项目标通过得 3.33 分；任一项 blocked 不计分 |
| 第三方、迁移与长周期 | 10 | 真实 Provider、历史迁移、灰度回退、容量和长周期全部通过得满分 |
| 证据完整与有效 | 10 | 482 项索引完整、证据可读、未过期、敏感信息合规且差异清零得满分 |

计算分数之外还必须满足零容忍门槛：越权或泄露 0、无 change_id 变化 0、未登记写入口 0、直接跨模块存储访问 0、依赖环 0、未批准业务差异 0、无证据 DONE 0。任一零容忍项不为 0，即使计算分数达到 100 也不能声明完成。
