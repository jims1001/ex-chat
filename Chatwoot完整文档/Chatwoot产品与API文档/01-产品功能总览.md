# Chatwoot 产品功能总览

> 导航：[全体功能与 API 总表](00-全体功能与API总表.md)｜[文档目录](README.md)

## 1. 产品定位

Chatwoot 是一个多租户客户沟通平台。它把网站聊天、Email、WhatsApp、Facebook、Instagram、Telegram、LINE、TikTok、X、SMS 和 API 渠道统一到 Inbox，再以 Contact、Conversation 和 Message 组织客服工作。

## 2. 核心角色

| 角色 | 主要能力 |
|---|---|
| Account Administrator | 管理账号、成员、渠道、权限、自动化、Webhook、集成和 AI |
| Agent | 处理会话、发送消息、使用团队工具和查看授权范围内的数据 |
| Custom Role User | 按企业版自定义权限使用指定功能 |
| Contact | 通过 Widget、渠道或 Public Client 与客服沟通 |
| Platform App | 代表 SaaS 控制平面创建和管理账号、用户及授权资源 |
| Agent Bot | 通过事件通知和 API 参与会话处理 |
| Captain Assistant | 使用知识和工具自动回答或辅助客服 |

| 消息 | 公开回复、私有备注、附件、引用、模板、翻译和失败重试 |
| 工作流管理 | Assignment Policy、保存筛选、批量操作、导入和草稿 |
| 自动化 | 条件规则、动作、Macro、快捷回复、模板和活动触达 |

## 4. 核心业务对象

| 对象 | 业务含义 |
|---|---|
| Account | 租户边界，所有业务数据必须属于某个账号 |
| Inbox | 一条客户接入渠道或业务线入口 |
| Contact | 客户主体，可以拥有多个渠道身份 |
| ContactInbox | Contact 在一个 Inbox 中的具体身份 |
| Conversation | 一次持续的客户服务会话 |
| Message | 客户消息、客服回复、私有备注、活动或互动内容 |
| Team | 客服团队，用于分配、筛选和报表 |
| Label | 可复用的业务标签 |
| Custom Attribute | 账号自定义的结构化业务字段 |
| Webhook | 向外部系统发送业务事件的订阅 |
| Agent Bot | 通过外部服务参与会话的机器人 |
| Captain Assistant | 面向客户或客服的 AI 助手 |
| Assignment Policy | Inbox 的自动分配顺序、会话优先级和公平分配规则 |
| Data Import | 外部系统数据迁移任务及其状态和错误 |
| Call | 联系人、Inbox 和 Conversation 之间的语音通话记录 |
| User Session | 当前用户的登录设备和有效认证会话 |
| Audit Log | 账号关键对象变化的审计记录 |

## 5. 主要业务流程

### 5.1 客户发起会话

1. 客户通过某个渠道进入 Inbox；
2. 系统识别或创建 Contact 与渠道身份；
3. 创建或复用 Conversation；
4. 保存 Incoming Message；
5. 根据规则分配 Agent、Team、Bot 或 Captain；
6. 向工作台、Webhook 和通知订阅者发送更新。

### 5.2 客服处理会话

1. Agent 在授权 Inbox 中查看会话；
2. 可以分配、加标签、设优先级或添加私有备注；
3. 发送公开回复后由对应渠道送达客户；
4. 问题完成后将状态改为 resolved；
5. 客户再次回复时可重新打开会话；
6. SLA、CSAT 和报表记录服务结果。

### 5.3 自动化和机器人

1. 业务事件满足自动化条件；
2. 执行分配、标签、消息、状态或 Webhook 动作；
3. Agent Bot 或 Captain 可在 pending 会话中响应；
4. 无法继续处理时转交人工；
5. 人工接管后机器人不应继续发送过期回答。

### 5.4 AI 知识问答

1. 管理员创建 Assistant；
2. 绑定 Inbox；
3. 上传 PDF、添加网页文档或维护 FAQ；
4. 文档完成处理后形成可检索知识；
5. 客户消息触发自动回答，或 Agent 在 Copilot 中提问；
6. 无可靠答案、工具失败或业务需要时转人工。

### 5.5 身份与安全

1. 用户使用邮箱和密码登录；
2. 启用 MFA 时完成第二步验证；
3. 登录后读取 Profile 和所属 Account；
4. 认证头用于访问受保护接口；
5. 用户可以查看并移除其他登录设备；
6. 企业账号可以通过 SAML 进入登录流程。

### 5.6 数据导入和批量处理

1. 验证外部数据来源和可导入范围；
2. 创建 Data Import 任务；
3. 读取处理数量、状态和错误；
4. 对失败任务重新开始或放弃；
5. 会话和联系人批量操作完成后重新读取结果。

### 5.7 通话处理

1. 配置支持 Voice 或 WhatsApp Calling 的 Inbox；
2. 从 Contact 或 Conversation 发起 Call；
3. Agent 接听、拒绝或结束；
4. 通话在 Conversation 中形成对应消息；
5. 录音和转写可以在通话结束后补充；
6. 报表根据 Call 状态、方向、成员和时间进行筛选。

## 6. 版本和依赖标记

| 标记 | 含义 |
|---|---|
| 通用功能 | 当前版本基础能力 |
| Enterprise | 需要企业版或企业功能授权 |
| Cloud | 仅云托管环境提供 |
| 第三方依赖 | 需要外部平台账号、权限、凭证或审核 |
| 可选功能 | 需要账号 Feature、安装配置或特定 Inbox 类型 |

## 7. API 使用原则

- Account 路径中的 account_id 是租户边界，不代表调用者自动拥有权限；
- 资源 ID 必须从当前 Account 的列表或详情接口获得；
- 写接口应处理重复提交、并发状态变化和异步结果；
- 渠道发送成功与 API 接受请求不是同一个状态；
- Webhook、实时事件和 REST 响应可能提供不同字段集合；
- Enterprise、Cloud 和第三方功能应在界面和接口中分别判断可用性。
