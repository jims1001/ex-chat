# 公共字段、枚举、错误与接入验收

> 导航：[全体功能与 API 总表](00-全体功能与API总表.md)｜[文档目录](README.md)

## 1. 公共摘要对象

### 1.1 User 摘要

| 字段 | 类型 | 说明 |
|---|---|---|
| id | integer | User ID |
| name | string | 姓名 |
| email | string 或缺失 | 只有允许的内部响应提供 |
| type | string | user、agent 或相关展示类型 |
| availability_status | enum 或缺失 | online、busy、offline |
| thumbnail | string 或 null | 头像 |

### 1.2 Contact 摘要

| 字段 | 类型 | 说明 |
|---|---|---|
| id | integer | Contact ID |
| name | string | 姓名 |
| email | string 或 null | 邮箱 |
| phone_number | string 或 null | 电话 |
| identifier | string 或 null | 外部标识 |
| thumbnail | string 或 null | 头像 |
| blocked | boolean 或缺失 | 是否阻止联系 |

### 1.3 Inbox 摘要

| 字段 | 类型 | 说明 |
|---|---|---|
| id | integer | Inbox ID |
| name | string | 名称 |
| channel_type | string | 渠道类型 |
| avatar_url | string 或 null | 头像 |

### 1.4 Account 摘要

| 字段 | 类型 | 说明 |
|---|---|---|
| id | integer | Account ID |
| name | string | Account 名称 |

## 2. 核心枚举

### 2.1 Conversation status

| 值 | 含义 |
|---|---|
| open | 待处理或处理中 |
| resolved | 已解决 |
| pending | 等待客户、Bot 或其他条件 |
| snoozed | 延后处理 |

### 2.2 Conversation priority

| 值 | 含义 |
|---|---|
| low | 低 |
| medium | 中 |
| high | 高 |
| urgent | 紧急 |
| null | 未设置 |

### 2.3 Message type

| 值 | 含义 |
|---|---|
| incoming | 客户发给 Chatwoot |
| outgoing | Chatwoot 发给客户或内部备注 |
| activity | 系统活动 |
| template | 模板消息 |

### 2.4 Message status

| 值 | 含义 |
|---|---|
| sending | 等待发送 |
| sent | 已发送到渠道或已接受 |
| delivered | 已送达 |
| read | 已读 |
| failed | 发送失败 |

不同渠道不一定提供 delivered 和 read。

### 2.5 Agent availability

| 值 | 含义 |
|---|---|
| online | 在线 |
| busy | 忙碌 |
| offline | 离线 |

### 2.6 Captain 状态

| 对象 | 值 |
|---|---|
| FAQ | pending、approved |
| Document | in_progress、available |
| Document Sync | syncing、synced、failed |
| Hook | enabled、disabled、reauthorization_required，按集成提供 |

## 3. 时间字段

| 形式 | 示例含义 | 使用要求 |
|---|---|---|
| Unix integer | 秒级时间 | 按 UTC 转换 |
| Unix number | 可能含小数 | 保留精度 |
| ISO 8601 string | 带时区日期时间 | 使用字符串中的时区 |
| Date string | 仅日期 | 不按时间戳处理 |

同名 created_at 在不同接口面可能使用不同形式，必须按具体响应确认。

## 4. 扩展字段对象

| 字段 | 用途 | 使用规则 |
|---|---|---|
| custom_attributes | Account 自定义业务字段 | 只写已定义且允许的字段 |
| additional_attributes | 渠道或系统扩展信息 | 不应整体覆盖未知字段 |
| content_attributes | Message 内容结构 | 按 content_type 解释 |
| settings | Account、Hook 或功能设置 | 局部更新时保留未提交字段 |
| meta | 分页、统计或事件元数据 | 不能作为固定业务对象使用 |

## 5. 字段可见性

| 接口面 | 不应返回的内容 |
|---|---|
| Public/Widget | 私有备注、内部邮箱、权限、Secret、其他 Contact 数据 |
| 普通 Account 成员 | 安装级 Secret、未授权 Inbox、其他成员私有 AI Thread |
| Webhook | 未订阅事件、无关账号数据、Token 和 Secret |
| Platform App | 未授权给该 App 的资源 |
| Integration App 页面 | Access Token、API Key 和未授权客户数据 |

## 6. 错误分类

| 分类 | 常见状态码 | 说明 |
|---|---:|---|
| Authentication | 401 | Token 缺失、无效或过期 |
| Authorization | 403 | 身份有效但没有权限 |
| Not Found | 404 | 资源不存在或不在当前范围 |
| Validation | 400、422 | 字段格式、必填项或业务规则失败 |
| Conflict | 409、422 | 唯一性、状态或并发冲突 |
| Rate Limit | 429 | 请求过快或额度限制 |
| External Provider | 422、502、503、504 | 第三方平台拒绝、超时或不可用 |
| Internal | 500 | 未处理异常 |

## 7. 常见错误处理

| 场景 | 正确处理 |
|---|---|
| 401 | 清除失效身份并重新认证 |
| 403 | 显示权限不足，不重复请求 |
| 404 | 核对 Account、资源 ID 和访问范围 |
| 422 | 显示字段错误并保留用户输入 |
| 429 | 遵循 Retry-After 或延迟重试 |
| 500/503 | 保留请求时间和关联信息，只对安全操作重试 |
| 异步操作超时 | 查询资源最终状态，不立即重复创建 |

## 8. 敏感字段

以下字段不得记录在普通日志、报表或共享文档中：

- api_access_token；
- access-token、client 和 uid 组合；
- Webhook secret；
- Agent Bot access_token 和 secret；
- OAuth access_token、refresh_token；
- Provider API Key；
- Captain 模型 API Key；
- Widget 客户令牌和 PubSub Token；
- 信用卡、身份号码及非必要的完整客户消息。

## 9. 分页验收

- page 从有效起始值开始；
- 空页返回空数组或明确空 payload；
- 切换过滤条件后重置 page；
- 不根据当前页长度推断总数；
- 大批量读取保存最后成功页；
- 数据变化期间允许相邻页面出现变动，并按资源 ID 去重。

## 10. Account 隔离验收

每类 Account API 至少检查：

1. Account A 正常读取自己的资源；
2. Account A 不能使用 Account B 的资源 ID；
3. 普通 Agent 不能执行 Administrator 动作；
4. 无 Inbox 权限的 Agent 不能读取对应会话；
5. Contact Token 不能读取其他 Contact；
6. Platform Token 不能访问未授权资源；
7. Agent Bot Token 不能作为普通 User Token 使用。

## 11. 创建与重复验收

| 资源 | 重复控制建议 |
|---|---|
| Contact | 使用稳定 identifier，并检查已有记录 |
| ContactInbox | 同一 Inbox 和 source_id 不重复 |
| Conversation | 保存服务端返回 ID，超时后先查询 |
| Message | 使用 echo_id 或 source_id 关联请求 |
| Webhook Event | 使用 Delivery ID 去重 |
| Provider Event | 使用 Provider Event ID 去重 |
| Linear Link | 先查询 linked_issues |
| Captain Document | 避免同一 Assistant 重复添加相同 URL |

## 12. 异步状态验收

以下操作不能只依据首次响应判断完成：

- 渠道消息发送；
- Captain 文档抓取和同步；
- PDF 处理；
- 数据导入和导出；
- Campaign 发送；
- Provider 模板同步；
- Webhook 和 Agent Bot 投递；
- 报表和搜索索引更新。

应通过状态查询、实时事件、Webhook 或最终资源详情确认结果。

## 13. 版本兼容验收

- 记录目标 Chatwoot 版本；
- 保存实际使用的 API 路径清单；
- 保存每个路径使用的请求字段；
- 验证响应新增字段不会导致失败；
- 验证新增枚举值有默认展示；
- 验证时间字段格式；
- 验证权限、Feature 和 Enterprise 差异；
- 验证 Webhook 事件和签名；
- 验证异步状态和重复请求；
- 升级后重新执行关键业务流程。

## 14. 接入完成标准

只有同时满足以下条件才算完成：

- 身份和 Account 边界正确；
- 所需资源字段完整保存；
- 错误状态有明确展示和恢复方式；
- 重复请求不会造成重复业务结果；
- 异步操作能够确认最终状态；
- Webhook 和实时事件可以去重并恢复；
- Secret 和客户敏感信息受到保护；
- 目标渠道和第三方功能已经使用真实账号确认；
- Enterprise、Cloud 和 Feature 限制已经记录。

身份安全验收详见：[身份、个人资料、安全与登录会话 API](13-身份资料安全与登录会话API.md)。
