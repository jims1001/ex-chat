# 各渠道创建与更新字段字典

> 导航：[全体功能与 API 总表](00-全体功能与API总表.md)｜[Inbox、渠道与 Widget API](04-Inbox渠道与Widget-API.md)｜[渠道授权、通话、会议与高级 Inbox API](15-渠道授权通话会议与高级Inbox-API.md)

## 1. 功能范围

本分册集中说明不同 Inbox 渠道在创建、更新和读取时使用的字段。Inbox 公共配置与渠道凭证分开组织：公共配置决定客服流程，channel 对象决定消息从哪里接收、向哪里发送。

## 2. Inbox 创建与更新 API

| 方法 | 路径 | 功能 | 通常权限 |
|---|---|---|---|
| POST | /api/v1/accounts/{account_id}/inboxes | 创建 Inbox 和渠道 | Administrator |
| GET | /api/v1/accounts/{account_id}/inboxes/{inbox_id} | 获取 Inbox 与渠道摘要 | 有权访问该 Inbox 的成员 |
| PATCH | /api/v1/accounts/{account_id}/inboxes/{inbox_id} | 更新公共配置或允许更新的渠道字段 | Administrator |
| DELETE | /api/v1/accounts/{account_id}/inboxes/{inbox_id} | 删除 Inbox | Administrator |

创建请求使用 name、公共配置和 channel。channel.type 决定其余字段的解释方式。更新时不应通过普通字段改变渠道类型；需要更换渠道时，通常创建新 Inbox 并迁移成员和业务入口。

## 3. 公共请求字段

| 字段 | 类型 | 创建 | 更新 | 说明 |
|---|---|---:|---:|---|
| name | string | 是 | 可选 | Inbox 名称 |
| avatar | file | 可选 | 可选 | Inbox 头像 |
| greeting_enabled | boolean | 可选 | 可选 | 是否启用欢迎消息 |
| greeting_message | string | 可选 | 可选 | 欢迎消息正文 |
| enable_email_collect | boolean | 按渠道 | 按渠道 | 是否在网站聊天中收集邮箱 |
| csat_survey_enabled | boolean | 可选 | 可选 | 是否在会话解决后发送满意度调查 |
| csat_config | object | 可选 | 可选 | 满意度调查展示与触发规则 |
| enable_auto_assignment | boolean | 可选 | 可选 | 是否自动分配新会话 |
| working_hours_enabled | boolean | 可选 | 可选 | 是否启用营业时间 |
| out_of_office_message | string | 可选 | 可选 | 非营业时间提示 |
| timezone | string | 可选 | 可选 | Inbox 使用的 IANA 时区 |
| allow_messages_after_resolved | boolean | 按渠道 | 按渠道 | 已解决后是否允许客户继续发消息 |
| lock_to_single_conversation | boolean | 按渠道 | 按渠道 | 同一渠道身份是否只保留一个会话线程 |
| portal_id | integer 或 null | 可选 | 可选 | 关联帮助中心 Portal |
| sender_name_type | enum | 按渠道 | 按渠道 | friendly 或 professional |
| business_name | string | 按渠道 | 按渠道 | 对外展示的业务名称 |
| branded_email_layout | string 或 null | 否 | Email 可选 | Email 品牌布局 |
| channel | object | 是 | 按渠道 | 渠道专属字段 |

公共布尔字段未提交时保留产品默认值；更新请求只提交需要改变的字段，避免覆盖目标账号已经启用的新配置。

## 4. CSAT 配置字段

| 字段 | 类型 | 说明 |
|---|---|---|
| csat_config.display_type | enum | emoji 或 star |
| csat_config.message | string | 调查说明 |
| csat_config.button_text | string | 调查按钮文字 |
| csat_config.language | string | 调查语言 |
| csat_config.survey_rules.operator | string | 多条触发值之间的组合方式 |
| csat_config.survey_rules.values | array | 触发调查的规则值 |

csat_survey_enabled 控制总开关，csat_config 控制展示和发送规则。只提供配置而不开启总开关，不代表调查会自动发送。

## 5. 工作时间字段

工作时间通常通过 Inbox 的工作时间子资源维护，读取 Inbox 时会出现在 working_hours 中。

| 字段 | 类型 | 说明 |
|---|---|---|
| day_of_week | integer | 0 至 6，0 表示星期日 |
| closed_all_day | boolean | 当天全天关闭 |
| open_all_day | boolean | 当天全天开放 |
| open_hour | integer | 开始小时，0 至 23 |
| open_minutes | integer | 开始分钟，0 至 59 |
| close_hour | integer | 结束小时，0 至 23 |
| close_minutes | integer | 结束分钟，0 至 59 |

时间按 Inbox timezone 解释。全天开放、全天关闭和具体时间段应保持互斥；启用 working_hours_enabled 后，非营业时间回复、SLA 营业时间口径和自动化判断都可能受其影响。

## 6. Web Widget 渠道

channel.type 使用 web_widget。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| channel.website_url | string | 是 | 部署 Widget 的主网站地址 |
| channel.welcome_title | string | 否 | 欢迎标题 |
| channel.welcome_tagline | string | 否 | 欢迎说明 |
| channel.widget_color | string | 否 | Widget 主题颜色 |
| channel.reply_time | enum | 否 | in_a_few_minutes、in_a_few_hours、in_a_day |
| channel.pre_chat_form_enabled | boolean | 否 | 是否启用聊天前表单 |
| channel.pre_chat_form_options | object | 否 | 表单标题、说明和字段配置 |
| channel.continuity_via_email | boolean | 否 | 是否通过 Email 延续网站会话 |
| channel.hmac_mandatory | boolean | 否 | 是否强制验证外部客户标识 |
| channel.allowed_domains | string | 否 | 允许嵌入的域名，多个值以逗号分隔 |
| channel.selected_feature_flags | string array | 否 | Widget 功能开关 |

selected_feature_flags 当前可使用 attachments、emoji_picker、end_conversation、use_inbox_avatar_for_bot、allow_mobile_webview。未列入允许集合的值不应提交。

设计重点：website_token 用于公开定位 Inbox，HMAC 用于验证登录客户身份，两者不能互相替代。启用 hmac_mandatory 后，应同时维护稳定的 identifier 和对应签名。

## 7. API Channel

channel.type 使用 api。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| channel.webhook_url | string 或 null | 否 | 接收消息和会话事件的外部地址 |
| channel.hmac_mandatory | boolean | 否 | Public Contact 身份是否强制 HMAC |
| channel.additional_attributes | object | 否 | API Channel 附加配置 |

API Channel 由外部系统负责最终渠道送达。Chatwoot 将事件发送到 webhook_url，外部系统再调用 Public API 写入联系人、会话、消息或状态。callback_webhook_url 与 webhook_url 含义不同：前者通常是 Chatwoot 提供给渠道平台的回调地址，后者是外部系统接收 Chatwoot 事件的地址。

## 8. Email 渠道

channel.type 使用 email，channel.email 为必填收件地址。

### 8.1 收件配置

| 字段 | 类型 | 说明 |
|---|---|---|
| channel.imap_enabled | boolean | 是否启用 IMAP 收件 |
| channel.imap_login | string | IMAP 登录名 |
| channel.imap_password | string | IMAP 密码 |
| channel.imap_address | string | IMAP 主机 |
| channel.imap_port | integer | IMAP 端口 |
| channel.imap_enable_ssl | boolean | 是否启用 SSL |
| channel.imap_authentication | string | IMAP 认证方式 |

### 8.2 发件配置

| 字段 | 类型 | 说明 |
|---|---|---|
| channel.smtp_enabled | boolean | 是否启用自定义 SMTP |
| channel.smtp_login | string | SMTP 登录名 |
| channel.smtp_password | string | SMTP 密码 |
| channel.smtp_address | string | SMTP 主机 |
| channel.smtp_port | integer | SMTP 端口 |
| channel.smtp_domain | string | SMTP 域名 |
| channel.smtp_enable_starttls_auto | boolean | 是否自动启用 STARTTLS |
| channel.smtp_enable_ssl_tls | boolean | 是否直接使用 SSL/TLS |
| channel.smtp_openssl_verify_mode | string | 证书验证方式 |
| channel.smtp_authentication | string | SMTP 认证方式 |
| channel.provider | string | Email Provider 标识 |
| channel.verified_for_sending | boolean | 发件身份是否已验证 |

设计重点：收件成功和发件成功是两套独立状态。修改密码或主机后，应分别验证收件与发件；verified_for_sending 不能代替一次真实发送验证。

## 9. WhatsApp Cloud 渠道

channel.type 使用 whatsapp，channel.provider 使用 whatsapp_cloud。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| channel.phone_number | string | 是 | 对外 WhatsApp 号码 |
| channel.provider | string | 是 | whatsapp_cloud |
| channel.provider_config.api_key | string | 是 | Provider 访问凭证 |
| channel.provider_config.phone_number_id | string | 是 | Meta Phone Number ID |
| channel.provider_config.business_account_id | string | 是 | WhatsApp Business Account ID |

旧的 360dialog 配置使用 provider 的兼容值和 provider_config.api_key，属于兼容入口。新接入优先使用 WhatsApp Cloud 授权流程。模板同步、会话窗口、消息回执、Calling 和 CSAT Template 仍受 Provider 账号能力限制。

## 11. Telegram 渠道

channel.type 使用 telegram。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| channel.bot_token | string | 是 | Telegram Bot Token |

Bot Token 同时决定接收和发送身份。轮换 Token 后必须重新确认 Webhook 注册状态；旧 Token 不应继续保存在日志或其他配置中。

## 12. SMS 渠道

channel.type 使用 sms。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| channel.phone_number | string | 是 | 渠道号码，建议使用 E.164 |
| channel.provider_config | object | 是 | Provider 账号、认证和发送配置 |

SMS 的 provider_config 结构由所选 Provider 决定。Twilio SMS、Twilio WhatsApp 和语音 Inbox 使用专门的渠道接口与字段，详见第 15 分册。Messaging Service SID 是 Twilio 发送能力标识，不应与普通 phone_number 混用。

## 13. 授权型渠道

Google Email、Microsoft Email、Facebook、Instagram、TikTok 和 X 主要通过授权及回调流程创建，不能仅靠普通 Inbox 创建请求完成连接。

| 渠道 | 主要入口 | 授权结果需要确认 |
|---|---|---|
| Google Email | /api/v1/accounts/{account_id}/google/authorization | 授权账号、收件地址、Token 状态 |
| Microsoft Email | /api/v1/accounts/{account_id}/microsoft/authorization | 租户、邮箱、权限范围 |
| Facebook | /api/v1/accounts/{account_id}/facebook/authorization 和 callbacks | Page、订阅、Page Token |
| Instagram | /api/v1/accounts/{account_id}/instagram/authorization | Instagram 业务账号与消息权限 |
| TikTok | /api/v1/accounts/{account_id}/tiktok/authorization | Business 账号和回调订阅 |
| X | /api/v1/accounts/{account_id}/twitter/authorization | Profile、访问凭证和 Webhook |

授权返回成功只表示第三方授权流程完成。还应读取 Inbox health、执行收发测试，并监控 reauthorization_required 等状态。

| 字段 | 类型 | 说明 |

| id、name、channel_id、channel_type | 基础字段 | Inbox 和渠道标识 |
| avatar_url | string 或 null | Inbox 头像 |
| website_url、website_token、web_widget_script | string 或 null | Web Widget 地址、公开 Token 和嵌入内容 |
| widget_color、welcome_title、welcome_tagline | string 或 null | Widget 展示配置 |
| greeting_enabled、greeting_message | boolean、string | 欢迎消息配置 |
| enable_auto_assignment、auto_assignment_config | boolean、object | 自动分配配置 |
| working_hours_enabled、working_hours、timezone | 混合 | 营业时间配置 |
| out_of_office_message | string 或 null | 非营业时间提示 |
| csat_survey_enabled | boolean | 满意度调查开关 |
| allow_messages_after_resolved | boolean | 解决后是否允许继续发消息 |
| lock_to_single_conversation | boolean | 是否锁定为单会话 |
| sender_name_type、business_name、branded_email_layout | 混合 | Email 对外展示配置 |
| hmac_mandatory、selected_feature_flags、reply_time | 混合 | Widget 与 API Channel 配置 |

敏感凭证可能被省略、遮蔽或不再返回。不能通过读取响应来备份密码、Token 或 Secret。

## 15. 更新与安全规则

- 只在轮换凭证时提交密码、Token、Secret 和 api_key；
- 不把敏感字段写入自定义属性、备注、Webhook Payload 或错误描述；
- 先更新 Provider 凭证，再验证 Inbox health、回调和双向消息；
- 渠道授权失效时保留 Inbox 和历史会话，优先执行重新授权，不重复创建相同渠道；
- 删除 Inbox 前确认第三方回调、活动、自动化、Bot、成员和未完成会话的影响；
- 以 Inbox 详情和 health 返回为最终状态，不以授权页面跳转结果代替收发验证。

## 16. 渠道验收清单

- 创建结果返回正确 channel_type 和 channel_id；
- Inbox 成员能读取，未授权成员不能读取；
- 工作时间、欢迎语、CSAT 和自动分配按目标设置生效；
- 外部渠道能接收一条客户消息并发送一条客服回复；
- 回调验签、模板、送达状态和重新授权状态可被识别；
- Secret 轮换后旧凭证失效且新凭证可用；
- 响应没有泄露密码、Token 或完整 Provider Secret。
