# 自动化条件、操作符与动作字典

> 导航：[全体功能与 API 总表](00-全体功能与API总表.md)｜[自动化、活动、通知与模板 API](07-自动化活动通知与模板API.md)

本字典中的 action_name 在目标架构中必须映射到 [统一 Action Capability 合同](../Chatwoot全系统基础层规范/10-自动化规则宏与统一动作能力合同.md)，不能由 AUT、OPS 和手工接口分别实现。

## 1. 设计目标

Automation Rule 把一次业务事件拆成触发事件、条件集合和动作序列。事件决定何时检查，条件决定是否命中，动作决定命中后做什么。规则只处理当前 Account 内的会话、成员、团队、Inbox、标签和自定义字段。

## 2. Rule API

| 方法 | 路径 | 功能 | 通常权限 |
|---|---|---|---|
| GET | /api/v1/accounts/{account_id}/automation_rules | 规则列表 | Administrator |
| POST | /api/v1/accounts/{account_id}/automation_rules | 创建规则 | Administrator |
| GET | /api/v1/accounts/{account_id}/automation_rules/{id} | 规则详情 | Administrator |
| PATCH | /api/v1/accounts/{account_id}/automation_rules/{id} | 更新规则 | Administrator |
| DELETE | /api/v1/accounts/{account_id}/automation_rules/{id} | 删除规则 | Administrator |
| POST | /api/v1/accounts/{account_id}/automation_rules/{id}/clone | 复制规则 | Administrator |

## 3. Rule 顶层字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| name | string | 是 | 规则名称 |
| description | string 或 null | 否 | 规则目的和影响范围 |
| event_name | enum | 是 | 触发事件 |
| active | boolean | 否 | 是否启用，默认启用 |
| conditions | array | 是 | 条件列表 |
| actions | array | 是 | 按顺序执行的动作列表 |

更新 conditions 或 actions 时应提交完整的新列表。复制规则会生成新的 Rule ID，复制后应先停用或复核，避免原规则和副本同时执行。

## 4. 当前触发事件

| event_name | 触发时机 | 典型用途 |
|---|---|---|
| conversation_created | 新会话建立 | 首次分流、欢迎消息、设置优先级 |
| conversation_updated | 会话属性发生更新 | 监控状态、分配、标签或客户属性变化 |
| conversation_opened | 会话进入 open | 重新打开后的分流或提醒 |
| conversation_resolved | 会话进入 resolved | 发邮件、发送记录、通知外部系统 |
| message_created | 新消息建立 | 关键词分流、私有备注判断、自动回复 |

contact_created 和 contact_updated 是 Webhook 事件，不是当前 Automation Rule 的 event_name。

## 5. Condition 结构

| 字段 | 类型 | 说明 |
|---|---|---|
| attribute_key | string | 要检查的会话、消息、联系人或自定义字段 |
| filter_operator | enum | 比较方式 |
| values | array | 一个或多个比较值 |
| query_operator | enum 或空 | 与下一条件的 AND 或 OR 关系 |
| custom_attribute_type | enum 或空 | 自定义字段归属，常用 conversation_attribute 或 contact_attribute |

通常只有最后一条条件可以不填写 query_operator。AND 表示前后条件都满足，OR 表示任一满足。多条条件混用 AND 和 OR 时，应通过样本会话验证实际组合，避免因阅读顺序产生误解。

## 6. 内置条件字段

| attribute_key | 值类型 | 含义 | 常用操作符 |
|---|---|---|---|
| status | enum | 会话状态 | equal_to、not_equal_to |
| assignee_id | integer | 当前负责人 | equal_to、not_equal_to、is_present、is_not_present |
| team_id | integer | 当前团队 | equal_to、not_equal_to、is_present、is_not_present |
| inbox_id | integer | 会话 Inbox | equal_to、not_equal_to |
| priority | enum | 会话优先级 | equal_to、not_equal_to |
| conversation_language | string | 会话识别语言 | equal_to、not_equal_to |
| browser_language | string | 网站客户浏览器语言 | equal_to、not_equal_to |
| referer | string | 网站来源地址 | equal_to、not_equal_to、contains、does_not_contain |
| mail_subject | string | Email 主题 | equal_to、not_equal_to、contains、does_not_contain |
| labels | string array | 会话标签 | equal_to、not_equal_to、is_present、is_not_present |
| message_type | enum | incoming、outgoing、activity 等消息方向 | equal_to、not_equal_to |
| private_note | boolean | 是否私有备注 | equal_to、not_equal_to |
| content | string | 规范化后的消息正文 | equal_to、not_equal_to、contains、does_not_contain |
| email | string | 联系人邮箱 | equal_to、not_equal_to、contains、does_not_contain |
| phone_number | string | 联系人电话 | equal_to、not_equal_to、contains、does_not_contain、starts_with |
| country_code | string | 联系人国家代码 | equal_to、not_equal_to |
| city | string | 联系人城市 | equal_to、not_equal_to、contains、does_not_contain |
| company_name | string | 联系人公司名 | equal_to、not_equal_to、contains、does_not_contain |

Account 已定义的会话或联系人自定义字段也可作为 attribute_key。提交时必须使用该 Account 内真实存在的 attribute_key，并填写正确的 custom_attribute_type。

## 7. 各事件常用条件

| 事件 | 当前常用条件集合 |
|---|---|
| message_created | message_type、private_note、content、email、inbox_id、status、assignee_id、team_id、priority、conversation_language、phone_number、company_name、labels |
| conversation_created | status、browser_language、mail_subject、country_code、phone_number、company_name、referer、email、inbox_id、conversation_language、priority、labels |
| conversation_updated | status、browser_language、mail_subject、country_code、referer、phone_number、company_name、assignee_id、team_id、email、inbox_id、conversation_language、priority、labels |
| conversation_opened | browser_language、email、mail_subject、country_code、referer、assignee_id、phone_number、company_name、team_id、inbox_id、conversation_language、priority、labels |
| conversation_resolved | browser_language、email、mail_subject、country_code、referer、assignee_id、phone_number、company_name、team_id、inbox_id、conversation_language、priority |

条件是否有业务意义取决于事件发生时是否已经存在对应值。例如 conversation_created 时可能还没有负责人；message_created 才能稳定判断消息正文和 private_note。

## 8. 操作符字典

| filter_operator | 适用值 | 说明 |
|---|---|---|
| equal_to | 文本、枚举、ID、布尔 | 等于任一指定值 |
| not_equal_to | 文本、枚举、ID、布尔 | 不等于指定值 |
| contains | 文本 | 包含指定文本 |
| does_not_contain | 文本 | 不包含指定文本 |
| starts_with | 电话等文本 | 以指定内容开头 |
| is_present | ID、标签、自定义字段 | 有值或已关联 |
| is_not_present | ID、标签、自定义字段 | 无值或未关联 |
| is_greater_than | 数字或日期 | 大于指定值 |
| is_less_than | 数字或日期 | 小于指定值 |
| days_before | 日期 | 早于当前时间指定天数 |
| attribute_changed | 已有兼容规则 | 判断字段旧值和新值；当前普通创建接口不建议新增此类条件 |

不能为字段使用未允许的操作符。attribute_changed 的评估能力主要用于已有兼容规则，而当前创建接口的 values 采用数组字段，因此新规则不应依赖旧值/新值对象。文本比较通常不应用于判断富文本展示结果；关键词规则应使用实际消息正文，并考虑大小写、空格和多语言差异。

## 9. Action 结构

| 字段 | 类型 | 说明 |
|---|---|---|
| action_name | enum | 动作名称 |
| action_params | array | 动作参数，结构随动作变化 |

动作按数组顺序执行。前一动作改变会话状态、负责人、团队或标签后，后一动作读取的是更新后的会话。单个动作失败不应被理解为后续动作一定停止，因此外部系统还需按最终会话状态确认结果。

## 10. 动作与参数字典

| action_name | action_params | 功能与规则 |
|---|---|---|
| assign_agent | [agent_id] | 分配给 Inbox 可分配成员；可使用 last_responding_agent |
| assign_team | [team_id] | 分配给当前 Account 团队 |
| remove_assigned_agent | [] | 清除负责人 |
| remove_assigned_team | [] | 清除团队 |
| add_label | [label...] | 添加已有标签 |
| remove_label | [label...] | 移除指定标签 |
| send_message | [message] | 发送公开消息 |
| add_private_note | [message] | 添加内部备注 |
| send_attachment | [blob_id...] | 发送规则已上传的附件 |
| send_email_to_team | [{team_ids、message}] | 向一个或多个团队发送通知邮件 |
| send_email_transcript | [email_list] | 向指定邮箱发送会话记录 |
| send_webhook_event | [url] | 向指定地址发送 automation_event.{event_name} |
| mute_conversation | [] | 静音会话通知 |
| snooze_conversation | [] | 将会话延后 |
| open_conversation | [] | 将会话设为 open |
| pending_conversation | [] | 将会话设为 pending |
| resolve_conversation | [] | 将会话设为 resolved |
| change_status | [status] | 按允许状态修改会话 |
| change_priority | [priority] | 设置 urgent、high、medium、low，或清除优先级 |
| add_sla | [sla_policy_id] | 企业版为会话应用 SLA Policy |

send_message、add_private_note 和 send_attachment 对部分社交消息形态可能不适用。send_email_transcript 还受 Account 是否启用会话记录邮件和邮件发送额度限制。

## 11. 各事件常用动作

| 事件 | 常用动作 |
|---|---|
| message_created | 分配成员或团队、增删标签、发送消息或附件、邮件通知、静音、延后、打开、待处理、解决、Webhook |
| conversation_created | 分配成员或团队、邮件通知、发送消息或附件、静音、延后、待处理、解决、Webhook |
| conversation_updated | 分配成员或团队、邮件通知、发送消息或附件、静音、延后、待处理、解决、Webhook |
| conversation_opened | 分配成员或团队、邮件通知、发送消息或附件、静音、延后、待处理、Webhook |
| conversation_resolved | 分配成员或团队、邮件通知、发送消息或附件、Webhook |

高级动作 change_priority、add_private_note，以及企业版 add_sla，应在目标事件和渠道上单独验收。

## 12. 防重复和循环设计

- 自动回复消息本身也可能形成 message_created，规则应通过 message_type、private_note 或内容条件排除自身；
- 规则发送的消息会带有规则来源信息，外部接收端仍应按消息 ID 去重；
- conversation_updated 规则不要无条件更新同一个属性，否则可能重复触发；
- Webhook 接收端应使用业务对象 ID、event 和更新时间实现幂等；
- 多条规则同时命中时，不保证按规则名称或创建时间形成业务优先级；
- 改状态、分配和标签动作应设计为重复执行后结果仍可接受。

## 13. 规则启用流程

1. 选择单一 event_name，并写清业务目的。
2. 用 Inbox、消息方向、状态或标签缩小范围。
3. 确认最后一条条件没有多余的 AND 或 OR。
4. 按依赖顺序排列动作，例如先分配，再通知。
5. 先保持 active 为 false，用样本会话核对字段值。
6. 启用后检查会话活动、消息、标签、分配和外部接收结果。
7. 发现重复或循环时先停用规则，再调整条件。

## 14. 错误与验收

| 情况 | 预期结果 |
|---|---|
| event_name 不受支持 | 规则不应启用或应返回校验错误 |
| attribute_key 不存在 | 返回条件不支持或自定义字段不存在 |
| filter_operator 与字段不匹配 | 返回条件校验错误 |
| query_operator 不是 AND/OR | 返回 422 类业务错误 |
| action_name 不受支持 | 返回动作不支持 |
| agent_id 不属于可分配范围 | 不应错误分配给其他 Inbox 成员 |
| team_id、label、sla_policy_id 不属于 Account | 不应跨 Account 应用 |
| Webhook 或邮件失败 | 会话中的其他动作结果需要单独确认 |
| 规则被复制 | 新规则拥有新 ID，是否启用需重新检查 |
