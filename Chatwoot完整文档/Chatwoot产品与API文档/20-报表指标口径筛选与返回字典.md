# 报表指标口径、筛选与返回字典

> 导航：[全体功能与 API 总表](00-全体功能与API总表.md)｜[报表、SLA、帮助中心与搜索 API](08-报表SLA帮助中心与搜索API.md)

## 1. 功能范围

报表 API 提供时间趋势、当前与上一周期汇总、成员/团队/Inbox/标签汇总、实时会话指标、机器人指标、首响分布、Inbox×标签矩阵和 CSV 导出。报表权限通常属于 Administrator；企业版拥有 report_manage 的自定义角色也可访问报表与 CSAT。

## 2. 趋势与汇总 API

| 方法 | 路径 | 功能 |
|---|---|---|
| GET | /api/v2/accounts/{account_id}/reports | 指定指标的时间趋势 |
| GET | /api/v2/accounts/{account_id}/reports/summary | 当前周期与上一周期汇总 |
| GET | /api/v2/accounts/{account_id}/reports/bot_summary | 机器人解决和转人工汇总 |
| GET | /api/v2/accounts/{account_id}/reports/drilldown | 指标明细，仅 Administrator |

## 3. 公共筛选字段

| 字段 | 类型 | 说明 |
|---|---|---|
| since | Unix 秒、RFC3339 或 YYYY-MM-DD | 开始时间，包含；纯日期按 UTC 零点 |
| until | Unix 秒、RFC3339 或 YYYY-MM-DD | 排他上界；纯日期包括整个指定 UTC 日期，内部换算为次日零点 |
| metric | enum | 趋势或明细指标 |
| type | enum | account、agent、inbox、team、label |
| id | integer | type 不是 account 时的目标 ID |
| group_by | enum | hour、day、week、month、year；无效值按 day |
| timezone_offset | number | 时间分桶使用的时区偏移 |
| business_hours | boolean | 平均时长是否只统计营业时间 |
| page、per_page | integer | Drilldown 分页 |
| bucket_timestamp | Unix 秒 | Drilldown 指定的趋势时间桶 |

since 与 until 形成半开时间范围。切换 timezone_offset 会改变分桶边界，但不应改变同一绝对时间范围内的原始事件。

### 3.1 现有 REST 实现的时间边界（phase43）

- 现有 `ReportHandler/ReportService` 工作流使用的 RPT、CON、MSG、CUS 报表读取统一使用 `[since, until)`；相邻窗口不会重复统计公共端点。相同或倒置的精确时间戳范围为空。
- Unix 秒和 RFC3339（含小数秒及数值时区偏移）表示原始时刻并转为 UTC。`until=2026-01-31T00:00:00Z` 就是该排他上界，不自动加一秒或一天。
- PostgreSQL 按绝对时刻比较并以微秒精度存储时间戳。为正确比较带纳秒小数的边界，只有报表 SQL 参数向上对齐到下一个可存储微秒；对于数据库已存储的时刻，`>= since` 和 `< until` 的成员资格与原始精确边界一致。HTTP 解析结果与上一周期时长不舍入，SQLite 参数不舍入，也不重写数据或声称恢复已丢失的存储精度。
- SQLite 保留现有的时间文本表示比较方式，不强制把直接调用方的 SQL 参数改为 UTC；匹配存储/参数偏移的读取兼容性仍保留。现有 UTC 存储配合 HTTP 的 UTC 参数受本次边界测试覆盖；混合偏移文本存储与查询参数之间的绝对时刻比较存在先前限制，不在本次修复中迁移数据或用丢失小数精度的日期函数处理。不能据此宣称 SQLite 已支持任意混合存储表示。
- 为兼容纯日期的完整日期含义，`since=2026-01-31&until=2026-01-31` 选择 `[2026-01-31T00:00:00Z, 2026-02-01T00:00:00Z)`。月末、闰日和年末均按 UTC 日历进位。纯日期并非 Account 时区中的日期。
- `from/to` 仅在对应 `since/until` 原始查询值为空时作为别名；解析失败或纯空白仍按缺省端点处理，不新增参数拒绝规则。
- `reports/trends` 在两个端点都存在时按精确时刻选择数据，前一周期向前平移同样的时长；每日标签单独按相交 UTC 日期生成，排他上界恰为零点时不增加末尾日期。缺少任一端点时保留原有 `days` 回退，包括今天的 UTC 日历范围。
- phase43 时仅 conversation traffic 消费 `timezone_offset`：数据库选择仍使用绝对时间，事件日期/小时与列标题同时使用该数值偏移；保留范围相交但零流量的日期，排除范围外末尾日期。此修复不扩展其他接口的时区或 type/id 支持，也不引入 IANA 时区政策。
- year-in-review 选择当年 UTC 1 月 1 日至次年 UTC 1 月 1 日（不含后者）。drilldown 仍选择 `bucket_timestamp` 所在 UTC 日期，保留原有创建会话范围及忽略 ReportFilter 的行为；`meta.bucket.until` 现在为次日零点的排他 Unix 秒，不再是当天最后一秒。JSON/CSV 字段、权限和包络不变。
- 此次只修正 `ReportHandler/ReportService` 现有工作流的时间范围，不实现未注册的通用 `/reports` 指标序列引擎，不改变非机器人营业时间计数筛选、机器人分子/分母范围、独立 Captain/AIC 分析读取或 AUT 的日期语义。


### 3.2 有限固定偏移日历计数序列合同（phase47/53）

phase47 在 phase44 已有 V1 与 V2 的 `GET /accounts/{account_id}/reports` 根路径上扩展日历分组，phase53补齐固定数值偏移，不增加路径。两者沿用原有 Auth、Tenant、PermissionReportView 权限链，仅支持 `conversations_count`、`incoming_messages_count`、`outgoing_messages_count` 三项 Account 计数；不代表文档中所有通用报表能力均已实现。

- `metric` 和有效的显式时间上下界必填，缺失或格式无效返回 400。时间格式、纯日期完整 UTC 日和精确半开端点继承 phase43，不修改共享时间解析器或 ReportFilter；`from/to` 只在对应原始主参数为空时使用。主参数解析失败或纯空白不能退化成无界查询。
- 本入口选定 `type=account`、`group_by=day`、`timezone_offset=0` 缺省值；支持 `group_by=hour|day|month|year`，无效/未知 group_by 仍回退 day。成功返回按自然固定偏移日历桶起点的 UTC Unix 秒升序的稀疏裸数组 `[{"value":整数,"timestamp":整数}]`，不含零值桶、平均值样本数或外层 data/payload。hour 标签为整点，day 为零点，month 为当月 1 日零点，year 为当年 1 月 1 日零点；上述零点/整点以固定偏移日历解释，偏移缺省为0。
- 桶内只选择请求范围与该日历桶的精确 `[since, until)` 交集，部分首尾桶的标签仍为自然桶起点；排他上界恰为桶边界时不增加下一桶。月份和年份按日历进位，正确处理月份长短、闰日和跨年。无记录返回 `[]`；有效空区间和倒置区间返回 `[]` 且不执行 owner SQL。
- 已知但未支持的其他指标、维度、week 分组、Account 的 `id`、IANA `timezone`、CSV 返回 422。未知 metric/type、无效数值/布尔值/格式、重复或未知参数返回 400。不能把不支持的筛选静默当成已经应用。
- 会话按 CON.created_at，消息按 MSG 自身 created_at 计数；旧会话中新产生的消息包含在内。outgoing 包括私有备注、机器人、queued/failed 记录，准确 incoming/outgoing 类型排除 activity/template；记录数量不证明发送或送达。`business_hours` 不改变这三项计数，不改变旧 summary/trends 的营业时间行为。
- 最多选择相交的 400 个所选固定偏移日历分组桶，部分桶和没有记录的桶都占预算；触及第 401 桶时，在调用 owner 前返回 422 `report_range_too_large`。这是所选桶数上限，不是日历时长、扫描记录数或稀疏结果数上限；400 个年桶与 400 个小时桶使用同一预算。
- 请求读取期限为 5 秒，继承更早取消/期限，出错或取消不返回部分数组。每次非空读取由对应 owner 用单条分组 COUNT 查询完成，CON/MSG 最多 801/802 个绑定参数、400 个返回点，两个根路径的响应缓冲上限为 64 KiB；不读取正文、不跨 owner 连接、不写入。该预算不保证恒定数据库工作量。
- PostgreSQL 延续 phase43 的 SQL 参数微秒向上对齐，桶由显式 UTC 边界确定，不受 session timezone 影响；保留其较宽的查询边界支持，不套用 SQLite 年份限制。
- SQLite 新根路径的实际裁剪查询边界须能表示为年份 0001–9999 的规范零偏移 UTC 文本；不能表示时，在 SQL 前返回 422 `report_query_bound_unsupported`，field 为 `since/until`。仅检查实际裁剪边界，不因名义下一桶越界而拒绝：例如 year=9999 桶在 9999 年内结束仍有效，虽然下一年是 10000；实际 until=10000（包括纯日期换算后）不受支持。不能夹紧边界或悄悄改写查询表示。
- SQLite 存储只支持规范驱动 UTC 文本 `YYYY-MM-DD HH:MM:SS[.1..9位小数]+00:00`、年份 0001–9999、有效日历字段及末尾无零的小数；同一 Account（消息还限定准确 type）的任何不支持存储表示，即使位于请求时间范围外，也使读取以 503 `report_storage_representation_unsupported`、`retryable=false` 整体失败。其他 Account/type 不影响；不解析、迁移或归一化存储，不扩大 phase43 的 SQLite 表示支持。
- 两个根路径的错误遵循基础04：稳定 code/category/message、field_errors、request_id/correlation_id、retryable 和适用的公开 dependency。超时 504，取消或计数存储暂不可用 503。查询边界不支持是 422 验证错误，存储表示不支持仍为 503。根路径以外的旧响应形状和错误帮助函数不变。

完整范围、静态表示检查、资源预算、错误、局部 owner 能力和回滚见 `architecture/rpt-daily-count-series.md`。分组通过显式 `domain.ReportCountGrouping` 参数传递，CON/MSG `CountReportBuckets` 仍是本地同步聚合能力，不虚构远程合同。Captain/AIC、BOT 分子口径、其他维度/聚合、远程通用报表引擎及异步导出不属于本次实现。

### 3.2.1 固定数值时区分桶扩展（phase53）

- 上述 V1/V2 reports 根入口的三个 count 指标支持数值小时 `timezone_offset`；正数表示当地时间=UTC+偏移。支持十进制、小数和科学计数法，必须能精确换算为整秒且位于 ±9,223,372,036 秒安全算术范围内。它是技术表示边界，不引入 ±24 小时地域政策。+5.5、+5.75、-3.5、25 和 .0025 小时均有明确语义。
- 不以浮点近似决定接受，不截断或舍入。有限但非整秒/超安全范围的输入返回422；无效十进制、非有限数或被拒绝且超过原有限浮点范围的输入返回400。普通正负/指数/补零的0兼容；十六进制、Go下划线和分数斜杠形式不属于十进制输入。长补零先线性归一化，指数不触发大整数分配。
- 仅改变 hour/day/month/year 的自然日历边界。since/until 仍是原绝对半开区间，纯日期仍按UTC解释；标签为当地自然桶起点对应的 UTC Unix 整秒。相同绝对范围内计数总和不变，不引入夏令时、IANA、Account时区或locale推断。
- 400桶预算按实际相交的当地日历桶计算。每桶显式携带相同 OffsetSeconds，CON/MSG owner拒绝混合偏移、错位标签、溢出或不安全转换；所有实际SQL边界仍为UTC。保留原SQLite实际边界/存储限制与PostgreSQL微秒成员资格规则；不迁移数据、不增加SQL时区函数。
- 算术或时间戳无法可靠表示时返回422 `report_query_bound_unsupported`，即使该非法端点表面上形成空/倒置范围。有效空/倒置范围仍返回[]且不读owner。旧Summary、traffic、BOT、维度、week与其他指标不随本扩展改变。

### 3.3 现有 Summary 消息计数修正（phase45）

- V1/V2 `reports/summary` 及复用相同服务的 `reports/conversations_summary` 在缺省或 `business_hours=false` 时，`total_messages`、`incoming_messages_count`、`outgoing_messages_count` 统一按当前 Account 的 MSG.created_at 选择，不再依赖范围内是否恰好新建了会话。旧会话的新消息也计入；新增无关会话不会使消息数从非零降为零。
- `total_messages` 保留全部消息记录类型，包含 activity/template；incoming/outgoing 仅按准确的 `message_type` 分别计数。outgoing 保留 private、AgentBot、queued/failed 等记录，表示记录数量，不是发送或送达证明。
- MSG owner 通过单条 COUNT 聚合返回三个整数；RPT 不为计数加载正文或连接 CON 表。原有会话集合和正文读取仍用于首响、解决、回复时长、FCR 和机器人指标，不扩大这些指标的样本范围。
- 延续 phase43 的可选上下界、`from/to` 别名、无效值缺省处理、半开区间和 PostgreSQL 参数精度。没有把 phase44 新根路径的必填边界、400 日预算、结构化错误、5 秒期限或 SQLite 表示拒绝规则套用到旧 Summary。JSON 字段/包络、CSV 列/格式、权限和既有错误响应不变。
- **仍待产品决策的既有冲突**：第5节规定计数不受营业时间开关影响，但现有 `business_hours=true` Summary 会先按会话创建时间选择营业时间内的会话，再统计该集合内、消息时间范围内的记录。本批保留已测试的旧行为，包括空集合不做全 Account 回退；不将本次缺省路径修复表述为营业时间合同已完成。

实现、回滚边界和验证见 `architecture/rpt-summary-message-counts.md`。

### 3.4 已知机器人不终止人工回复计时（phase54）

现有 Summary、agent/team/inbox/label 汇总和首响分布在选择人工回复终点时，精确排除公开 outgoing 的 `AgentBot`、`CaptainAssistant`、`Captain::Assistant` 三种 SenderType。机器人消息不结束或重置已有客户等待周期；只有机器人回复的会话不产生人工时长样本。历史空值/未知 SenderType、消息状态和发送失败字段继续按原规则处理。

本批不改变 incoming 起点算法、会话 cohort、半开消息窗口、营业时间算法或返回结构；消息计数、FCR、机器人指标、解决时长与 SLA 不变。特别是 FRT 仍取已加载消息中的第一条 incoming，不能据此声称“最近一次非人工活动”起点或全部报表口径已经完成。范围与回归见 `architecture/rpt-human-response-durations.md`。

### 3.5 Inbox 依赖错误不能当作缺失配置（phase55）

现有 summary、四维度、首响分布、会话导出和 trends 在 CHN Inbox owner 列表返回错误时中止，复用各处理器既有 HTTP 500 通用失败包络；不再把读取失败当作空配置并成功返回默认营业时间、自然秒或 WebWidget 分类。部分行附带错误同样失败。健康空列表/缺失 Inbox 的旧回退、成功响应结构与营业时间定义不变。`conversations_summary` 和相关 V1/V2 别名同样适用。范围及待执行回归义务见 `architecture/rpt-inbox-dependency-errors.md`。

## 4. 核心指标口径

| metric | 聚合 | 单位 | 计算口径 |
|---|---|---|---|
| conversations_count | count | 条 | 时间范围内创建的会话数 |
| incoming_messages_count | count | 条 | 时间范围内的 incoming 消息数 |
| outgoing_messages_count | count | 条 | 时间范围内的 outgoing 消息数 |
| avg_first_response_time | average | 秒 | 从最近一次非人工活动起点到首次人工回复的平均时长 |
| avg_resolution_time | average | 秒 | 从会话创建到进入 resolved 的平均时长 |
| reply_time | average | 秒 | 从客户等待起点到人工回复的平均时长 |
| resolutions_count | count | 次 | 时间范围内 conversation_resolved 事件数 |
| bot_resolutions_count | count | 个会话 | Bot 解决且同范围没有转人工的会话数 |
| bot_handoffs_count | count | 个会话 | 发生 Bot 转人工的去重会话数 |

resolutions_count 统计解决事件，不等同于唯一已解决会话数；一个会话被重新打开后再次解决，可能产生新的解决事件。reply_time 在分组汇总响应中使用 avg_reply_time 字段名。

## 5. 营业时间口径

business_hours 为 true 时，avg_first_response_time、avg_resolution_time 和 reply_time 使用 Inbox 营业时间内的有效秒数。计数指标不因该开关变化。

| 场景 | business_hours=false | business_hours=true |
|---|---|---|
| 非营业时间收到消息，次日回复 | 计算完整经过时间 | 只计算营业时间段 |
| 全天开放 Inbox | 与自然时间接近 | 与自然时间接近 |
| 未配置营业时间 | 按产品当前营业时间规则处理 | 验收时必须核对实际结果 |

跨 Inbox 汇总时，每条事件按所属 Inbox 的工作时间计算，不能用单一 Account 时区重新估算。

## 6. 趋势响应

计数趋势元素包含 value 和 timestamp。平均时长趋势元素还包含 count，表示该时间桶中参与平均值的事件数。

| 字段 | 类型 | 说明 |
|---|---|---|
| value | number | 计数或平均秒数 |
| timestamp | Unix 秒 | 时间桶起点 |
| count | integer | 平均指标的样本数，计数指标通常不提供 |

没有事件的时间桶可能返回 value 为 0，也可能在部分聚合结果中省略。使用方应补全展示时间轴，但不能把“无样本”解释为“平均时长为 0 秒”。

## 7. Summary 响应

| 字段 | 类型 | 说明 |
|---|---|---|
| conversations_count | integer | 创建会话数 |
| incoming_messages_count | integer | 客户消息数 |
| outgoing_messages_count | integer | 发出消息数 |
| avg_first_response_time | number 或 null | 首次响应平均秒数 |
| avg_resolution_time | number 或 null | 解决平均秒数 |
| resolutions_count | integer | 解决事件数 |
| reply_time | number 或 null | 回复平均秒数 |
| previous | object | 与当前周期等长的上一周期相同字段 |

上一周期从 since 向前平移当前范围长度。current 和 previous 应使用相同 type、id、timezone_offset 和 business_hours。

## 8. 分组汇总 API

| 方法 | 路径 | 分组对象 |
|---|---|---|
| GET | /api/v2/accounts/{account_id}/summary_reports/agent | 成员 |
| GET | /api/v2/accounts/{account_id}/summary_reports/team | 团队 |
| GET | /api/v2/accounts/{account_id}/summary_reports/inbox | Inbox |
| GET | /api/v2/accounts/{account_id}/summary_reports/label | 标签 |
| GET | /api/v2/accounts/{account_id}/summary_reports/channel | 渠道类型 |

agent、team、inbox 和 label 常用返回字段：id、name、conversations_count、resolved_conversations_count、avg_resolution_time、avg_first_response_time、avg_reply_time。不同对象还会返回头像、邮箱、渠道或其他展示字段。

channel 返回每种 channel_type 的 open、resolved、pending、snoozed 和 total。该接口单次时间范围不能超过六个月。

## 9. 实时会话指标

| 方法 | 路径 | 功能 |
|---|---|---|
| GET | /api/v2/accounts/{account_id}/live_reports/conversation_metrics | Account 或指定 Team 的实时数量 |
| GET | /api/v2/accounts/{account_id}/live_reports/grouped_conversation_metrics | 按 team_id 或 assignee_id 分组 |

conversation_metrics 返回：

| 字段 | 含义 |
|---|---|
| open | 当前 open 会话数 |
| unattended | 当前 open 且尚未被有效处理的会话数 |
| unassigned | 当前 open 且没有负责人的会话数 |
| pending | 当前 pending 会话数 |

grouped_conversation_metrics 只对 open 会话统计 open、unattended 和 unassigned，并附带 team_id 或 assignee_id。它是当前状态快照，不使用 since 和 until。

## 10. 机器人指标

| 方法 | 路径 | 返回字段 |
|---|---|---|
| GET | /api/v2/accounts/{account_id}/reports/bot_metrics | conversation_count、message_count、resolution_rate、handoff_rate |
| GET | /api/v2/accounts/{account_id}/reports/bot_summary | bot_resolutions_count、bot_handoffs_count、previous |

| 字段 | 口径 |
|---|---|
| conversation_count | 绑定有效 Bot 的 Inbox 在范围内创建的会话数 |
| message_count | 上述会话在范围内产生的 outgoing 消息数 |
| resolution_rate | Bot 解决且未转人工的会话数 ÷ Bot 会话数 × 100 |
| handoff_rate | 发生转人工的去重会话数 ÷ Bot 会话数 × 100 |

同一会话既有 Bot 解决又有转人工时，转人工优先，不计入 Bot 独立解决。

## 11. 专项分析 API

| 方法 | 路径 | 参数 | 返回重点 |
|---|---|---|---|
| GET | /api/v2/accounts/{account_id}/reports/first_response_time_distribution | since、until | 按 channel_type 的 0-1h、1-4h、4-8h、8-24h、24h+ |
| GET | /api/v2/accounts/{account_id}/reports/inbox_label_matrix | since、until、inbox_ids、label_ids | inboxes、labels、matrix |
| GET | /api/v2/accounts/{account_id}/reports/outgoing_messages_count | since、until、group_by | 按 agent、team、inbox 或 label 的发送数 |
| GET | /api/v2/accounts/{account_id}/reports/conversations | type、user_id、page | 相关会话指标列表 |

Inbox×标签 matrix 的行顺序与 inboxes 一致，列顺序与 labels 一致。不能脱离两个标题数组单独解释矩阵数字。

## 13. 空值、延迟与一致性

- 计数没有样本时通常为 0；
- 平均时长没有样本时可能为 null、0 或缺少时间桶，按具体接口处理；
- 实时指标读取当前会话状态，趋势报表读取时间范围内的会话、消息和指标事件，两者不一定相等；
- 会话状态变化、异步汇总和时区分桶可能造成短暂延迟；
- 删除、合并或重新打开会话可能改变后续查询结果；
- 跨周期比较必须固定相同的筛选条件和营业时间开关。

## 14. 报表验收

- 用一个已知会话验证创建、首响、普通回复和解决四个时间点；
- 分别验证自然时间和营业时间秒数；
- 验证 hour、day、week、month、year 的分桶边界；
- 验证 Account、Agent、Team、Inbox、Label 维度不会跨范围；
- 验证空范围的计数和平均值展示；
- 验证 Bot 解决后又转人工时只计入转人工；
- 验证 CSV 与 JSON 在相同筛选下的样本范围一致；
- 非 Administrator 且无 report_manage 时不能访问报表。
