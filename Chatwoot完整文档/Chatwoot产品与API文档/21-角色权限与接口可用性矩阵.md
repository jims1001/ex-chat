# 角色权限与接口可用性矩阵

> 导航：[全体功能与 API 总表](00-全体功能与API总表.md)｜[账号、成员、团队与权限 API](03-账号成员团队与权限API.md)｜[API 通用约定与认证](02-API通用约定与认证.md)

## 1. 权限设计

权限由身份类型、Account 成员角色、Inbox 或 Team 可见范围、资源归属、Custom Role、Feature 和企业授权共同决定。仅拥有有效 Token 不代表可以访问 Token 所属用户看不到的 Inbox 或资源。

## 2. 身份类型

| 身份 | 主要认证 | 数据范围 | 典型用途 |
|---|---|---|---|
| Administrator | Account 成员认证头 | 当前 Account 全部管理范围 | 配置账号、渠道、成员、规则和报表 |
| Agent | Account 成员认证头 | 已分配 Inbox、Team 和允许资源 | 处理会话、联系人和个人工作流 |
| Custom Role 成员 | Account 成员认证头 | Agent 基础范围加细粒度授权 | 企业版自定义工作范围 |
| Widget Contact | Widget 客户令牌 | 当前 ContactInbox 和自己的会话 | 网站聊天 |
| Public Contact | Inbox、Contact 公开标识与访问令牌 | 指定客户在指定 Inbox 的资源 | 自有客户界面 |
| Platform App | Platform App Token | App 被授权的平台资源 | 多租户账号和用户管理 |
| Agent Bot | Bot Access Token 和 Secret | 绑定 Inbox 的 Bot 会话 | 自动处理消息和转人工 |

这些身份不可互换。Account 成员认证头不能替代 Platform App Token，Widget 客户令牌也不能调用 Account 管理接口。

## 3. 基础角色能力

### 3.1 Administrator

- 读取和更新 Account；
- 创建、更新和删除成员、Team、Inbox、渠道和标签；
- 管理自动化、Campaign、Webhook、Integration、Agent Bot 和 Dashboard App；
- 查看报表、CSAT、Audit、计费和企业设置；
- 删除联系人、公司和会话等高影响资源；
- 管理 Custom Role、SAML、SLA 和容量策略。

### 3.2 Agent

- 读取 Account 基础信息、成员和 Team 摘要；
- 读取已分配 Inbox 或所属 Team 可见的会话；
- 处理可见会话、发送消息、添加备注、分配、打标签和切换状态；
- 搜索、创建和更新联系人，不能默认删除或批量导入导出；
- 使用个人 Macro、快捷回复、AI 文本任务和可见 Assistant；
- 不能修改 Account、渠道、成员、自动化、Webhook 等管理配置。

## 4. Custom Role 权限

企业版 Custom Role 的 permissions 只接受以下 6 个值。

| permission | 权限范围 | 重要边界 |
|---|---|---|
| conversation_manage | 管理所有原本可见的会话 | 仍受 Account 与基础 Inbox/Team 可见范围限制 |
| conversation_unassigned_manage | 管理未分配会话以及分配给自己的会话 | 不能管理已分配给其他人的会话 |
| conversation_participating_manage | 管理分配给自己或自己作为参与者的会话 | 未参与且未分配给自己的会话不可处理 |
| contact_manage | 联系人导入和导出 | 联系人日常查看、创建、更新本来就向 Agent 开放 |
| report_manage | 报表和 CSAT 管理 | 可访问报表，但不等于获得其他管理设置权限 |
| knowledge_base_manage | Portal、Category、Article 管理 | 只扩展知识库管理，不扩展 Inbox 或成员管理 |

Custom Role 会进一步限制会话详情访问。若角色没有任何 conversation 权限，即使成员属于 Inbox，也可能无法查看具体会话。

## 5. 核心接口权限矩阵

图例：读写表示可查询并执行日常业务操作；只读表示不能修改配置；范围表示仅限有权资源；管理表示需要 Administrator 或对应 Custom Role。

| 接口组 | Administrator | Agent | Custom Role | Contact / Platform |
|---|---|---|---|---|
| Account 详情 | 读写 | 只读 | 只读 | 不适用 |
| 成员和 Team 列表 | 读写 | 只读 | 只读 | Platform App 按平台范围管理 |
| Inbox 列表与详情 | 全部读写 | 已分配范围只读 | 已分配范围只读 | Public Contact 只定位指定 Inbox |
| Inbox 成员、渠道、工作时间 | 管理 | 无配置权 | 无配置权 | 不适用 |
| Conversation | 全部读写 | Inbox/Team 范围读写 | 再受 conversation 权限限制 | Contact 仅自己的会话 |
| Message 与 Attachment | 可见会话读写 | 可见会话读写 | 可见会话读写 | Contact 仅客户可见消息 |
| Contact | 读写、删除、导入、导出 | 读写，不含默认删除和导入导出 | contact_manage 可导入导出 | Contact 只读写自己允许字段 |
| Company | 读写、删除 | 读写，不含默认删除 | 与 Agent 相同 | 不适用 |
| Label 定义 | 管理 | 只读 | 只读 | Widget 只可为当前会话使用已有标签 |
| Automation、Campaign | 管理 | 无 | 无 | 不适用 |
| Macro | 全局管理和个人使用 | 创建个人 Macro、使用全局或自己的 Macro | 与 Agent 相同 | 不适用 |
| Custom Filter | 读写自己的筛选 | 读写自己的筛选 | 与 Agent 相同 | 不适用 |
| Assignment Policy、Capacity | 管理 | 无 | 无 | 不适用 |
| Report、CSAT | 管理 | 无 | report_manage | 不适用 |
| SLA Policy | 管理 | 列表与详情 | 列表与详情 | 不适用 |
| Portal、Category、Article | 管理 | 可读取部分知识内容 | knowledge_base_manage 可管理 | 公共帮助中心读取已发布内容 |
| Webhook、Integration、Agent Bot | 管理 | 部分只读 Bot 信息 | 通常无配置权 | Agent Bot 仅自身绑定范围 |
| AI Task | 可用 | 可用 | 可用 | 不适用 |
| Assistant、Scenario、Tool | 管理；统计和测试可用 | 查看和测试 | 查看和测试 | 不适用 |
| AI Preferences | 读写 | 只读 | 只读 | 不适用 |
| Audit、SAML、Billing | 管理 | 无 | 无 | Platform App 只访问专用平台接口 |

## 6. Conversation 可见性

### 6.1 基础范围

Agent 可以查看以下任一条件满足的会话：

- 会话属于其已分配 Inbox；
- 会话属于其所在 Team。

直接分配给成员或将成员添加为参与者，不会绕过基础 Inbox 或 Team 可见范围；这两个关系主要用于 Custom Role 的二次约束。

Administrator 不受普通 Inbox 成员范围限制。

### 6.2 Custom Role 二次约束

| 权限组合 | 可查看和处理的会话 |
|---|---|
| conversation_manage | 基础范围内全部会话 |
| conversation_unassigned_manage | 未分配会话或分配给自己的会话 |
| conversation_participating_manage | 分配给自己或自己参与的会话 |
| 后两项同时存在 | 两个集合的并集 |
| 三项均不存在 | 无法通过 Custom Role 访问具体会话 |

列表数量、未读数和详情权限可能因 Custom Role 调整而变化。角色变更后，客户端应刷新会话列表和未读统计。

## 7. 联系人和公司权限

| 操作 | Administrator | Agent | contact_manage |
|---|---:|---:|---:|
| 列表、搜索、筛选 | 是 | 是 | 是 |
| 创建、查看、更新 | 是 | 是 | 是 |
| 修改头像和自定义字段 | 是 | 是 | 是 |
| 导入、导出联系人 | 是 | 否 | 是 |
| 删除联系人 | 是 | 否 | 否，除非同时为 Administrator |
| 创建、更新公司 | 是 | 是 | 是 |
| 删除公司 | 是 | 否 | 否 |

contact_manage 不是“联系人全部管理”，它主要扩展导入和导出权限，不能自动获得删除权限。

## 8. 知识库、报表和 AI 权限

| 功能 | 读取 | 修改 |
|---|---|---|
| Portal 基础信息 | Account 成员 | Administrator 或 knowledge_base_manage |
| Category、Article | Account 成员按接口范围 | Administrator 或 knowledge_base_manage |
| Report | Administrator 或 report_manage | 同读取权限 |
| CSAT | Administrator 或 report_manage | 更新备注、下载同样受 report_manage 控制 |
| Assistant | Account 成员 | Administrator |
| Assistant Drilldown 与 Tool 目录 | Administrator | Administrator |
| Custom Tool | Account 成员查看 | Administrator 创建、测试、更新、删除 |
| AI Task | Account 成员 | 生成结果由当前成员决定是否使用 |
| AI Preferences | Account 成员查看 | Administrator |

## 9. Macro 的特殊权限

- Account 成员可创建 Macro；
- personal Macro 仅创建者可查看、更新、删除和执行；
- global Macro 可被成员执行；
- global Macro 的修改和删除需要 Administrator；
- Macro 执行仍受目标会话可见性限制。

## 10. 公共与平台身份边界

### 10.1 Widget / Public Contact

- 只能读取和修改自己的 Contact 与会话；
- 不能看到私有备注、内部活动、其他 Contact 或完整成员资料；
- HMAC 开启时，identifier 必须通过签名验证；
- 只能使用 Inbox 允许的消息类型、标签和附件能力。

### 10.2 Platform App

- 只调用 /platform/api/v1 范围；
- 可管理 Platform User、Account、Account User、Bot 和专用迁移资源；
- 数据范围由 Platform App 授权决定，不继承某个 Account Agent 的权限；
- Platform Token 泄露可能影响多个 Account，应与成员 Token 分开保存和轮换。

### 10.3 Agent Bot

- 仅处理已绑定 Inbox 的事件；
- Secret 用于验证请求，Access Token 用于允许的 Bot 接口；
- 转人工后不应继续无条件发送 Bot 回复；
- Bot 不能借由事件 Payload 访问其他 Account。

## 11. 权限错误处理

| HTTP 状态 | 常见含义 |
|---|---|
| 401 | 认证头无效、过期或身份类型错误 |
| 403 | 身份有效但角色或 Custom Role 不允许操作 |
| 404 | 资源不存在，或为防止泄露而隐藏不可见资源 |
| 422 | 有权限但字段、状态或资源关系不合法 |

不能通过 404 与 403 的差异推断其他 Account 是否存在某个资源。

## 12. 权限验收

- 使用 Administrator、普通 Agent 和每种 Custom Role 分别测试；
- 验证 Agent 只能读取已分配 Inbox 或 Team 范围；
- 验证 conversation_unassigned_manage 不能处理分配给他人的会话；
- 验证 conversation_participating_manage 只覆盖本人参与范围；
- 验证 contact_manage 允许导入导出但不允许删除；
- 验证 report_manage 不会获得渠道或成员管理权限；
- 验证 knowledge_base_manage 不会获得 Account 更新权限；
- 验证 Widget、Public、Platform 和 Bot Token 不能跨接口类型使用；
- 验证角色变更后列表、详情和未读数都立即按新权限刷新。

当权限还受 Feature、套餐、安装配置、对象状态和历史数据共同影响时，按 [权限、Feature、套餐、配置与兼容优先级](35-权限Feature套餐配置与兼容优先级.md) 的十二层顺序判定，并使用 [完整系统一致性对照验收规范](37-完整系统一致性对照验收规范.md) 保存对照证据。
