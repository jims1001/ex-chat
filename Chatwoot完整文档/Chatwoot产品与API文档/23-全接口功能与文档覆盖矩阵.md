# Chatwoot 全接口功能与文档覆盖矩阵

> 导航：[全体功能与 API 总表](00-全体功能与API总表.md)｜[完整文档目录](README.md)

## 1. 本分册用途

本分册把 Chatwoot 4.16.0 的对外入口、账号入口、安装管理入口和第三方回调入口，逐组映射到对应文档。它解决三个问题：某项功能是否存在、通过什么入口使用、具体字段和规则应到哪一册查询。需要逐条方法和完整路径时，进入 30 分册。

覆盖级别定义如下：

| 级别 | 含义 |
|---|---|
| 详细 | 已说明方法、路径、主要请求字段、响应字段、权限、状态和设计规则 |
| 专项 | 除基础说明外，还有独立字段字典、枚举矩阵或事件字典 |
| 边界 | 该入口主要由页面、第三方平台或安装管理界面使用，文档说明用途、输入输出边界和安全规则 |

## 15. 不作为业务 API 的入口

以下入口存在，但不应当作稳定业务 API 使用：

- 页面入口只负责呈现 Dashboard、Widget、登录页和帮助中心，不承诺 JSON 结构；
- 第三方入站 Webhook 的原始字段由第三方平台版本决定，Chatwoot 文档只定义接收目的、校验边界、幂等和处理结果；
- 非正式环境的 Widget 测试页面只用于验证展示，不属于产品集成合同；
- 监控页面和首次安装页面使用最高权限浏览器会话，不向普通 Account 成员开放；
- 第三方 OAuth 回调只接受授权流程生成的 state、code 和错误信息，不应由业务端主动调用。

## 16. 覆盖结论

当前文档已把全部入口归入 00 至 42 共 43 个编号分册，并提供逐动作路径索引、第三方入站 Payload 字典、异步最终状态、公开字段补充字典、分页容量边界、业务副作用、Provider 逐动作版本和完整一致性验收规则。现有基线包含 430 条路径记录、651 个 HTTP 方法动作、273 个公开接口唯一字段名称、68 个 Account Feature、102 个安装配置、15 类第三方入站回调和 37 个业务变化名称。

覆盖维度已从功能、接口、字段、权限、事件、配置和状态，扩展到以下一致性规则：

- 版本、Account、Inbox、数据、时间和 Provider 基线；
- 并发胜负、原子边界、幂等和状态乱序；
- 默认值、空值、唯一范围和数据生命周期；
- Feature、套餐、配置传播和历史兼容；
- 超时、重试、限流、第三方回声和人工恢复；
- 全功能案例、证据包、长周期观察和 100% 通过门槛。
- 查询、排序、分页、批量和字段容量边界；
- 业务动作对通知、自动化、Webhook、Bot、集成、报表、CSAT 和 AI 的连带结果；
- Provider 在不同业务动作中的版本差异及历史数据兼容；
- 真实第三方、时间、并发、规模和历史样本的未决条件关门清单。

单个第三方平台可能随其 API 版本增加事件字段；这类新增字段不改变当前已定义的 Account、Inbox、Conversation、Message、Contact 和 Hook 业务边界，但必须在 Provider 版本变化后更新基线并执行相关回归。
