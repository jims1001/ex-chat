# Chatwoot 异步任务、进度、终态与补偿规则

> 导航：[全 API 逐动作路径索引](30-全API逐动作路径索引.md)｜[公共字段、枚举、错误与验收](12-公共字段枚举错误与验收.md)

## 1. 为什么需要区分受理和完成

Chatwoot 中的消息发送、联系人导入导出、批量操作、Campaign、文档抓取、模板同步、删除、邮件发送和第三方回调，通常不会在 HTTP 响应期间完成全部工作。

| 阶段 | 含义 |
|---|---|
| 请求通过 | 身份、权限和字段校验通过 |
| 已受理 | 已创建业务记录或后台任务 |
| 处理中 | 正在访问第三方、转换数据或批量更新 |
| 部分成功 | 一部分对象成功，一部分失败或跳过 |
| 完成 | 所有必要工作已结束 |
| 失败 | 无法继续，需要修复、重试或人工处理 |
| 已放弃 | 用户主动终止可终止的流程 |

200、201、202 或 204 只能说明当前 HTTP 阶段成功，不能统一解释为第三方已经送达或后台任务已经完成。

## 2. 最终状态查询方式

| 任务类型 | 最终结果来源 |
|---|---|
| Message 发送 | Message.status、external_error、Provider 状态回调 |
| Data Import | GET /data_imports/{id} |
| Captain Document | GET /captain/documents/{id} |
| Help Center 引导生成 | GET /onboarding/help_center_generation |
| Campaign | GET /campaigns/{id} |
| CSAT/WhatsApp Template | GET /inboxes/{id}/csat_template 或重新读取 Inbox 模板 |
| Portal SSL | GET /portals/{id}/ssl_status |
| Contact Export | User 通知或导出结果通知 |
| Bulk Action、Macro | 重新读取目标 Conversation、Contact 或 Article |
| 异步删除 | 重新读取对象；404 表示删除完成 |
| 邮件 Transcript、说明邮件 | 邮件投递状态与收件结果 |
| Account Seed | 重新读取 Account 下的初始化对象 |

没有专用状态接口的任务，应通过业务资源读取确认，不能只重复提交原操作。

## 3. Message 发送状态

| status | 阶段 | 是否终态 | 说明 |
|---|---|---:|---|
| sent | 已受理或 Provider 已接受 | 否 | 等待渠道状态回调 |
| delivered | 已送达 | 否 | 对支持已读回执的渠道仍可进入 read |
| read | 客户已读 | 是 | 只在 Provider 支持时出现 |
| failed | 发送失败 | 是 | 查看 external_error，修复后可按规则 retry |

### 3.1 相关字段

| 字段 | 说明 |
|---|---|
| id | Chatwoot Message ID |
| source_id | Provider Message ID |
| status | 当前发送状态 |
| content_attributes.external_error | 第三方错误摘要 |
| content_attributes.is_unsupported | 入站消息是否无法完整显示 |
| content_attributes.external_echo | 是否来自第三方客户端的外发 Echo |
| created_at、updated_at | 创建和最近状态更新时间 |

### 3.2 补偿规则

- 只有 failed 消息适合使用 retry；
- sent 长时间不变时先检查 Provider 回调，不直接重复发送；
- delivered 或 read 不允许重试；
- 重新授权后不会自动保证所有历史 failed 消息重新发送；
- 模板、回复窗口、附件和号码状态必须在重试时仍有效。

## 4. Data Import 状态

### 4.1 Import 状态

| status | 说明 | 是否终态 |
|---|---|---:|
| pending | 已创建，等待开始 | 否 |
| processing | 正在读取和导入 | 否 |
| completed | 全部处理完成 | 是 |
| completed_with_errors | 已完成，但存在失败或跳过记录 | 是 |
| failed | 导入无法继续 | 是，可重新启动 |
| abandoned | 用户已放弃 | 是，可重新启动 |

### 4.2 进度响应字段

| 字段 | 说明 |
|---|---|
| id | Data Import ID |
| name | 导入名称 |
| data_type | contacts 或 intercom |
| source_type | 来源类型 |
| source_provider | 当前集成来源，如 intercom |
| import_types | contacts、conversations 等导入范围 |
| status | 当前状态 |
| total_records | 预计总记录数 |
| processed_records | 已处理记录数 |
| stats | 各对象和结果统计 |
| cursor | 当前读取位置摘要 |
| started_at | 开始时间 |
| completed_at | 完成时间 |
| abandoned_at | 放弃时间 |
| import_errors_count | 非跳过错误数 |
| skip_logs_count | 跳过记录数 |
| initiated_by | 发起人 id、name、email |

进度百分比可以使用 processed_records / total_records 计算；total_records 为空或为 0 时不应计算百分比。

### 4.3 单条记录状态

| status | 说明 |
|---|---|
| pending | 等待处理 |
| processing | 正在处理 |
| imported | 已导入并建立 Chatwoot 对象 |
| skipped | 根据规则跳过 |
| failed | 单条失败 |

单条记录还可包含 attempt_count、source_object_type、source_object_id、chatwoot_record_type、chatwoot_record_id、last_error_code 和 last_error_message。

### 4.4 Error/Skip CSV 字段

| 字段 | 说明 |
|---|---|
| created_at | 错误时间 |
| kind | 错误或跳过类别 |
| source_object_type | 来源对象类型 |
| source_object_id | 来源对象 ID |
| error_code | 稳定错误码 |
| message | 错误摘要 |
| details | 附加字段 |

### 4.5 重启和放弃

- 只有 failed 或 abandoned Import 可重新启动；
- Intercom pending 或 processing 可以 abandon；
- 缺少原 Access Token 时不能重新启动；
- 同一 Account 同时已有进行中的 Intercom Import 时，新建返回 422；
- restart 不清除已成功记录，单条唯一标识用于防止重复导入。

## 5. Contact CSV Import 与 Export

### 5.1 CSV Import

POST /contacts/import 在文件存在并创建 DataImport 后返回成功，实际导入随后开始。最终状态通过 Data Import 查询。

| 失败点 | 结果 |
|---|---|
| import_file 缺失 | 422 |
| 文件过大或类型不允许 | 上传校验错误 |
| 行字段错误 | completed_with_errors，并产生错误记录 |
| 部分重复 | 根据导入规则跳过或更新，并记录统计 |

### 5.2 Export

POST /contacts/export 只表示导出任务已受理。请求字段 column_names、payload 和 label 决定导出列和范围。当前没有独立 Export 状态接口，结果通过当前 User 的通知或导出交付渠道获取。

重复点击导出可能产生多个导出任务，应在界面上暂时禁用重复提交或使用请求标识管理。

## 6. Captain Document 状态

Captain Document 同时具有内容准备状态 status 和同步状态 sync_status，两者不能混为一个字段。

### 6.1 status

| status | 说明 | 是否可用于生成 FAQ |
|---|---|---:|
| in_progress | 正在抓取、解析或读取 PDF | 否 |
| available | 内容已经可用 | 是 |

### 6.2 sync_status

| sync_status | 说明 | 是否终态 |
|---|---|---:|
| syncing | 正在同步外部页面 | 否 |
| synced | 最近一次同步成功 | 是 |
| failed | 最近一次同步失败 | 是，可重试 |
| null | 尚未执行可记录的同步 | 否 |

### 6.3 响应字段

| 字段 | 说明 |
|---|---|
| id | Document ID |
| assistant | 所属 Assistant 摘要 |
| name | 文档名称 |
| external_link | 原始网页或 PDF 标识 |
| display_url | 可展示地址 |
| content | 已解析内容，存在时返回 |
| content_type | PDF 等附件内容类型 |
| file_size | 文件大小 |
| pdf_document | 是否为 PDF |
| status | 内容准备状态 |
| sync_status | 最近同步状态 |
| sync_in_progress | 是否仍被视为有效同步中 |
| last_synced_at | 最近成功同步时间 |
| last_sync_attempted_at | 最近尝试时间 |
| last_sync_error_code | 最近同步错误码 |
| responses_count | 已生成 FAQ 数量 |

### 6.4 超时和重试

syncing 超过 2 小时会被视为陈旧同步，sync_in_progress 返回 false。此时可以检查 last_sync_error_code 后重新调用 /documents/{id}/sync。

同步接口返回 202 只表示已受理。PDF 不属于网页自动同步范围；网页 external_link 在同一 Assistant 内必须唯一。

## 7. Assistant Response 与 FAQ 候选

| status | 说明 | 是否进入正式知识范围 |
|---|---|---:|
| pending | 等待审核 | 否 |
| approved | 已批准 | 是 |

| 字段 | 说明 |
|---|---|
| id | FAQ ID |
| question | 问题 |
| answer | 答案 |
| status | pending 或 approved |
| edited | 是否经过人工编辑 |
| documentable.type | Captain::Document、Conversation 或 User |
| documentable.id | 来源对象 ID |
| assistant | 所属 Assistant |

批量批准前应确认重复 FAQ、答案事实和所属 Assistant。删除 Document 可能连带影响其生成的响应。

## 8. Help Center 引导生成

### 8.1 查询响应

| 字段 | 说明 |
|---|---|
| generation_id | 本次生成任务 ID |
| state | 进度对象 |
| articles_count | 当前已创建 Article 数量 |
| categories_count | 当前已创建 Category 数量 |

### 8.2 state 字段

| 字段 | 说明 |
|---|---|
| status | generating、completed 或 skipped |
| total | 计划生成的文章数 |
| finished | 已结束的文章数 |
| skip_reason | skipped 时的原因 |

状态数据保留 7 天。generation_id 不存在时返回基础引导状态。completed 表示生成任务结束，生成的 Article 默认仍需检查状态、语言和内容后再公开。

## 9. Campaign 状态

| campaign_status | 说明 | 是否终态 |
|---|---|---:|
| active | 持续型 Campaign 可触发，或一次性 Campaign 等待 scheduled_at | 否 |
| processing | 一次性 Campaign 正在发送 | 否 |
| completed | 一次性 Campaign 已结束 | 是 |

| 相关字段 | 说明 |
|---|---|
| campaign_type | ongoing 或 one_off |
| enabled | 是否允许持续型规则触发 |
| scheduled_at | one_off 计划时间 |
| audience | one_off 接收范围 |
| trigger_rules | ongoing 触发条件 |
| trigger_only_during_business_hours | 是否只在工作时间触发 |
| template_params | WhatsApp 等模板参数 |

同一个 one_off Campaign 在进入 processing 后会阻止重复触发。completed Campaign 不能继续修改后再次发送；需要创建新的 Campaign。

## 10. WhatsApp 与 CSAT Template

### 10.1 同步动作

POST /inboxes/{id}/sync_templates 只受理同步。完成后重新读取 Inbox 的 message_templates。

| 字段 | 说明 |
|---|---|
| id 或 template_id | Provider Template ID |
| name | 模板名称 |
| language | 语言 |
| category | 模板类别 |
| status | Provider 审核状态 |
| components | Header、Body、Footer 和 Button 结构 |

### 10.2 常见状态

| 状态 | 是否可发送 | 说明 |
|---|---:|---|
| PENDING 或 pending | 否 | 等待 Provider 审核 |
| APPROVED 或 approved | 是 | 已批准 |
| REJECTED 或 rejected | 否 | 被拒绝，需要查看原因并重新创建 |
| PAUSED | 否 | Provider 暂停 |
| DISABLED | 否 | Provider 停用 |

创建 CSAT Template 后通常处于 pending。template_exists=true 不等于 APPROVED。

## 11. Portal SSL 状态

GET /portals/{id}/ssl_status 会主动检查当前自定义域名并返回：

| 字段 | 说明 |
|---|---|
| status | 自定义主机名证书状态 |
| verification_errors | 域名验证错误数组或摘要 |

没有 custom_domain 时返回 422。常见过程是等待 DNS 验证、验证通过、证书签发、激活；具体 status 字符串由域名服务返回，不应硬编码为只有两种状态。

/.well-known/cf-custom-hostname-challenge/{id} 使用请求域名和验证 ID 返回验证正文。域名或 ID 不匹配返回 404。

## 12. Account 删除状态

POST /enterprise/api/v1/accounts/{account_id}/toggle_deletion 使用 action_type=delete 或 undelete。

| 字段 | 说明 |
|---|---|
| custom_attributes.marked_for_deletion_at | 计划删除时间，当前为标记后的 7 天 |
| custom_attributes.marked_for_deletion_reason | manual_deletion 或 inactivity |

delete 成功后 Account 进入等待删除期，并可能取消 Cloud 订阅；undelete 会移除两个标记。标记成功不是数据已经删除，真正删除后读取 Account 才会失败。

## 13. Call 状态

| status | 说明 | 是否终态 |
|---|---|---:|
| ringing | 正在呼叫 | 否 |
| in_progress | 已接通 | 否 |
| completed | 正常结束 | 是 |
| no_answer | 无人接听 | 是 |
| failed | 呼叫失败 | 是 |
| rejected | 被拒绝 | 是 |

终态不能被后到的早期状态覆盖。Call、Conversation.additional_attributes.call_status 和 Call Message 的状态应保持一致。

## 14. Applied SLA 状态

| sla_status | 说明 | 是否终态 |
|---|---|---:|
| active | SLA 正在评估，尚无违约 | 否 |
| active_with_misses | 已有一个指标违约，其他指标仍可能继续评估 | 否 |
| hit | 适用指标在阈值内完成 | 是 |
| missed | SLA 最终违约 | 是 |

相关截止时间为 sla_frt_due_at、sla_nrt_due_at 和 sla_rt_due_at。只有策略存在对应阈值时字段才有值。

## 15. Bulk Action

以下动作通常返回受理结果，不提供独立 Job ID：

- Conversation 或 Contact bulk_actions；
- Macro execute；
- Captain bulk_actions；
- Article bulk status、category、translate 和 delete；
- 通知 destroy_all；
- Label 关联清理。

### 15.1 结果确认

| 动作 | 确认方式 |
|---|---|
| 批量更新 Conversation | 按 ids 重新读取 status、assignee、team、labels 或 custom_attributes |
| 批量更新 Contact | 按 ids 重新读取目标字段和标签 |
| Macro | 读取 Conversation 的 Message、Activity、Assignment 和 Label |
| Captain 批量操作 | 重新读取 FAQ 或 Document 状态 |
| Article 批量操作 | 重新读取 status、category_id 或确认 404 |
| 通知批量删除 | 查询 unread_count 和列表 |

### 15.2 补偿原则

- 不要因为列表尚未刷新而立刻重复提交；
- 记录目标 ids 和动作参数，便于比较完成情况；
- 部分对象因权限或当前状态失败时，只重试失败对象；
- 删除动作以 404 或列表中不存在作为完成标准；
- Macro 可能包含发消息等不可逆动作，不能无条件重复执行。

## 16. 异步删除

Inbox、Company、SLA Policy、User 和 Account 等大对象可能先受理，再异步清理关联数据。

| 阶段 | 可观察结果 |
|---|---|
| 受理 | DELETE 返回 2xx，目标可能短时间仍可在旧列表中出现 |
| 隔离 | 新业务不能继续关联即将删除的对象 |
| 清理 | 下级关系、附件、索引和统计逐步更新 |
| 完成 | 目标详情返回 404，关联列表不再出现 |

删除期间不要创建同名替代对象并假设旧 ID 已释放。需要恢复的场景优先使用 disabled、archived 或 suspended，而不是 DELETE。

## 17. 异步邮件

| 动作 | 受理接口 | 完成判断 |
|---|---|---|
| Conversation Transcript | /conversations/{id}/transcript 或 Widget transcript | 目标邮箱收到邮件，或邮件发送记录显示完成 |
| Portal 域名说明 | /portals/{id}/send_instructions | 目标邮箱收到说明 |
| Contact Export | /contacts/export | User 收到导出完成通知或文件 |
| 确认和密码重置 | /auth/confirmation、/auth/password | 邮件到达且 Token 可使用 |

邮件接口 2xx 不保证目标邮箱接受。还要检查每日 Account Email Limit、收件地址、发送域和退信情况。

Widget Transcript 还可能返回 402 表示 Account 不允许邮件 Transcript，429 表示会话无效、超出发送限制或请求过于频繁。

## 18. Account Seed

POST /super_admin/accounts/{id}/seed 用于初始化 Account 数据。该操作可能异步创建联系人、会话或示例资源，当前没有普通 Account 状态字段。

完成判断应检查目标 Account 的预期 Inbox、Contact、Conversation 或其他初始化对象。重复 seed 前必须判断已有对象，避免重复演示数据。

## 19. Webhook 投递与 Provider 回调

### 19.1 Chatwoot 出站 Webhook

出站 Webhook 的单次 2xx 表示接收方接受；超时或非 2xx 可能进入重试。接收方必须按 Event ID 和对象 ID 幂等。完整规则见 19 分册。

### 19.2 第三方入站回调

Chatwoot 向 Provider 返回 2xx 只表示事件已接收。Message、Call、Document 或 Billing 对象可能随后才更新。完整字段见 29 分册。

### 19.3 不可重复的回调

OAuth code、SAML 登录结果和一次性 state 不能通过重复提交补偿。失败后必须重新发起授权。

## 20. 轮询建议

| 场景 | 建议 |
|---|---|
| 短任务 | 先等待短间隔，再逐步增加轮询间隔 |
| 长导入 | 使用 processed_records、updated_at 和 status 判断进展 |
| Provider 审核 | 使用较长间隔，不进行秒级轮询 |
| 进入终态 | 立即停止轮询 |
| updated_at 长时间不变 | 检查错误、后台任务和第三方状态，不无限轮询 |

客户端应设置总超时和“继续后台处理”状态。总超时只停止客户端等待，不应把业务记录改成 failed。

## 21. 幂等和补偿矩阵

| 动作 | 是否适合原样重试 | 正确补偿方式 |
|---|---:|---|
| GET 查询 | 是 | 使用相同筛选重新读取 |
| 更新普通字段 | 通常是 | 重新读取后提交目标最终值 |
| 创建 Contact | 否 | 使用 identifier、email 或 phone_number 查重 |
| 发送 Message | 否 | 查 Message、echo_id 和 source_id |
| retry failed Message | 有条件 | 只重试 failed 且渠道已恢复的消息 |
| OAuth Callback | 否 | 重新发起授权 |
| Data Import start | 有条件 | 先读 status，仅 failed/abandoned 重启 |
| Macro execute | 否 | 检查动作是否已经产生 Message 或 Assignment |
| Campaign trigger | 否 | 检查 campaign_status |
| Document sync | 有条件 | 检查 sync_in_progress 和最近尝试时间 |
| 删除 | 通常是 | 目标 404 时视为已完成 |

## 22. 异步任务验收

- 2xx、202 和最终业务状态分别记录；
- 每个可轮询任务都能识别非终态和终态；
- completed_with_errors 不显示为完全成功；
- failed 能看到稳定错误码或错误摘要；
- 重启 Data Import 不重复创建已导入对象；
- Document syncing 超时后可识别为陈旧任务；
- Message delivered/read 不被重复发送；
- Campaign processing 不会因重复调度发送两次；
- Provider Template 未批准前不能用于发送；
- Account 标记删除和真正删除明确区分；
- 没有状态接口的动作通过目标资源读取确认；
- 所有补偿动作先判断已产生的副作用。

并发胜负与原子边界见 [并发、原子性、幂等与状态竞争规则](33-并发原子性幂等与状态竞争规则.md)，外部超时和重试间隔见 [异常、超时、重试、限流与第三方差异规则](36-异常超时重试限流与第三方差异规则.md)，全量终态验收见 [完整系统一致性对照验收规范](37-完整系统一致性对照验收规范.md)。
