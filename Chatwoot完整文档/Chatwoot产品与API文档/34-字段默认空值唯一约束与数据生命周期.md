# 字段默认、空值、唯一约束与数据生命周期

> 适用版本：Chatwoot 4.16.0
> 本分册用于固定“同一个请求产生同一种数据结果”的规则，覆盖默认值、空值、更新方式、唯一性、归属边界、删除效果和最终可见状态。

## 1. 为什么需要本分册

只对齐接口路径和字段名称，仍可能出现以下差异：

- 未提交字段时，一侧采用默认值，另一侧保存为空；
- null、空字符串、空数组和缺失字段被当成同一种输入；
- 更新操作在一侧合并对象，在另一侧整体替换；
- 同一业务对象在并发请求下生成重复记录；
- 删除后，一侧彻底不可见，另一侧仍以脱敏形式保留；
- 账号之间错误地复用联系人、标签、团队或外部身份；
- 关联对象删除后，子对象的保留、解绑和清理结果不同。

本分册与 [32-完整系统一致性还原目标与基线](32-完整系统一致性还原目标与基线.md)、[33-并发原子性幂等与状态竞争规则](33-并发原子性幂等与状态竞争规则.md) 和 [37-完整系统一致性对照验收规范](37-完整系统一致性对照验收规范.md) 联合使用。

## 2. 五类空值必须区分

| 输入形态 | 含义 | 通用处理规则 | 响应核对点 |
|---|---|---|---|
| 字段缺失 | 调用方没有表达修改意图 | 创建时采用默认值；更新时通常保持原值 | 原值是否保留、默认值是否出现 |
| null | 明确要求没有值 | 仅允许可空字段；不可空字段返回校验错误 | 字段为 null，或错误字段明确 |
| 空字符串 | 提交了文本但内容为空 | 可能被标准化为空、null，或被校验拒绝 | 标准化后的最终值 |
| 空数组 | 明确提交空集合 | 对替换型集合表示清空；对增量型操作通常表示无变化 | 关联数量、事件数量 |
| 空对象 | 明确提交空映射 | 对替换型对象表示清空；对合并型对象通常不删除旧键 | 旧键是否保留 |

不得用下列简化方式替代真实规则：

- 不得把所有假值统一转为 null；
- 不得在更新时自动补齐创建默认值；
- 不得把空数组统一解释为“未提供”；
- 不得因为响应省略字段，就推断该字段已被删除；
- 不得因为文本仅含空格，就保留为有意义值。

## 3. 主要对象创建默认值

### 3.1 Account

| 字段 | 未提交时的默认结果 | 说明 |
|---|---|---|
| status | active | 账号创建后默认可用；暂停状态会阻止账号范围访问 |
| locale | en | 可由账号设置修改 |
| custom_attributes | 空对象 | 后续按账号设置接口管理 |
| feature_flags | 由版本、版本形态和账号授权共同决定 | 不能仅根据字段是否存在判断可用性 |

### 3.2 Contact

| 字段 | 未提交时的默认结果 | 说明 |
|---|---|---|
| contact_type | visitor | 联系人可在后续补全身份资料 |
| blocked | false | 为 true 时阻止正常消息交互 |
| name | 空文本状态 | 未识别身份时允许没有名称 |
| location | 空文本状态 | 可由资料或会话信息补充 |
| country_code | 空文本状态 | 与国家名称字段分开处理 |
| additional_attributes | 空对象 | 保存头像、社交资料等扩展信息 |
| custom_attributes | 空对象 | 只接受账号已定义或允许的自定义字段 |

### 3.3 Inbox

| 字段 | 未提交时的默认结果 | 说明 |
|---|---|---|
| timezone | UTC | 工作时间、活动计划和报表日期都受其影响 |
| enable_auto_assignment | true | 仍受成员、容量和分配策略约束 |
| enable_email_collect | true | 主要用于网站聊天收集邮箱 |
| csat_survey_enabled | false | 开启后才会进入满意度调查流程 |
| allow_messages_after_resolved | true | 决定已解决会话是否允许客户继续发送消息 |
| working_hours_enabled | false | 开启后才应用工作时间段和离线消息 |
| greeting_enabled | false | 开启且配置内容后展示欢迎语 |
| lock_to_single_conversation | false | 开启后同一联系身份复用一个会话 |
| out_of_office_message | 空值或空文本状态 | 仅在工作时间规则生效时有意义 |

### 3.4 Conversation

| 字段 | 未提交时的默认结果 | 说明 |
|---|---|---|
| status | open | 创建入口可根据上下文改变初始状态 |
| priority | null | 可取 low、medium、high、urgent |
| assignee_id | null | 自动分配、团队分配或人工分配后产生值 |
| team_id | null | 不自动推断团队，除非入口或策略明确指定 |
| custom_attributes | 空对象 | 更新时采用整体替换规则，见第 5 节 |
| snoozed_until | null | status 为 snoozed 时才有实际意义 |
| first_reply_created_at | null | 首次符合条件的回复产生后写入 |

### 3.5 Message

| 字段 | 未提交时的默认结果 | 说明 |
|---|---|---|
| status | sent | 表示已进入发送流程，不等同于对方已收到 |
| private | false | true 表示账号成员可见的私密备注 |
| content_type | text | 模板、表单、卡片、选择项等使用其他类型 |
| content_attributes | 空对象 | 渠道、模板或交互消息可填充 |
| additional_attributes | 空对象 | 可承载外部状态和补充信息 |
| external_source_ids | 空对象 | 渠道确认后可补充外部消息标识 |
| deleted | false | 删除消息采用内容脱敏规则，不等于移除记录 |

### 3.6 Campaign

| 字段 | 未提交时的默认结果 | 说明 |
|---|---|---|
| campaign_type | ongoing | 部分渠道只允许 one_off |
| status | active | 调度领取后可能进入 processing，完成后进入 completed |
| enabled | true | false 时不进入正常触发流程 |
| scheduled_at | 当前时间附近 | 一次性活动未提供时间时按创建时刻处理 |
| trigger_rules | 空对象或入口要求的规则 | ongoing 活动必须满足对应触发条件 |

SMS 和 WhatsApp 类型活动按一次性活动处理，即使请求尝试提交持续型活动，也不能假定会保留该值。

### 3.7 其他对象

| 对象 | 主要默认结果 | 需要核对的后续变化 |
|---|---|---|
| Notification | unread | 阅读、批量阅读和全部阅读会改变状态 |
| Data Import | pending 或待处理 | 随校验、执行和完成流程变化 |
| Captain Document | pending 或待同步 | 抓取、分段、索引或失败后改变公开状态 |
| Assignment Policy | 未绑定 Inbox | 一个 Inbox 同一时刻只能使用一个有效策略 |
| Webhook | 按提交订阅事件 | 未提交事件集合不能解释为订阅全部 |
| SLA Policy | 按提交目标和工作时间规则 | 是否使用工作时间必须单独核对 |
| Contact Inbox | 由 Inbox 与 source_id 唯一识别 | 可承载渠道 HMAC、外部身份和会话上下文 |

## 4. 文本、标识和时间标准化

### 4.1 邮箱

- 比较前去除首尾空白；
- 账号内唯一性比较不应依赖大小写差异；
- 空邮箱不能作为跨请求稳定身份；
- 同一账号发生邮箱冲突时，应返回明确校验结果，不得静默覆盖另一联系人；
- 不同账号可以存在相同邮箱联系人。

### 4.2 电话号码

- 有效号码应标准化为带国家区号的国际格式；
- 缺少国家信息且无法可靠推断时，应返回校验错误或保持未确认状态；
- 同一账号内，标准化后的号码用于唯一性判断；
- 仅格式不同但含义相同的号码不得创建重复联系人。

### 4.3 外部标识

- identifier、source_id、provider_message_id 和 provider_call_id 属于不同命名空间；
- 外部标识的大小写是否敏感，以对应 Provider 的回调规则为准；
- 同一 source_id 只能在其 Inbox 范围内标识一个 Contact Inbox；
- 不能把同一外部标识跨 Inbox、跨 Account 全局复用；
- 展示编号和全局 ID 不是同一种标识，接口路径必须使用该入口规定的类型。

### 4.4 时间

- API 时间结果以带时区的标准时间或 Unix 时间表达；
- 工作时间按 Inbox 时区计算；
- 报表按请求时区或账号时区切分日期；
- 外部回调时间应保留事件来源时间，并单独记录本系统接收时间；
- 秒级和毫秒级时间不得混用；
- 夏令时切换日必须以时区规则计算，不能固定按 24 小时推算自然日。

## 5. 更新操作：合并、替换与删除

### 5.1 更新语义总表

| 功能 | 提交对象或集合时的规则 | 空值结果 | 删除指定内容的方式 |
|---|---|---|---|
| Contact additional_attributes | 与已有键合并 | 空对象通常不删除旧键 | 提交对应键的允许空值，或使用专门资料操作 |
| Contact custom_attributes | 与已有键合并 | 空对象通常不删除旧键 | 自定义属性删除入口提交键名集合 |
| Company custom_attributes | 非空对象与已有键合并 | 空对象为无变化 | 自定义属性删除入口提交键名数组 |
| Conversation custom_attributes | 整体替换 | 空对象表示清空 | 再次提交完整目标对象 |
| Conversation labels | 整体替换 | 空数组表示移除全部标签 | 提交剩余标签标题集合 |
| Team members | 整体替换成员集合 | 空数组表示清空成员 | 提交最终成员 ID 集合 |
| Inbox members | 整体替换成员集合 | 空数组表示清空成员 | 提交最终成员 ID 集合 |
| Conversation participants | 整体替换参与者集合 | 空数组表示清空参与者 | 提交最终参与者 ID 集合 |
| Webhook subscriptions | 按最终订阅集合保存 | 空数组通常无有效订阅 | 更新为最终事件集合 |
| Message | 普通更新不改变原始方向和身份 | 删除不接受以空内容替代 | 使用消息删除动作进行脱敏 |

### 5.2 整体替换的核对要求

执行替换型操作时必须核对：

1. 请求未包含的旧成员或旧键是否被移除；
2. 请求中重复 ID 是否被去重；
3. 不属于当前 Account 或当前 Inbox 的 ID 是否被拒绝；
4. 响应集合顺序是否属于稳定承诺；
5. 新增、移除对应事件是否各触发一次；
6. 空数组是有效清空还是校验错误。

### 5.3 增量合并的核对要求

执行合并型操作时必须核对：

1. 未提交旧键保持不变；
2. 新键被加入；
3. 同名键以本次合法输入覆盖；
4. 不允许的键被忽略还是返回错误；
5. null 是否表示删除，不能自行推断；
6. 合并后的对象在详情、列表、事件和导出中是否一致。

## 6. 唯一约束总表

| 对象或关系 | 唯一范围 | 冲突时的预期结果 |
|---|---|---|
| Account User | Account + User | 不重复创建成员关系 |
| Team Member | Team + User | 不重复加入同一团队 |
| Inbox Member | Inbox + User | 不重复加入同一 Inbox |
| Conversation Participant | Conversation + User | 不重复加入参与者 |
| Contact email | Account + 标准化邮箱 | 返回冲突或复用明确目标，不静默覆盖 |
| Contact phone_number | Account + 标准化号码 | 返回冲突或复用明确目标 |
| Contact identifier | Account + identifier | 一个账号内不可重复 |
| Contact Inbox | Inbox + source_id | 复用已有渠道身份，不产生重复身份 |
| Company domain | Account + 标准化 domain | 一个账号内不可重复 |
| Label title | Account + 标准化标题 | 不创建同名标签 |
| Team name | Account + 标准化名称 | 不创建同名团队 |
| Webhook URL | Account + URL | 同一账号不建立重复目标 |
| Assignment Policy name | Account + 名称 | 不创建同名策略 |
| Inbox Assignment Policy | Inbox | 同一 Inbox 只绑定一个策略 |
| Capacity Policy Inbox | Capacity Policy + Inbox | 同一绑定关系只存在一次 |
| Captain Assistant Inbox | Assistant + Inbox | 同一知识助手不重复绑定同一 Inbox |
| Captain Document external_link | Assistant + 外部链接 | 同一助手下不重复导入同一链接 |
| Data Import Item | Import + 外部条目标识 | 重试时复用条目，防止重复导入 |
| Data Import Mapping | Import + 映射类型或来源 | 同一映射不重复保存 |
| Call | Provider + provider_call_id | 重复回调更新原通话 |
| Provider Message | Provider 范围 + 外部消息 ID | 重复回调不得生成第二条消息 |

唯一性不等于全局唯一。所有带 Account、Inbox、Assistant 或 Provider 范围的条目，必须先固定归属范围再比较。

## 7. 跨归属边界校验

以下请求即使 ID 存在，也必须拒绝或表现为目标不可见：

- 把另一个 Account 的用户加入当前 Team；
- 把另一个 Account 的联系人加入当前 Conversation；
- 使用另一个 Inbox 的 source_id 创建消息；
- 为当前 Conversation 指定另一个 Account 的 assignee；
- 使用不属于当前 Assistant 的 Document；
- 在 Platform 操作中使用不属于授权 Account 的资源；
- 用网站聊天 token 访问另一个 Inbox 的会话；
- 用 Contact token 读取不属于该联系身份的消息；
- 用 Agent Bot token 操作未与该 Bot 关联的 Inbox 或 Conversation。

出于隔离要求，部分入口应返回“未找到”而不是泄露对象存在性。

## 8. 字段规模和集合边界

| 项目 | 边界或规则 | 超出后的结果 |
|---|---|---|
| Message content | 最长 150000 个字符 | 返回字段校验错误 |
| 单条消息附件 | 最多 15 个 | 返回字段校验错误 |
| 分页 page | 从 1 开始 | 非法值回退或返回校验结果，以入口约定为准 |
| 批量 ID 集合 | 只接受当前账号可见且类型正确的 ID | 非法项不得被静默当作成功项 |
| 自定义字段值 | 受字段类型和选项约束 | 类型、选项或格式错误应明确指出 |
| 文件 | 受安装配置、文件类型和渠道能力限制 | 上传拒绝、发送失败或外部渠道拒绝需区分 |

## 9. 删除、脱敏、解绑和延迟清理

### 9.1 四种生命周期结果

| 类型 | 定义 | 典型结果 |
|---|---|---|
| 立即删除 | 操作成功后目标立即不可查询 | 小型独立配置对象 |
| 延迟清理 | 先接受请求，关联内容随后清理 | Account、Inbox、Contact、Company 等大对象 |
| 内容脱敏 | 保留记录和时间线位置，但移除正文或附件 | Message 删除 |
| 解除关联 | 保留两侧对象，只移除它们的关系 | Company 与 Contact、Portal 与 Inbox 等 |

### 9.2 主要对象生命周期

| 对象 | 删除后的立即结果 | 后续结果 | 不应发生的结果 |
|---|---|---|---|
| Message | 正文变为已删除状态，deleted 为真，附件被移除 | 会话时间线保留消息位置和审计意义 | 物理消失导致相邻事件顺序改变 |
| Conversation | 删除请求被接受，随后不可正常访问 | 消息和相关记录随任务清理；Email 渠道需保留必要来源追踪 | 只删除列表项但留下可操作消息 |
| Contact | 在线处理期间可阻止删除；接受后进入清理 | 会话、渠道身份、备注等按关系清理 | 删除一个账号联系人影响另一个账号同邮箱联系人 |
| Contact Merge 来源联系人 | 合并完成后来源联系人不可用 | 会话、消息归属、渠道身份、备注等迁移到保留联系人 | 两边都保留可编辑副本 |
| Inbox | Inbox 与渠道停止使用 | 大量关联对象延迟清理 | 已删除 Inbox 继续接收并创建正常会话 |
| Company | Company 不再可查询 | Contact 保留，但解除 Company 关联 | 连带删除联系人 |
| Portal | Portal 不再公开可用 | Category、Article 等内容按关系清理，Inbox 解除关联 | 继续从旧公开入口返回内容 |
| Article/Category | 从帮助中心公开结果移除 | 搜索、缓存和统计随后收敛 | 删除后继续被新会话引用为有效公开内容 |
| Account Cloud 删除 | 先进入计划删除状态 | 默认等待期为 7 天，期满后执行清理 | 计划删除期间被当作永久立即删除 |
| Webhook/Integration Hook | 停止新事件投递 | 已经发出的请求不承诺可撤回 | 删除后仍产生新的投递任务 |
| Campaign | 停止后续触发或调度 | 已经交给外部渠道的消息不保证撤回 | 停用后继续产生新的目标批次 |
| Captain Document | 从知识集合移除 | 分段和检索结果随后清理 | 删除后继续作为新回答的知识来源 |

### 9.3 Message 删除的精确结果

消息删除必须同时验证：

- 消息 ID 保持不变；
- created_at 等时间线定位信息保持可解释；
- 正文不再返回原始敏感内容；
- deleted 状态变为真；
- 附件不可继续下载；
- 会话最后消息摘要不再泄露原文；
- 搜索结果不再返回原文；
- 实时事件和详情查询表达同一删除状态；
- 外部渠道已送达内容通常无法远程撤回，除非该渠道另有撤回能力。

### 9.4 延迟清理观察规则

收到成功响应不等于所有关联结果已经收敛。对延迟清理对象应记录：

1. 请求接受时间；
2. 目标立即可见性；
3. 关联对象开始变化时间；
4. 最终不可访问时间；
5. 搜索、报表、导出和实时事件的收敛时间；
6. 失败后的可重试或人工恢复入口。

不能通过固定等待几秒来判定完成，应查询对象状态或使用对应最终状态规则。

## 10. 联系人合并的数据规则

联系人合并不是简单删除。完成后应满足：

- 选定的保留联系人继续使用原 ID；
- 来源联系人的会话转移到保留联系人；
- 消息发送者归属按合并结果保持可追踪；
- Contact Inbox、备注和相关活动转移；
- 保留联系人已有非空基础资料优先；
- 只有保留联系人缺少的基础资料，才从来源联系人补全；
- 唯一字段冲突必须得到确定结果；
- 来源联系人最终不可继续独立访问；
- 合并过程失败时不得留下同一会话同时属于两个联系人；
- 同一合并请求重试不得重复迁移或生成重复关系。

## 11. 状态字段和派生字段

### 11.1 不可直接写入的派生信息

以下信息通常由业务动作产生，不应把普通更新字段当作等价入口：

- unread_count；
- last_activity_at；
- first_reply_created_at；
- waiting_since；
- last_seen_at；
- message delivery status；
- campaign processing/completed；
- report 汇总值；
- SLA 命中与超时状态；
- provider 健康或授权失效状态；
- AI Document 同步状态。

### 11.2 状态与时间必须联合核对

例如会话由 open 变为 resolved，不能只核对 status。还需核对：

- resolved 时间或相关活动是否产生；
- 未读数是否按规则变化；
- SLA 等待时间是否停止或重算；
- 自动化规则是否触发；
- 实时事件是否送达；
- 报表是否在允许延迟后反映变化；
- 客户后续发消息是否重开会话。

## 12. 列表、详情、事件和导出的字段一致性

同一对象可能在不同入口返回不同字段集合，但公共字段的值必须一致。

| 对照入口 | 必须一致的内容 | 允许差异 |
|---|---|---|
| 列表与详情 | ID、状态、归属、更新时间 | 详情可包含更多嵌套对象 |
| API 响应与实时事件 | 事件发生时刻的状态和关键字段 | 事件可为精简 Payload |
| 详情与搜索 | 标识、名称、可搜索正文、删除状态 | 搜索存在索引收敛延迟 |
| 详情与导出 | 业务值、时区换算、枚举含义 | 导出可使用表格列名和格式化文本 |
| 当前对象与报表 | 状态变化对应的计数和时长 | 报表存在聚合时间窗 |

允许差异必须在基线中注明最大延迟和归一化方式。

## 13. 必测边界场景

| 编号 | 场景 | 预期核对结果 |
|---|---|---|
| FDL-01 | 创建 Contact 不提交 contact_type | 最终为 visitor |

## 14. 一致性判定标准

本分册范围达到一致，必须同时满足：

1. 创建默认值逐字段一致；
2. 缺失、null、空文本、空数组和空对象的结果一致；
3. 合并型和替换型更新没有混用；
4. 所有唯一范围不产生重复有效对象；
5. 跨 Account、Inbox、Assistant 和 Provider 的归属校验一致；
6. 删除后采用相同的立即删除、延迟清理、脱敏或解绑方式；
7. 列表、详情、事件、搜索、报表和导出的公共字段最终一致；
8. 延迟结果在规定时间内到达同一最终状态；
9. 所有允许差异均登记在基线中；
10. 第 13 节场景全部通过。

仅字段名称相同、接口返回成功，不能证明数据行为一致。
