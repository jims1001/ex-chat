# 列表查询、分页、排序、筛选与容量边界

> 适用版本：Chatwoot 4.16.0
> 本分册统一说明列表型 API 的页码、每页数量、排序、搜索、筛选、批量数量和字段规模，避免数据量增加后出现漏读、重复读取或边界行为不一致。

## 1. 通用列表规则

| 项目 | 通用规则 |
|---|---|
| page | 从 1 开始；未提交时使用第 1 页 |
| per_page | 只有明确支持的入口才允许调用方指定 |
| sort / sort_by | 只接受该资源列出的排序值 |
| sort_order / direction | 通常为 asc 或 desc |
| q / query / search | 名称不同，搜索范围也不同，不能互换 |
| filter | 可为保存筛选 ID、状态筛选或结构化筛选对象，按具体入口解释 |
| total_count | 满足当前权限和筛选条件的总数量 |
| has_more | 当前结果之后是否还有可读取内容 |
| meta | 可能包含总数、当前页、每页数量和分类计数 |
| payload / data | 当前页对象集合 |

页码和每页数量必须使用整数。负数、0、非数字文本和超出上限的值按具体入口回退或返回校验错误，不得产生跨账号读取。

## 2. 列表响应的三种形态

| 形态 | 常见结构 | 使用方式 |
|---|---|---|
| Payload + Meta | payload 为对象数组，meta 为数量和页信息 | 优先读取 meta，而不是用数组长度推断总数 |
| 对象数组 | 顶层直接返回数组 | 由入口规定固定数量或完整集合 |
| 数据 + 独立计数 | data/payload 与 count、total_count、has_more 并列 | 同时保存当前页数量和总数量 |

空列表应返回空数组，而不是 null。没有下一页时，可以通过 total_count、has_more 或当前页数量判断，不能假定一定存在 next_page 字段。

## 3. 当前版本固定分页数量

| 资源或入口 | 每页或返回数量 | 是否可调 | 说明 |
|---|---:|---|---|
| Conversation 列表 | 默认 25 | 可由 CONVERSATION_RESULTS_PER_PAGE 调整 | 只影响标准分页路径 |
| Contact 列表、active、search、filter | 15 | 否 | search 额外返回 has_more 语义 |
| Notification | 15 | 否 | 默认排除已读和延后通知 |
| Call | 25 | 否 | 按 created_at 倒序 |
| Company | 25 | 否 | Feature 可用时生效 |
| Company Contacts | 15 | 否 | 只返回当前 Company 关联 Contact |
| Reporting Event | 25 | 否 | 按 created_at 倒序 |
| Applied SLA 违约列表 | 25 | 否 | 只对满足 SLA 条件的 Conversation 统计 |
| CSAT Survey Response | 25 | 否 | 指标和下载不使用同一分页结果 |
| Audit Log | 25 | 否 | Account 范围 |
| Captain Assistant Response | 25 | 否 | 支持 Assistant、Document、状态和文本筛选 |
| Captain Document | 25 | 否 | 同时返回筛选前后的计数语义需区分 |
| Captain Copilot Thread | 5 | 否 | Thread 列表 |
| Captain Copilot Message | 1000 | 否 | 单个 Thread 的消息历史 |
| Contact Attachment | 100 | 否 | Contact 范围附件 |
| Conversation Attachment | 100 | 否 | Conversation 范围附件 |
| Public Portal Article | 默认 25，最高 100 | 是 | per_page 小于 1 时回退为 25，超过 100 时按 100 |
| Public Portal Search | 10 | 否 | 搜索结果固定每页 10 条 |
| Category | 1000 | 否 | 大型 Portal 仍需按 page 读取 |
| Data Import error 摘要 | 最近 5 条 | 否 | 不是完整错误清单 |
| Data Import skip 摘要 | 最近 5 条 | 否 | 完整信息需使用对应下载或详情能力 |

分页数量属于当前版本合同。版本变化后应重新核对，不能把前端一次展示数量当作 API 固定数量。

## 4. Conversation 列表查询字段

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| page | integer | 1 | 标准分页页码 |
| inbox_id | integer | 当前用户可见的全部 Inbox | 只接受当前 Account 且当前用户可见 Inbox |
| team_id | integer | 不限定 Team | 只返回目标 Team 的 Conversation |
| assignee_type | enum | all 语义 | me、unassigned、assigned 或全部范围 |
| status | enum | open | open、resolved、pending、snoozed、all |
| q | string | 无 | 搜索 incoming 和 outgoing Message 正文 |
| labels | array 或标签列表 | 无 | 任一目标 Label 命中即可进入结果 |
| source_id | string | 无 | 按 Contact Inbox 的渠道身份筛选 |
| conversation_type | enum | 普通可见会话 | mention、participating、unattended |
| sort_by | enum | last_activity_at_desc | 见第 5 节 |
| updated_within | integer 秒 | 无 | 只返回最近指定秒数内更新的 Conversation |

### 4.1 关键组合规则

- 未提交 status 时只查询 open；
- status=all 才包含全部会话状态；
- 提交 q 时，正文搜索不再按默认 open 状态过滤；
- inbox_id 必须先经过当前用户 Inbox 可见范围限制；
- team_id 不自动扩大 Inbox 权限；
- labels 采用任一标签匹配，而不是必须同时拥有全部标签；
- conversation_type=participating 使用当前用户参与关系；
- conversation_type=mention 使用当前用户被提及关系；
- conversation_type=unattended 使用无人处理定义；
- updated_within 走最近更新时间窗口，不使用标准 page 分页，结果数量可能大于默认 25；
- q 只搜索 incoming 和 outgoing 正文，不应把 activity Message 当作聊天正文结果。

## 5. Conversation 排序值

| sort_by | 结果 |
|---|---|
| last_activity_at_asc | 最早活动在前 |
| last_activity_at_desc | 最近活动在前，默认 |
| created_at_asc | 最早创建在前 |
| created_at_desc | 最近创建在前 |
| priority_asc | 按优先级升序 |
| priority_desc | 按优先级降序 |
| waiting_since_asc | 等待起点较早在前 |
| waiting_since_desc | 等待起点较晚在前 |
| priority_desc_created_at_asc | 高优先级优先，同级按较早创建优先 |
| unread | 未读 Conversation 优先 |

当前版本仍兼容以下历史排序值：

| 历史值 | 当前等价含义 |
|---|---|
| latest | last_activity_at_desc |
| sort_on_created_at | created_at_asc |
| sort_on_priority | priority_desc |
| sort_on_waiting_since | waiting_since_asc |

未识别的 sort_by 按 last_activity_at_desc 处理。历史值属于兼容入口，新调用应使用当前明确值。

## 6. Contact 列表、搜索和排序

### 6.1 查询字段

| 字段 | 入口 | 说明 |
|---|---|---|
| page | index、active、search、filter | 每页 15 |
| q | search | 必填；搜索 name、email、phone_number、identifier |
| labels | index | 任一标签匹配 |
| include_contact_inboxes | 列表、详情、更新 | true 时包含渠道身份；未提交时默认为 true |
| inbox_id | create | 同时创建 Contact Inbox 时使用 |
| source_id | create | 与 inbox_id 一起标识渠道身份 |
| sort | 列表、搜索、筛选 | 选择排序字段 |
| direction | 列表、搜索、筛选 | asc 或 desc |
| payload | filter/export | 结构化筛选条件 |
| label | export | 导出标签筛选 |
| column_names | export | 选择导出列 |

q 为空时 search 返回 422，不返回全部 Contact。

### 6.2 可排序字段

| sort | 含义 |
|---|---|
| email | 邮箱 |
| name | 名称 |
| phone_number | 电话 |
| last_activity_at | 最近活动时间 |
| created_at | 创建时间 |
| company_name | Company 名称 |
| city | 城市 |
| country | 国家名称 |

### 6.3 Search 特殊返回

Contact search 为判断下一页，会额外读取一条记录：

- 响应最多仍返回 15 个 Contact；
- has_more 表示是否存在第 16 条候选结果；
- 当前页 contacts_count 不等同于所有搜索命中总数；
- 调用方应继续递增 page，直到 has_more 为 false；
- 不能把 has_more 缺失解释为 true。

## 7. Company 查询和排序

| 字段 | 说明 |
|---|---|
| page | 默认 1，每页 25 |
| q | 搜索时必填，匹配 name 或 domain |
| sort | name、domain、created_at、last_activity_at、contacts_count |
| direction | asc 或 desc |

Company search 的 q 为空时返回 422。Company Contacts 每页 15，可按 q 搜索 Contact 的 name、email、phone_number 或 identifier。

## 8. Notification 查询

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| page | integer | 1 | 每页 15 |
| includes | string array | 空数组 | 可包含 read、snoozed |
| sort_order | enum | desc | 按 last_activity_at 的 asc 或 desc |

默认结果：

- 排除 read 通知；
- 排除 snoozed 通知；
- unread_count 为当前筛选范围下的未读数量；
- includes 包含 read 时，列表可含已读，但 unread_count 仍只统计未读；
- includes 包含 snoozed 时，延后通知可以进入列表。

每个用户每个 Account 的通知读取范围独立。当前系统定期只保留最近 300 条通知，旧通知可能被清理。

## 9. Call 查询

| 字段 | 类型 | 说明 |
|---|---|---|
| page | integer | 默认 1，每页 25 |
| status | enum | 按通话展示状态筛选 |
| direction | enum | incoming 或 outgoing 等通话方向 |
| inbox_id | integer | 目标 Voice/WhatsApp Calling Inbox |
| agent_id | integer | accepted_by_agent |
| since | Unix 时间 | 起始时间 |
| until | Unix 时间 | 结束时间 |

since 和 until 同时存在时才应用完整日期范围。Administrator 和具备 report_manage 权限的角色可查看 Account 范围；其他身份只查看本人处理且仍可访问 Conversation 的 Call。

## 10. Reporting Event、Applied SLA 和 CSAT

### 10.1 Reporting Event

| 字段 | 说明 |
|---|---|
| page | 默认 1，每页 25 |
| since / until | 日期范围 |
| inbox_id | Inbox 筛选 |
| user_id | 成员筛选 |
| name | 事件名称筛选 |

默认按 created_at 倒序。

### 10.2 Applied SLA

| 字段 | 说明 |
|---|---|
| page | 默认 1，每页 25 |
| since / until | 日期范围 |
| inbox_id | Inbox |
| team_id | Team |
| sla_policy_id | SLA Policy |
| label_list | Label 标题集合 |
| assigned_agent_id | assignee |
| sort / direction | 当前支持 created_at 排序 |

列表只返回 missed Applied SLA；metrics 同时使用全部应用数量和 miss 数量计算 hit rate；download 返回同一筛选范围的违约明细，不受当前页限制。

### 10.3 CSAT Survey Response

| 字段 | 说明 |
|---|---|
| page | 默认 1，每页 25 |
| since / until | created_at 范围 |
| user_ids | assignee ID 集合 |
| inbox_id | Inbox |
| team_id | Team |
| rating | 评分 |
| sort / direction | created_at 排序 |

metrics 返回筛选范围的总响应数量和各 rating 数量；已发送问卷总数使用同一日期范围，但不等于已提交响应数量。

## 11. Portal、Category 和 Article 查询

### 11.1 Account Article

| 字段 | 说明 |
|---|---|
| locale | 文章语言 |
| query | 标题或正文搜索 |
| page | 页码 |
| category_slug | Category 范围 |
| status | draft、published、archived 等状态 |
| author_id | 作者成员 |

列表排序可按位置或更新时间，由当前入口和查询上下文决定。

### 11.2 Public Portal Article

| 字段 | 默认或范围 | 说明 |
|---|---|---|
| query | 无 | 搜索公开文章 |
| locale | Portal 默认语言 | 限定语言 |
| sort | 当前公开排序值 | 不支持值按入口默认 |
| status | 公开可见状态 | 普通客户不应读取草稿 |
| page | 1 | 页码 |

## 12. Captain 列表查询

### 12.1 Document

| 字段 | 可选值或说明 |
|---|---|
| assistant_id | 只返回目标 Assistant 的 Document |
| page | 默认 1，每页 25 |
| source | web、pdf；其他或缺失表示全部 |
| filter | stale、synced、syncing、failed |
| sort | recently_created；其他或缺失按 updated_at 倒序 |
| search_key | 匹配 name 或 external_link |

stale 和 synced 只适用于可同步的网页类 Document。PDF 不应被错误归为网页过期状态。

### 12.2 Assistant Response

| 字段 | 说明 |
|---|---|
| assistant_id | Assistant 筛选 |
| document_id | Document 筛选 |
| status | 候选回答状态 |
| search | 文本搜索 |
| page | 默认 1，每页 25 |

### 12.3 Copilot

- Thread 每页 5；
- 单个 Thread 的 Message 每页 1000；
- 页码默认 1；
- Message 数量超过 1000 时必须继续读取后续页；
- 删除 Thread 后不得继续通过旧 ID 获取 Message。

## 13. Search 时间与范围边界

| 搜索类型 | 范围规则 |
|---|---|
| Conversation q | incoming 和 outgoing Message 正文 |
| Contact q | name、email、phone_number、identifier |
| Company q | name、domain |
| Article query | 当前 Portal、语言和权限范围 |
| Captain Document search_key | name、external_link |
| 高级 Message Search | 最长回看 90 天 |

高级 Message Search 超出 90 天时，应缩小时间范围或分段查询。搜索结果存在索引收敛延迟，最终必须与对象详情和删除状态对账。

## 14. 批量操作边界

| 功能 | 当前上限 | 处理规则 |
|---|---:|---|
| 通用 Bulk Action | 100 个对象 | 超出时拆分；每批仍需保持 Account 隔离 |
| 单批外部 HTTP 调用 | 25 个目标 | 控制第三方压力，后续目标进入下一批 |
| 自动分配单批处理 | 100 个 Conversation | 可由 AUTO_ASSIGNMENT_BULK_LIMIT 调整 |
| Captain Document 自动同步 | 每 Account 每轮 50 | 可由安装配置调整 |
| Captain Document 自动同步 | 全局每轮 1000 | 可由安装配置调整 |
| Data Import 错误摘要 | 5 条 | 摘要不是完整失败集合 |

批量请求返回成功，不代表每个对象均已完成。需要逐对象状态、失败列表或异步最终状态确认。

## 16. 消息和发送速率边界

| 项目 | 默认边界 | 统计范围 |
|---|---:|---|
| 单个 Conversation Message | 200 次/分钟 | 可由 CONVERSATION_MESSAGE_PER_MINUTE_LIMIT 调整 |
| Account 非渠道邮件 | 100 封/天 | 可由 ACCOUNT_EMAILS_LIMIT 和套餐配置调整 |
| 全局 HTTP 请求 | 3000 次/分钟 | IP；其他具体入口限制见 36 分册 |

达到消息速率上限时不得产生超过上限的外部发送。调用方应在 429 后查询 Message 是否已经创建，再决定是否重试。

## 17. 业务数量与展示数量

| 功能 | 数量 | 含义 |
|---|---:|---|
| Portal popular categories | 最多 3 | 公开首页精选分类 |
| Portal popular articles | 最多 6 | 公开首页精选文章 |
| 用户保留 Notification | 最近 300 | 超出的旧通知可被清理 |
| 登录 Session | 默认最多 25 | 超限时按会话规则处理 |
| Feature 单列容量 | 最多 63 个标志位 | 当前 68 个 Feature 分布在多个标志范围，不影响 Feature Key 使用 |

展示数量不等于业务对象总量。例如 popular articles 只限制首页精选，不限制 Portal 总文章数。

## 18. Capacity Policy 边界

| 字段 | 规则 |
|---|---|
| name | 必填，最多 255 字符 |
| conversation_limit | 0 或更大的整数 |
| inbox_id | 必须属于当前 Account |
| Policy + Inbox | 同一组合只允许一个容量限制 |

conversation_limit=0 是合法值，表示该策略下目标 Inbox 不提供可自动分配容量，不能把 0 当作字段缺失。

## 19. 页码变化期间的数据一致性

当列表读取过程中对象新增、更新或删除，基于 page 的分页可能出现移动。需要稳定全量读取时：

1. 固定排序字段和方向；
2. 优先选择唯一时间和 ID 组合可解释的排序；
3. 保存读取开始时间；
4. 处理页间重复 ID；
5. 完成后按 total_count 或时间范围对账；
6. 对不断变化的 Conversation 列表使用更新时间窗口增量校验；
7. 删除造成当前页缩短时，不得直接判断已经到最后一页；
8. 权限变化后应重新开始读取，而不是继续旧页码。

## 20. 不同计数不能混用

| 字段 | 含义 |
|---|---|
| current page length | 当前响应数组长度 |
| total_count | 当前筛选范围总数 |
| contacts_count | Company 关联数量或当前 Contact 响应计数，按对象解释 |
| unread_count | 当前身份和筛选范围未读数量 |
| all_count | Conversation 当前可见范围总数 |
| mine_count | 分配给当前用户的 Conversation 数量 |
| assigned_count | 已分配 Conversation 数量 |
| unassigned_count | 未分配 Conversation 数量 |
| has_more | 当前游标或页后是否还有结果 |

计数必须与同一权限、Inbox、Team、状态和时间范围配对。不能把列表过滤后的 total_count 与未过滤的报表总数直接比较。

## 21. 边界错误与回退

| 输入 | 预期处理 |
|---|---|
| page 缺失 | 使用 1 |
| Public Article per_page 缺失 | 使用 25 |
| Public Article per_page=0 或负数 | 回退 25 |
| Public Article per_page>100 | 使用 100 |
| Contact search q 为空 | 422 |
| Company search q 为空 | 422 |
| 未知 Conversation sort_by | 回退 last_activity_at_desc |
| 未知 Captain Document filter | 不应用该筛选 |
| since 或 until 只提供一个用于 Call | 不应用完整日期范围 |
| Bulk Action 超过 100 | 拒绝或拆分，不得静默漏掉后半部分 |
| URL 超过 2048 | 422 |
| 自定义属性文本超过 1500 | 422，指出对应键 |

## 22. 完整性验收

本分册通过必须满足：

1. 所有固定分页数量与当前版本一致；
2. Conversation 的默认 status、搜索例外、排序和 updated_within 行为一致；
3. Contact、Company、Notification、Call、SLA、CSAT、Portal 和 Captain 查询字段均有边界案例；
4. total_count、has_more、unread_count 和分类计数没有混用；
5. 100、25、15、10、5、1000 等不同分页大小按资源正确使用；
6. 批量上限不造成静默漏处理；
7. 字段长度、附件、URL、AI 内容和自定义属性边界均返回确定错误；
8. 达到发送速率后无额外外部副作用；
9. 列表变化期间通过 ID 去重和最终对账保证完整读取；
10. 安装配置改变默认上限后，基线和验收结果同步更新。
