# 业务动作、事件、副作用与跨入口一致性

> 适用版本：Chatwoot 4.16.0
> 本分册说明一个业务动作除同步响应外，还会影响哪些对象、通知、报表、自动化、Webhook、Bot、集成和实时事件，并规定这些结果之间如何对照。

## 1. 为什么需要副作用字典

同一个“发送消息”动作可能同时产生：

- Message；
- Conversation last_activity_at 和 waiting_since 变化；
- 未读数量变化；
- 实时事件；
- Account Webhook；
- API Inbox Webhook；
- Agent Bot 投递；
- Automation Rule；
- Mention Notification；
- 普通新消息 Notification；
- 第三方 Integration Hook；
- 报表事件；
- Provider 外部请求。

只核对 Message 创建成功，会漏掉这些连带结果。完整一致性必须按“主对象 + 直接关联 + 业务变化事件 + 外部投递 + 最终统计”整体判定。

## 2. 五层观察模型

| 层次 | 内容 | 典型观察入口 |
|---:|---|---|
| 1 | 同步响应 | 当前 API 响应和状态码 |
| 2 | 主对象与直接关联 | 详情、列表、关联资源 |
| 3 | 业务变化事件 | 实时事件、活动时间线、通知 |
| 4 | 外部副作用 | Webhook、Agent Bot、Provider、Integration Hook |
| 5 | 派生结果 | 报表、SLA、搜索、AI 知识、导出和审计 |

上层成功不自动证明下层成功。每一层都要记录自己的接收时间和最终状态。

## 3. 当前版本业务变化名称总表

当前版本定义 37 个业务变化名称。这些名称用于产品不同能力之间传递变化；只有 19 分册明确列出的 Webhook 和实时事件属于外部订阅合同。

## 4. Conversation 创建的完整副作用

| 顺序层 | 可能结果 | 必须满足的条件 |
|---|---|---|
| 主对象 | 新 Conversation，默认 open | Contact Inbox、Account、Inbox 有效 |
| 分配 | Agent、Team、Bot 或未分配 | 创建入口、自动分配和策略决定 |
| 参与者 | 已有 assignee 可加入 participants | 不产生重复成员关系 |
| Notification | 向 Inbox 成员发送创建通知 | Conversation 非 pending |
| Automation | 执行 conversation_created 规则 | 规则 active、条件匹配且不是应跳过的自动回复场景 |
| Webhook | conversation_created | api_and_webhooks 可用且订阅匹配；API Inbox 可投递自身 Webhook |
| Agent Bot | 由后续状态或 Message 事件处理 | Bot 已绑定或为 Conversation assignee |
| Integration Hook | LeadSquared 等支持的 Hook | Hook active 且事件在支持范围 |
| 实时事件 | conversation.created | 只发送给可见成员和当前 Contact |
| 报表 | 后续打开、回复、解决时产生时长事件 | 创建本身不等于 First Response 或 Resolution |

如果创建请求同时包含第一条 Message，还要叠加第 5 节的全部消息副作用。

## 5. Message 创建的完整副作用

### 5.1 所有 Message 的公共变化

- Message 获得稳定 ID；
- 关联 Conversation、Inbox、Account 和 sender；
- Conversation last_activity_at 或相关摘要按消息类型变化；
- last_non_activity_message 只考虑非 activity Message；
- 消息可见范围由 private、message_type 和身份决定；
- message.created 实时事件按可见范围发送；
- Webhook、Bot 和 Integration Hook 只对符合发送条件的 Message 生效。

### 5.2 Incoming Message

| 副作用 | 说明 |
|---|---|
| 未读数量 | 增加相应成员或会话未读状态 |
| Conversation 状态 | 可能从 resolved、pending 或 snoozed 恢复 open，按渠道和设置决定 |
| 自动分配 | 未分配 Conversation 可进入分配流程 |
| Notification | 发送新消息通知；Mention 另行产生通知 |
| Automation | 执行 message_created 条件和动作 |
| Agent Bot | 向 Conversation Bot 和有效 Inbox Bot 投递 |
| Account/API Inbox Webhook | 投递 message_created |
| Integration Hook | Slack、Dialogflow 等支持的连接执行 |
| SLA | waiting_since、首次响应目标或下一次回复目标开始计算 |

### 5.3 Outgoing Message

| 副作用 | 说明 |
|---|---|
| Provider 发送 | 仅非 private 且渠道允许时发送到外部 |
| 首次回复 | 第一条符合条件的人工回复产生 first.reply.created |
| 后续回复 | 存在 waiting_since 时产生 reply.created |
| 报表 | First Response 或 Reply Time 使用秒和工作时间秒记录 |
| Contact 实时事件 | 客户可见的消息发送给 Contact 连接 |
| 状态 | sent 后由 Provider 回调更新 delivered、read 或 failed |

### 5.4 Activity Message

- 用于会话时间线说明状态、分配或系统动作；
- 不应作为 Conversation 正文搜索结果；
- 不应被当作客户消息发送给 Provider；
- 不进入 Automation 的普通 message_created 处理；
- 不应成为 last_non_activity_message；
- 是否进入成员实时事件按当前活动类型决定。

### 5.5 Private Message

- 仅账号成员可见；
- 不发送给 Contact；
- 不发送到普通外部渠道；
- 不应出现在 Public API；
- Mention 可以产生账号成员通知；
- 外部 Webhook 是否过滤必须按 webhook_sendable 条件验收。

## 6. Message 更新的副作用

| 更新类型 | 主对象变化 | 连带结果 |
|---|---|---|
| sent → delivered | status、外部时间或附加状态 | message.updated、实时刷新、Webhook/Bot 条件投递 |
| delivered → read | status | 同上，且不得被后到 delivered 降级 |
| 任意可发送状态 → failed | status、external_error | 失败提示、恢复入口、message.updated |
| failed 重试 | status 重置为 sent，清理当前内容错误信息 | 新的外部发送尝试，不创建无法解释的重复 Message |
| CSAT 交互提交 | submitted_values 或相关内容属性 | message.updated 后建立或更新 CSAT Response |
| Message 删除 | deleted、正文脱敏、附件移除 | 搜索和摘要收敛、实时更新；不等于外部撤回 |

message.updated 可能被 Account Webhook、API Inbox Webhook、Agent Bot 和支持 message.updated 的 Integration Hook 同时消费。

## 7. Conversation 状态变化副作用

### 7.1 open

- 产生 conversation.opened；
- status 实际变化时产生 conversation.status_changed；
- Automation 可执行 conversation_opened；
- Agent Bot 接收 opened 和 status changed；
- 报表记录首次打开为 0，重新打开记录距最近一次 resolved 的时间；
- snoozed_until 应按状态规则清理；
- 实时事件刷新成员和客户可见状态。

### 7.2 resolved

- 产生 conversation.resolved 和 conversation.status_changed；
- Automation 可执行 conversation_resolved；
- Reporting Event 记录从 Conversation 创建到解决的时长和工作时间时长；
- 若 active Bot 处理且没有 User outgoing Message，可额外记录 bot resolved；
- SLA 停止或结算对应目标；
- CSAT 开启时触发调查消息；
- Agent Bot 接收 resolved 和 status changed；
- LeadSquared 等支持 resolved 的 Integration Hook 可执行；
- Captain active 时，可按 feature_memory 生成 Contact Notes，按 feature_faq 生成并去重 FAQ；
- 客户后续发送消息是否重开，由 Inbox 设置决定。

### 7.3 pending

- status 变化产生 conversation.status_changed；
- 创建通知和分配通知会跳过 pending Conversation；
- Agent Bot 失败后是否保持 pending 由 keep_pending_on_bot_failure 决定；
- pending 不等于 resolved，报表和 CSAT 不应按解决处理。

### 7.4 snoozed

- status 变化并设置 snoozed_until；
- 到期或新消息到达后按规则恢复 open；
- 到期恢复应产生一次有效状态变化，不能重复打开；
- 报表、SLA 和通知按恢复后的状态继续。

## 8. 分配和 Team 变化副作用

### 8.1 assignee.changed

| 条件 | 结果 |
|---|---|
| 新 assignee 有效 | 更新 Conversation assignee |
| notifiable_assignee_change 为真且非 pending | 向新 assignee 创建 assignment Notification |
| assignee 为 User | 将该 User 加入 Conversation participants，已有关系复用 |
| 实时范围允许 | 发送 assignee.changed |
| 自动分配竞争 | 只有一个请求取得未分配 Conversation |

当 Team 变化导致 assignee 被清空时，不创建没有接收人的分配 Notification。

### 8.2 team.changed

- 更新 Conversation team；
- 可能清空不再适用的 assignee；
- 改变可见范围和可分配成员；
- 发送 team.changed 实时事件；
- Automation、报表和筛选后续使用新 Team；
- Team 成员关系不自动变成 Inbox 成员关系。

## 9. Notification 副作用

| 触发 | Notification 类型或结果 | 跳过条件 |
|---|---|---|
| Conversation created | conversation_creation，发给 Inbox Members | Conversation pending |
| Bot handoff | conversation_creation，发给 Inbox Members | Conversation pending |
| Assignee changed | conversation_assignment，发给新 assignee | assignee 空、不可通知、Conversation pending |
| Message created | Mention 和新消息通知 | 按私密、发送者、可见范围和偏好过滤 |

Notification 新建、更新和删除分别产生对应实时事件，并携带 unread_count 和 count。用户通知偏好可以阻止邮件或推送，但不应错误改变业务 Conversation。

## 10. Automation 副作用

Automation 当前处理以下触发：

- conversation_created；
- conversation_updated；
- conversation_opened；
- conversation_resolved；
- message_created。

跳过规则：

- 由 Automation 自身产生的后续变化不得再次无条件触发同一链路；
- activity Message 不进入普通 message_created 自动化；
- auto reply Email 不进入普通 message_created 自动化；
- 标记为 auto_reply 的 Conversation 在创建或打开事件中跳过自动回复型处理；
- 只有 active 规则执行；
- 条件不匹配时没有动作副作用。

同一个事件匹配多条规则时，各规则均可能执行，动作顺序和防循环见 18 分册。

## 11. Webhook 副作用

| 事件 | Account Webhook | API Inbox Webhook | changed_attributes |
|---|---:|---:|---|
| conversation_created | 是 | 是 | 否 |
| conversation_updated | 是 | 是 | 是 |
| conversation_status_changed | 是 | 是 | 是 |
| conversation_typing_on/off | 是 | 是 | is_private 单独提供 |
| message_created | 条件是 | 条件是 | 否 |
| message_updated | 条件是 | 条件是 | 通过 Message 当前状态解释 |
| webwidget_triggered | 是 | 是 | event_info |
| contact_created | 是 | 否 | 否 |
| contact_updated | 有实际变化时 | 否 | 是 |
| inbox_created | 是 | 否 | 否 |
| inbox_updated | 有实际变化时 | 否 | 是 |

Account Webhook 还要求 api_and_webhooks Feature 可用并订阅当前事件。API Inbox Webhook 只使用目标 API Channel 自身 webhook_url。

同一业务变化同时投递两类 Webhook 时，会有不同 delivery_id；接收方应以业务对象 ID 和事件时间进行业务去重，以 delivery_id 进行单次投递去重。

## 12. Agent Bot 副作用

Agent Bot 接收：

- conversation_opened；
- conversation_resolved；
- conversation_status_changed；
- conversation_updated；
- message_created；
- message_updated；
- webwidget_triggered。

接收 Bot 集合由两部分合并去重：

1. 当前 Conversation assignee Agent Bot；
2. 当前 Inbox active Agent Bot。

同一个 Bot 同时满足两种关系时只投递一次。Bot 必须具有 outgoing_url；非 Webhook Bot 不按此方式投递。

## 13. Integration Hook 副作用矩阵

| App | message.created | message.updated | contact.updated | conversation.created | conversation.resolved |
|---|---:|---:|---:|---:|---:|
| Slack | 是 | 是 | 否 | 否 | 否 |
| Dialogflow | 是 | 是 | 否 | 否 | 否 |
| Google Translate | 是 | 否 | 否 | 否 | 否 |
| LeadSquared | 否 | 否 | 是 | 是 | 是 |
| Linear | 是 | 否 | 否 | 否 | 否 |

补充规则：

- disabled Hook 不执行；
- Inbox 级 Hook 只处理该 Inbox 的 Message；
- Account 级 Hook 按当前 App 支持事件执行；
- 一个 Account 可有多个 Hook，每个有效 Hook 各自产生自己的副作用；
- Hook 失败不能回滚已成功创建的 Message 或 Conversation；
- 恢复和重试必须使用业务对象 ID 去重。

## 14. Reporting Event 副作用

| 业务变化 | Reporting Event name | value 口径 | business hours 口径 |
|---|---|---|---|
| conversation.resolved | conversation_resolved | resolved 时间 - Conversation created_at | 同区间工作时间秒数 |
| Bot 无人工 outgoing 后解决 | conversation_bot_resolved | 同解决时长 | 同区间工作时间秒数 |
| first.reply.created | first_response | 首次回复 - 最近非人工活动起点 | 同区间工作时间秒数 |
| reply.created | reply_time | 回复时间 - waiting_since | 同区间工作时间秒数 |
| conversation.bot_handoff | conversation_bot_handoff | 交接时间 - Conversation created_at | 同区间工作时间秒数 |
| Captain 推断解决 | conversation_captain_inference_resolved | 推断时间 - Conversation created_at | 当前事件不要求相同工作时间值 |
| Captain 推断转人工 | conversation_captain_inference_handoff | 推断时间 - Conversation created_at | 当前事件不要求相同工作时间值 |
| conversation.opened | conversation_opened | 首次打开为 0；重开为距最近 resolved 的秒数 | 重开区间工作时间秒数 |

bot handoff 对同一 Conversation 只保留一个有效报表事件，避免重复交接导致汇总重复。原始 Reporting Event 和汇总结果可能存在短暂时间差，最终必须可重建和对账。

## 15. CSAT 副作用

| 触发 | 条件 | 结果 |
|---|---|---|
| conversation.status_changed | Conversation 最终为 resolved，Inbox CSAT 开启 | 发送或安排 CSAT Message |
| message.updated | 目标 Message 为 input_csat | 建立或更新 CSAT Survey Response |

重复 resolved 事件不得重复发送同一轮 CSAT。客户重复提交的处理必须符合 Message submitted_values 和 CSAT 更新规则。

## 16. Captain 副作用

Conversation resolved 时，只有同时满足以下条件才触发 Captain 后续能力：

- Inbox Captain active；
- Inbox 绑定有效 Assistant；
- feature_memory 或 feature_faq 在 Assistant config 中开启；
- AI Provider、模型、额度和凭据可用。

| Feature | 结果 |
|---|---|
| feature_memory | 根据 Conversation 生成并更新 Contact Notes |
| feature_faq | 根据 Conversation 生成 FAQ 候选并去重 |

Conversation 已解决不代表 AI 任务同步完成。Notes 和 FAQ 必须按各自状态确认，失败不能回滚 resolved。

## 17. Campaign 副作用

campaign.triggered 包含：

- contact_inbox；
- event_info.campaign_id；
- event_info.custom_attributes；
- 其他 Conversation additional_attributes。

只有 campaign_id 存在时才进入 Campaign Conversation 建立流程。最终应：

- 使用 Contact Inbox 定位客户渠道身份；
- 以 Campaign 显示标识定位目标 Campaign；
- 把 custom_attributes 写入 Conversation 对应字段；
- 把其他 event_info 写入 additional_attributes；
- 不因同一客户事件重放创建无法解释的重复 Conversation 或 Message。

## 18. Contact 生命周期副作用

### 18.1 Contact 创建

- Contact 主对象建立；
- 可选建立 Contact Inbox；
- Account Webhook contact_created；
- 支持的 Integration Hook；
- contact.created 实时事件；
- 头像 URL 处理为独立结果；
- 不自动创建 Conversation，除非入口同时明确要求。

### 18.2 Contact 更新

- 只有实际字段变化才应发送有效 contact_updated Webhook；
- changed_attributes 表达前值和后值；
- Integration Hook 可接收 contact.updated；
- 实时事件刷新 Contact；
- 自定义属性采用合并或删除指定键规则；
- 不因名称更新改变 Contact Inbox source_id。

### 18.3 Contact 合并

- 来源 Contact 会话、消息归属、Contact Inbox 和备注迁移；
- contact.merged 实时事件；
- Conversation 可产生 contact_changed；
- 来源 Contact 最终不可继续使用；
- Webhook 和搜索在允许时间内收敛；
- 不得为迁移对象逐条制造新的业务创建事件。

### 18.4 Contact 删除

- 在线 Contact 可被阻止删除；
- 接受后产生 contact.deleted 实时事件；
- Webhook、搜索和列表最终不再返回；
- 关联清理按 34 分册执行；
- 其他 Account 的同邮箱 Contact 不受影响。

## 19. Inbox 变化副作用

| 动作 | 直接结果 | 连带结果 |
|---|---|---|
| 创建 Inbox | Inbox + Channel | inbox_created Webhook、缓存刷新、成员和 Bot 后续绑定 |
| 更新普通字段 | Inbox 变更 | 有实际变化时 inbox_updated、Widget 或渠道配置刷新 |
| 更新工作时间 | working_hours、timezone | 在线状态、SLA、Campaign 和离线消息规则变化 |
| 更新成员 | Inbox Members 替换 | 会话可见范围、自动分配候选和通知接收者变化 |
| 绑定 Bot/Assistant | 关系变化 | 后续事件投递和 AI 处理变化 |
| 重置 API Token | 新 Token 生效 | 旧 Token 按规则失效，Webhook URL 不自动改变 |
| 删除 Inbox | 立即停止正常使用 | 渠道、会话和关联对象延迟清理 |

## 20. 副作用顺序和一致性

以下顺序可以依赖：

1. 主对象先满足有效状态；
2. 业务变化以已保存对象为依据；
3. 下游异步结果最终引用同一业务对象 ID；
4. 外部失败不能撤销已经确认的主对象，除非该动作明确定义整体失败；
5. 重试不得创建重复主对象或重复外部副作用。

以下顺序不能依赖：

- Account Webhook 与实时事件谁先到达；
- Notification 与 Automation 谁先完成；
- 多个 Webhook URL 之间的全局顺序；
- Provider 状态回调与本地实时事件的绝对顺序；
- 搜索、报表和导出同时收敛；
- Captain Notes 与 FAQ 谁先完成。

## 21. changed_attributes 和 previous_changes

| 字段 | 作用 | 使用规则 |
|---|---|---|
| changed_attributes | Webhook 中表达对象字段的前值和后值 | 只处理出现的键，不推断未出现字段改变 |
| previous_changes | 实时事件或 Integration Hook 的变化摘要 | 用于局部刷新和状态判断 |

空变化：

- Contact 和 Inbox 的普通更新不应发送有效 updated Webhook；
- Conversation 是否发送 updated 还取决于当前业务动作；
- Message status 重复回调不应制造重复业务副作用；
- changed_attributes 的字段顺序不属于合同。

## 22. 失败隔离规则

| 失败项 | 不应回滚 | 需要的恢复 |
|---|---|---|
| Account Webhook | 已创建 Message/Conversation | delivery_id 对账或业务重放 |
| Agent Bot | 客户原始 incoming Message | Conversation 转 open 或保持 pending |
| Integration Hook | 主业务对象 | 修复 Hook 后按对象 ID 补偿 |
| Notification | Conversation/Message | 恢复通知任务，不重复业务动作 |
| Reporting 汇总 | 原始 Reporting Event | 重建或重新汇总 |
| Captain Notes/FAQ | resolved Conversation | 修复 AI 条件后重新处理 |
| Provider 状态回调 | 已接受的 outgoing Message | 状态查询或等待回调 |
| 搜索更新 | 主对象 | 等待收敛或重新建立搜索结果 |
