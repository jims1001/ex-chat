# 基础层总纲、权威顺序与边界

## 1. 目标

本分册把整个系统共同依赖的规则固定为基础层。基础层的目的不是把所有功能集中到一个模块，而是让所有独立模块使用同一组不可绕过的合同。

## 2. 基础层分层

| 层级 | 名称 | 统一内容 | 不允许包含 |
|---:|---|---|---|
| F0 | 合同内核 | ID、时间、版本、请求上下文、错误、Schema、兼容规则 | 客户、会话、消息等业务规则 |
| F1 | 数据完整性 | 所有权、生命周期、原子性、幂等、Change、对账 | 第二业务数据源 |
| F2 | 访问与安全 | 身份、Account、Role、Inbox、Feature、套餐、Scope、隐私 | 领域状态机 |
| F3 | 交互合同 | Command、Query、Event、ORC、API、插件能力 | 跨模块共享事务 |
| F4 | 可靠性 | 超时、重试、限流、隔离、积压、容量、监控、恢复 | 修改业务事实的捷径 |
| F5 | 审计与合规 | Local Journal、集中不可变账本、完整性、保留、导出 | 业务对象当前状态 |

F0 至 F5 是逻辑层，不要求由单一服务承载。每个模块实现自身范围内的基础能力，AUD、API、ORC、IAM、TEN 等模块分别承担集中职责。

## 3. 基础层和业务层边界

| 基础层负责 | 业务模块负责 |
|---|---|
| 统一身份和上下文表达 | 决定本领域动作是否符合业务状态 |
| 通用权限决策输入和拒绝方式 | 定义对象级业务权限和状态限制 |
| 通用对象、版本和生命周期合同 | 定义具体对象字段和允许转换 |
| Command、Query、Event 和流程格式 | 执行领域命令并发布事实 |
| 数据变化的强制记录和对账 | 拥有业务数据和计算真实 Diff |
| API 入口、错误、分页和兼容规则 | 提供领域动作和字段语义 |
| 插件、Provider 和外部调用隔离 | 决定哪些能力允许扩展 |
| 故障、重试和恢复框架 | 定义业务补偿和不可逆边界 |

基础层不能重新实现业务模块规则；业务模块不能自行创建与基础层冲突的认证、错误、审计或插件机制。

## 4. 权威决策顺序

遇到冲突时按以下顺序处理：

1. 检查是否违反本基础层的零容忍规则；
2. 检查目标版本、部署形态和适用 Feature；
3. 定位唯一权威模块和数据所有者；
4. 使用对应模块的具体业务规则；
5. 使用专项 API 字段和 Provider 差异；
6. 仍有差异时登记批准差异，不能静默选择既有行为。

## 5. 零容忍规则

以下内容不能通过批准差异长期绕过：

- 跨 Account 数据泄露；
- 未认证或未授权写入；
- 模块直接修改其他模块内部数据；
- 同一业务对象存在两个权威来源；
- 模块依赖形成循环；
- 成功数据变化没有 Local Change Journal 和 change_id；
- 密码、Token、Secret、MFA Secret 或完整支付凭证被记录或回显；
- 重复请求制造重复支付、重复消息、重复客户或重复外部动作；
- 不可逆动作被伪装为可以直接回滚；
- 插件或 Provider 绕过 Scope、签名、Account 和对象权限；
- 无证据将任务标记为完成。

## 6. 基础层公共能力

| 能力 | 主要承载者 | 使用方 |
|---|---|---|
| 身份验证与 Session | IAM | 所有入口和模块 |
| Account、成员、角色 | TEN | 所有业务模块 |
| Feature、套餐、额度 | ENT | API 和受限能力模块 |
| API 合同和外部身份映射 | API | Account、Widget、Public、Platform、Callback 等入口 |
| 流程与因果链 | ORC | 跨模块流程 |
| 日志合同和集中账本 | L0 Local Capture、AUD | 所有写模块 |
| 插件安装、Scope 和密钥 | EXT | 插件与外部能力 |
| 安装配置与版本 | SYS | 全部模块 |

模块可以独立运行，但这些公共能力必须通过稳定合同获得，不能复制其权威状态。

## 7. 公共处理顺序

一次外部写动作统一经过：

1. 入口协议、大小和基础频率检查；
2. 身份、签名、Token 或 Session 验证；
3. 解析合同版本、Path、Query、Header 和 Body；
4. 建立 request_id、command_id 和 correlation_id；
5. 判断 Account、Role、Inbox、Feature、套餐、Scope 和对象范围；
6. 检查幂等收据和重复动作；
7. 单模块动作进入权威模块 Command，跨模块动作进入 ORC；
8. 权威模块验证业务状态并计算变化；
9. 业务数据和 Local Change Journal 原子提交；
10. 返回完成结果或异步任务标识；
11. Event、实时、Webhook、通知、报表、搜索和 AUD 按事实处理；
12. 失败、超时或积压按基础层策略查询、重试、补偿和对账。

## 8. 基础层版本

基础层使用独立 foundation_version。以下变化必须提高版本并执行影响分析：

- 身份或权限范围变化；
- 公共字段含义、时间单位或错误语义变化；
- 幂等、事务、Event 顺序或补偿规则变化；
- Data Change Record、敏感分级或保留规则变化；
- 插件 Scope、能力合同或安全策略变化；
- 模块依赖方向、数据所有权或流程编排变化。

新增可选字段可以兼容追加；删除字段、改变语义、放宽权限或改变副作用必须进入新主版本。

## 9. 完成判定

- [ ] F0 至 F5 边界清楚且没有业务职责重叠；
- [ ] 公共能力均有唯一承载者；
- [ ] 所有写入口遵循统一处理顺序；
- [ ] 零容忍规则没有批准绕过项；
- [ ] foundation_version 和变更触发条件明确；
- [ ] 专项文档与本总纲没有冲突。
