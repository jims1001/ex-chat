# 统一上下文、身份、租户、权限与可用性

## 1. 统一上下文

每个请求、Command、Event、异步任务、插件调用和跨模块步骤必须携带可追踪上下文。

| 字段 | 必填规则 | 含义 |
|---|---|---|
| request_id | 外部请求必填 | 一次入口请求标识 |
| command_id | 写动作必填 | 一次业务命令标识 |
| event_id | Event 必填 | 一次事实事件标识 |
| correlation_id | 全部写动作必填 | 连接同一业务目标的全部步骤 |
| causation_id | 被其他动作触发时必填 | 直接原因的请求、命令或事件 |
| account_id | Account 数据必填 | 租户隔离边界 |
| actor_type | 必填 | user、contact、platform_app、plugin、bot、automation、provider、system |
| actor_id | 能识别主体时必填 | 操作主体稳定 ID |
| source_type | 必填 | account_api、widget、public、platform、callback、plugin、migration 等 |
| source_id | 按来源 | Inbox、安装实例、规则、Provider 连接或迁移任务 |
| contract_version | 必填 | 当前接口或模块合同版本 |
| foundation_version | 必填 | 当前基础层版本 |
| occurred_at | 写动作必填 | 业务动作发生时间 |

上下文在入口建立，跨模块传递时只能补充，不能替换原 actor、account、correlation 和 causation。

## 2. 身份类型边界

| 身份 | 允许范围 | 禁止混用 |
|---|---|---|
| Account User | 所属 Account、角色和 Inbox 范围 | 不能作为安装管理、Contact 或 Platform 身份 |
| Contact/Widget | 当前 Inbox、Contact 和允许的会话 | 不能管理 Account、成员或其他客户 |
| Public Client | 当前 Inbox 和客户公开资源 | 不能调用内部 Account 能力 |
| Platform App | 已授权的 Account、User 和平台关系 | 不能自动获得消息或敏感业务数据 |
| Installation Admin | 安装实例和全局资源 | 不能绕过 Account 业务审计和数据权限 |
| Plugin Installation | 清单、Scope 和对象授权范围 | 不能作为普通用户或读取其他插件数据 |
| Agent Bot | 获准 Inbox 和 Bot 能力 | 不能继承创建者全部权限 |
| Provider | 对应连接和已验签回调事件 | 不能执行任意查询或跨 Account 操作 |
| System/Automation | 明确规则、任务和系统能力 | 不能伪装为人工用户 |

## 3. Account 隔离

Account 隔离同时作用于：

- Path 和请求上下文；
- Token、Session、平台授权和插件安装；
- 对象 ID、唯一约束和关系；
- Query、缓存、搜索、报表和审计索引；
- Event、Webhook、实时频道和异步任务；
- 文件、知识、AI 上下文、导出和归档；
- Provider 连接、密钥和回调去重。

不能只因请求中提供 account_id 就信任其范围。必须从身份、对象归属和权威关系共同验证。

## 4. 统一可用性判断顺序

一个能力是否可用，按以下顺序判断：

1. 接口族和客户端类型是否允许；
2. 身份、Token、Session 或签名是否有效；
3. Account 是否有效且未暂停或删除；
4. 主体是否为 Account 成员或获准客户/平台/插件身份；
5. 标准角色或自定义权限是否允许；
6. Inbox、Team、对象或客户范围是否允许；
7. Account Feature 是否启用；
8. 安装配置和部署形态是否支持；
9. Enterprise、Cloud 或版本是否支持；
10. 套餐、额度、并发和速率是否允许；
11. 插件、Provider 或模型 Scope 是否允许；
12. 对象当前状态和领域规则是否允许。

前一层拒绝后不继续暴露后一层细节。拒绝结果必须能区分认证、权限、Feature、套餐、额度、对象状态和外部依赖，但不能泄露无权对象是否存在。

## 5. 权限责任

| 责任 | 所有者 |
|---|---|
| Token、Session、MFA、外部身份有效性 | IAM |
| Account、Membership、Role、Team | TEN |
| Feature、Entitlement、Quota | ENT |
| 外部入口与客户端身份映射 | API |
| Inbox、对象和业务状态限制 | 对应权威模块 |
| 插件安装、Scope 和允许域名 | EXT |
| Provider 连接和回调身份 | CHN、EXT 或 BIL 等对应模块 |

API 可以组合权限结果，但不能成为成员、角色、Feature 或对象状态的第二所有者。

## 6. 字段可见性

字段可见性由身份、Account、角色、对象范围、字段分级和用途共同决定：

| 视图 | 默认规则 |
|---|---|
| Account 内部视图 | 只展示当前角色和 Inbox 可见字段 |
| Widget/Public | 不展示私有备注、内部权限、其他客户和 Secret |
| Platform | 只展示 Platform Scope 明确允许的字段 |
| Plugin | 只展示当前 Invocation 必需的最小字段 |
| Webhook/Event | 只展示订阅合同和数据分级允许的字段 |
| Audit | before/after 仍受单独审计权限和遮蔽策略约束 |
| Export | 按冻结范围、用途、批准和加密策略生成 |

## 7. 高风险动作

以下动作除普通权限外，还需要原因、确认、增强审计或审批：

- 角色提升、权限放宽和成员移除；
- MFA、SSO、安全策略和全部 Session 撤销；
- Token、Secret、Certificate 和 Provider 授权变化；
- Account、客户、消息、支付、插件或大批量删除；
- Feature、套餐、额度和安装配置变化；
- restricted 数据查询或导出；
- AI Tool 或插件执行不可逆外部动作；
- 日志保留、完整性、纠正、脱敏和法律保留变化。

## 8. 验收

每种身份至少验证：

1. 正常范围访问；
2. 跨 Account；
3. 错误 Inbox、Team、对象或 Contact；
4. 角色不足；
5. Feature、套餐或额度不可用；
6. Token 过期、撤销和身份混用；
7. 插件或 Platform Scope 不足；
8. 对象状态禁止；
9. 敏感字段遮蔽；
10. 拒绝事件和高风险审计。

完成要求：跨 Account 泄露为 0，身份混用为 0，未授权写入为 0，Secret 回显为 0。
