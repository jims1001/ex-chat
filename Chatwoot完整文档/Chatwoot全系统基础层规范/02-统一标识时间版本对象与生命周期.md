# 统一标识、时间、版本、对象与生命周期

## 1. 标识合同

| 标识 | 规则 |
|---|---|
| object_id | 由权威模块生成，在对象生命周期内稳定 |
| display_id | 仅用于展示，不能替代 object_id 或作为跨模块唯一键 |
| external_id/source_id | 必须与 Provider、Inbox、来源类型共同确定唯一范围 |
| account_id | 所有租户对象和关系必须明确携带 |
| request_id | 一次外部请求唯一，重试可以使用新 request_id |
| command_id | 一次业务命令唯一，安全重试保持业务幂等关系 |
| event_id | 一次事实 Event 唯一，重复投递保持不变 |
| change_id | 一次实际数据变化唯一，重复投递保持不变 |
| process_id/correlation_id | 连接跨模块流程和全部因果记录 |
| idempotency_key | 在明确身份、Account、动作和时间范围内唯一 |

任何跨模块关系都使用稳定 ID，不使用名称、邮箱、电话号码、数组位置或当前显示值作为长期引用。

## 2. 时间合同

| 时间 | 含义 |
|---|---|
| occurred_at | 业务事实实际发生或提交时间 |
| recorded_at | 本地权威记录保存时间 |
| ingested_at | 集中账本、投影或外部系统接收时间 |
| created_at | 对象建立时间 |
| updated_at | 权威对象最近有效变化时间 |
| effective_at | 配置、规则或状态开始生效时间 |
| expires_at | Token、授权、下载或临时状态失效时间 |
| scheduled_at | 计划执行时间，不代表已经执行 |

跨模块排序优先使用对象版本和因果关系，不能仅依赖不同节点的墙钟时间。API 必须明确时间格式、时区和单位；Account 时区只影响展示和业务时段，不改变存储事实时间。

## 3. 版本合同

| 版本 | 用途 |
|---|---|
| object_version | 每次成功变化后单调增加 |
| schema_version | 对象或记录结构版本 |
| contract_version | Command、Query、Event 或 API 合同版本 |
| foundation_version | 基础层规范版本 |
| rule_version | 自动化、SLA、策略或安全规则版本 |
| provider_version | 外部 Provider API 或模型版本 |
| projection_version | 可重建投影使用的转换版本 |

对象版本用于并发和变化时间线；Schema 与合同版本用于兼容；两者不能互相替代。

## 4. 通用对象合同

每个权威对象至少明确：

- object_type、object_id、account_id；
- status 和允许状态集合；
- object_version；
- created_at、updated_at；
- created_by、updated_by 或等价 actor 关系；
- 数据分级和保留类别；
- 唯一约束；
- 关系对象及其所有者；
- 创建、更新、状态、归档、恢复和删除动作；
- 可变字段、只读字段、派生字段和敏感字段；
- 对应 Command、Query、Event 和 Change action。

## 5. 默认值、空值与更新语义

| 输入情况 | 通用含义 |
|---|---|
| 字段缺失 | 默认不修改现有值；创建时使用明确默认 |
| null | 只有字段合同允许清空时才表示清除 |
| 空字符串 | 与 null 分开定义，不自动互换 |
| 空数组 | 可能表示替换为空集合，必须由接口明确 |
| false、0 | 是有效值，不能当作缺失 |
| 未知字段 | 按版本合同拒绝或安全忽略，不能写入任意内部属性 |
| 未知枚举 | 读取方允许安全展示；写入方不得提交未支持值 |

局部更新只改变提交字段；整体替换必须明确标识，并保护调用方未获取的新字段。

## 6. 唯一约束

唯一范围必须写完整，常见形式包括：

- Account + 业务键；
- Account + Inbox + source_id；
- Account + Provider + external_id；
- Account + plugin_id + installation_id；
- Account + actor + idempotency_key + action；
- Provider connection + callback_event_id；
- process_id + step_id；
- object_id + object_version。

不能把全局唯一假设建立在第三方只保证局部唯一的字段上。

## 7. 关系对象

多对多关系、成员关系、绑定和集合替换必须明确：

- 关系所有者；
- 关系 ID 或复合唯一键；
- 添加、移除、替换和恢复动作；
- 并发集合语义；
- 删除一端后的处理；
- Change Diff 中 added、removed 和版本；
- Event 和查询视图的表达。

不能由关系两端同时维护不可对账的权威集合。

## 8. 生命周期

每个对象至少判断以下阶段是否适用：

created → active → updated → paused/disabled → archived → restored → deletion_scheduled → soft_deleted/redacted → hard_deleted。

生命周期规则：

1. 状态转换必须使用登记的 Command；
2. 每次成功转换增加 object_version 并生成 Change；
3. 删除不默认等于立即物理清理；
4. 归档和停用不得伪装为删除；
5. 恢复必须检查唯一约束、权限和外部连接；
6. 硬删除后只保留政策允许的不可逆摘要和清理证明；
7. 不可恢复动作执行前必须明确确认和审计；
8. 投影、缓存、搜索、附件、AI 索引和插件私有数据分别按事件清理。

## 9. 派生字段和投影

派生字段必须记录：来源对象、计算版本、更新时间、是否允许延迟以及重建方式。列表、搜索、报表和缓存可以暂时延迟，但详情和业务 Command 必须回到权威来源判断。

## 10. 迁移和兼容

迁移必须保留 legacy_id → target_id、来源版本、映射版本、批次、结果和 change_id。历史对象缺失新字段时使用明确默认或 unknown，不能静默伪造当前值。旧入口只能转换到当前 Command，不能保留第二套状态机。

## 11. 验收

- [ ] 每个对象有稳定 ID、Account、状态、版本和时间合同；
- [ ] 默认、缺失、null、空值和集合替换语义完整；
- [ ] 唯一范围和关系所有权明确；
- [ ] 状态转换、删除、恢复和清理都有 Change；
- [ ] 派生字段可以重建且不成为第二权威；
- [ ] 历史映射和迁移对账键完整；
- [ ] 并发后 object_version 无断层和重复。
