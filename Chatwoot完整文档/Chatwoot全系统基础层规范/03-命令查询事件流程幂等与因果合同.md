# 命令、查询、事件、流程、幂等与因果合同

## 1. 四类交互

| 类型 | 目的 | 是否改变数据 | 返回 |
|---|---|---:|---|
| Command | 请求权威模块执行动作 | 可以 | applied、rejected、accepted 或已存在结果 |
| Query | 读取权威状态或投影 | 否 | 数据、版本、新鲜度和部分不可用信息 |
| Event | 声明已经发生的事实 | 否 | 消费确认，不返回业务命令结果 |
| Process | 协调多个模块和外部步骤 | 通过 Command | 流程状态、步骤、补偿和终态 |

模块不能通过 Event 隐式要求其他模块修改数据；需要确定结果的写动作必须使用 Command 或 ORC Process。

## 2. Command 合同

| 字段 | 要求 |
|---|---|
| command_id | 全局唯一 |
| command_type/version | 稳定动作名称和版本 |
| account_id | 租户动作必填 |
| actor/source | 身份、来源和 Scope 快照 |
| target_type/target_id | 目标对象或创建范围 |
| expected_version | 需要乐观并发控制时提供 |
| idempotency_key | 创建、外部动作和不可逆动作必填 |
| correlation_id/causation_id | 写动作必填 |
| reason | 高风险动作必填 |
| payload | 只包含当前动作允许字段 |
| requested_at/deadline | 请求时间和允许处理期限 |

Command 只能由目标对象的权威模块执行。验证顺序为身份范围、幂等、对象存在、权限、状态、字段和业务约束。

## 3. Command 结果

| 结果 | 含义 |
|---|---|
| applied | 数据已提交，返回 object_version 和 change_id |
| no_change | 请求有效但没有实际变化，不伪造 Change |
| accepted | 已受理异步处理，返回 task_id/process_id 和查询方式 |
| already_applied | 重复命令，返回原结果而非再次执行 |
| rejected | 永久校验、权限或状态拒绝 |
| conflict | 版本、唯一或并发冲突，需要重新读取 |
| temporarily_unavailable | 可恢复依赖故障，指明是否安全重试 |
| result_unknown | 响应丢失或外部结果未知，必须先 Query |

## 4. Query 合同

Query 必须声明：查询类型和版本、Account、身份范围、对象或筛选、字段视图、分页、排序、新鲜度要求和最大成本。

Query 响应至少说明：

- 数据来源和对象版本；
- 投影时的 projection_version、updated_at 或 indexed_until；
- 分页游标和稳定排序；
- 遮蔽或省略字段；
- 可选模块不可用时的 partial 标志；
- 当前结果是否可直接用于后续 Command 前置判断。

## 5. Event 合同

| 字段 | 要求 |
|---|---|
| event_id | 全局唯一，重投保持不变 |
| event_type/version | 事实名称和合同版本 |
| source_module | 权威事实来源 |
| account_id | 租户事件必填 |
| object_type/object_id | 事实主体 |
| object_version | 变化后版本 |
| change_id | 数据变化事件必填 |
| correlation_id/causation_id | 因果链必填 |
| occurred_at/published_at | 事实时间和发布时间 |
| payload | 最小事实字段，不发送整个内部对象 |
| data_classification | 字段分级和订阅过滤依据 |

Event 是只追加事实。消费者按 event_id 幂等，并能处理重复、延迟、乱序、未知可选字段和版本升级。

## 6. 事件顺序和一致性

- 同一对象优先按 object_version 排序；
- 同一来源分区使用单调 source_sequence；
- 不同对象和模块不承诺全局时间顺序；
- Event 必须在业务数据和 Local Journal 成功后发布；
- 消费失败不能回滚已经完成的业务事实；
- 投影出现版本断层时等待、补读或重建，不能猜测缺失变化；
- 保留窗口外补读必须使用权威 Query 或快照。

## 7. 幂等

幂等范围由 Account、身份、动作、目标和幂等键共同决定：

| 场景 | 去重依据 |
|---|---|
| API 创建 | Idempotency-Key 或稳定业务键 |
| Widget/Public Message | echo_id/source_id |
| Provider Callback | connection_id + provider_event_id |
| Webhook Delivery | delivery_id/event_id |
| Plugin Action | installation_id + invocation_id |
| Automation | event_id + rule_id + rule_version |
| ORC Step | process_id + step_id + attempt policy |
| Payment | provider + payment_event_id/business_reference |
| Migration | job_id + source_object_id + mapping_version |

相同幂等键但 Payload 不同必须返回冲突并产生安全或运行记录。

## 8. 跨模块流程

需要两个以上模块改变状态、包含外部依赖、持续等待或需要补偿时，使用 ORC。ORC 只拥有流程、步骤、超时、幂等、补偿和终态，不拥有领域对象。

流程状态统一为：created、running、waiting、compensating、completed、partially_completed、failed、cancelled、manual_action_required。

每个步骤必须登记：目标模块、Command、前置条件、超时、结果 Query、重试、补偿、不可逆标志和人工处理方式。

## 9. 补偿

补偿是新的显式业务动作：

- 使用新的 command_id 和 change_id；
- 引用 original_command_id/original_change_id；
- 不删除已发生事实；
- 外部已可见或不可逆动作使用冲正、退款、纠正消息或人工处理；
- 补偿失败进入明确终态，不能无限隐藏重试。

## 10. 依赖方向

- 下层模块不反向依赖上层组合模块；
- 业务模块不依赖 API、RTM、RPT、SRH 或 AUD 查询才能完成权威状态；
- 投影消费者通过 Event 获取事实，不被权威模块同步回调；
- ORC 调用模块公开合同，模块不读取 ORC 内部状态；
- 插件只能通过 Capability 调用，不进入模块内部；
- 新增任何依赖后必须重新检查有向图无环。

## 11. 验收

- [ ] 所有写动作有唯一 Command；
- [ ] 所有 Event 均来源于已完成事实并引用 change_id；
- [ ] Query 标明权威性、新鲜度和分页；
- [ ] 重复、Payload 冲突、超时和乱序结果确定；
- [ ] 跨模块流程有唯一 ORC 和显式补偿；
- [ ] 模块依赖图无循环；
- [ ] Event 或投影失败不会回滚业务事实。
