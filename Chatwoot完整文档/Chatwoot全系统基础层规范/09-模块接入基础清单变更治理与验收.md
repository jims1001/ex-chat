# 模块接入基础清单、变更治理与验收

## 1. 模块基础声明

每个模块、插件或新功能开始前必须填写：

| 项目 | 必填内容 |
|---|---|
| module_id | 唯一模块标识和名称 |
| responsibility | 唯一职责和明确不负责内容 |
| foundation_version | 遵守的基础层版本 |
| owned_objects | 权威对象、关系、状态和版本 |
| stored_references | 其他模块 ID 或可重建快照 |
| commands | 写动作、幂等、权限和结果 |
| queries | 读取、字段视图、分页和新鲜度 |
| events | 发布、订阅、版本和顺序 |
| processes | 参与的 ORC 流程、步骤和补偿 |
| direct_dependencies | 允许的同步依赖 |
| event_dependencies | 允许的异步事实来源 |
| forbidden_dependencies | 明确禁止的反向或内部依赖 |
| api_surfaces | 适用接口族、身份和字段 |
| data_classes | 字段分级、Secret、保留和删除 |
| change_registry | 所有实际数据写入口 |
| plugin_points | 提供或使用的扩展点与 Scope |
| external_dependencies | Provider、模型、域名、配额和版本 |
| reliability | 超时、重试、限流、降级、容量和恢复 |
| migration | 映射、兼容、灰度、回退和对账 |
| evidence | 验收案例和证据索引 |

声明缺少任何适用项时，模块不能开始最终实施验收。

## 2. 接入实施顺序

1. 确定模块唯一职责和禁止边界；
2. 确定权威对象、关系和所有权；
3. 加入依赖矩阵并重新验证无环；
4. 冻结基础上下文、身份和 Account 范围；
5. 冻结对象 ID、版本、状态、唯一和生命周期；
6. 登记 Command、Query、Event 和 ORC 流程；
7. 登记 API 入口、字段、错误、分页、异步和兼容；
8. 登记全部写入口和 Data Change 规则；
9. 完成数据分级、Secret、保留、删除和导出策略；
10. 完成插件、Provider 和外部依赖合同；
11. 完成超时、幂等、重试、限流、降级、容量和恢复；
12. 执行基础层案例，通过后再执行模块功能案例；
13. 登记证据、差异和受影响任务；
14. 通过基础层关门后允许进入模块完成状态。

## 3. 基础层验收矩阵

| 验收域 | 必测内容 | 通过条件 |
|---|---|---|
| 边界 | 职责、禁止边界、停用影响 | 无重叠权威职责 |
| 所有权 | 对象、关系、投影、缓存 | 单一权威，直接跨存储访问为 0 |
| 依赖 | 同步、事件、ORC、插件 | 有向图无环 |
| 身份 | 全部适用身份和混用 | 身份混用为 0 |
| Account | 跨 Account、Inbox、对象 | 越权和泄露为 0 |
| 权限 | Role、Feature、套餐、Scope、状态 | 联合判断正确 |
| 对象 | ID、版本、默认、唯一、生命周期 | 状态和版本连续 |
| 合同 | Command、Query、Event、Process | 版本、幂等和因果完整 |
| API | 字段、分页、错误、异步、兼容 | 路径和可观察行为明确 |
| 数据变化 | Local Journal、Change、AUD | 成功变化覆盖 100% |
| 并发 | 重复、同对象竞争、乱序 | 无重复和不可解释状态 |
| 安全 | Secret、字段分级、导出 | restricted 泄露为 0 |
| 扩展 | 插件、Provider、AI、Webhook | 未登记入口为 0 |
| 故障 | 超时、依赖中断、积压、恢复 | 无丢失、重复和永久错误 |
| 迁移 | 映射、灰度、回退、对账 | 数据和业务关系完整 |
| 独立性 | 启停、升级、扩缩和替换 | 核心边界和恢复策略通过 |

## 4. 现有任务映射

| 基础层范围 | 既有任务 |
|---|---|
| 模块边界、所有权、无环、合同、插件、接口和编排 | ARCH-01 至 ARCH-10 |
| 版本、形态、Feature、配置、数据、第三方和差异 | BAS-01 至 BAS-12 |
| 日志采集、字段、存储、查询、隐私、恢复和全模块覆盖 | LOG-01 至 LOG-08 |
| 公共接口、认证、字段、错误、幂等、限流和兼容 | API-01 至 API-15 |
| 对象、默认、唯一、状态、生命周期和映射 | DATA-01 至 DATA-18 |
| 异步、并发、异常、重试、副作用和故障 | CONS-01 至 CONS-25 |
| 基础层综合验证 | QA-01 至 QA-24 |
| 最终基础层关门 | CLOSE-01、04、05、06、12、15、16 |

这些任务是本基础层的落地证据，不另建同义任务。任何任务发现基础层不满足，应重开对应基础任务，不能在业务分册内建立临时例外。

## 5. 基础层变更申请

每次基础层变化必须登记：

| 项目 | 内容 |
|---|---|
| change_request_id | 唯一变更编号 |
| affected_clause | 受影响分册和规则 |
| reason | 业务、法规、安全、Provider 或规模原因 |
| change_type | compatible、breaking、security、emergency |
| foundation_version | 变化前后版本 |
| affected_modules | 受影响模块、接口、插件和数据 |
| ownership_cycle_check | 所有权与无环复核结果 |
| data_migration | 对象、Change、索引和历史兼容 |
| rollout | 验证、灰度、观察和全量顺序 |
| rollback | 允许的回退范围和不可逆项 |
| reopened_tasks | 必须重开的 ARCH/BAS/LOG/API/DATA/CONS/QA |
| evidence | 合同、案例、迁移、故障和回归结果 |
| approval | 范围、有效期和批准记录 |

## 6. 兼容、替换与停用

### 新增

先建立接入声明和唯一所有权，再增加合同和任务。不能先建立私有入口，之后再补治理。

### 替换

旧新模块在兼容期内可以双运行，但只能有一个写入权威；另一个只读、影子或验证。切换前完成数据、事件、Change 和外部引用对账。

### 停用

停止新写入 → 等待或处理运行任务 → 撤权和停止事件 → 导出/迁移数据 → 清理投影和 Secret → 保留审计 → 验证依赖方降级 → 到期移除合同。

### 升级

比较基础版本、合同、Schema、权限、Scope、数据和 Provider 差异；先验证、再灰度、观察后全量。破坏性变化必须有迁移、兼容期和回退边界。

## 7. 完成状态规则

模块只有同时满足以下条件才能标记完成：

- 基础声明全部填写；
- 依赖、所有权和扩展点已登记；
- 基础层验收矩阵全部通过；
- 每个实际数据变化都有 change_id；
- 允许和拒绝权限案例完整；
- 重复、并发、超时、故障和恢复完整；
- 迁移和历史兼容完成；
- 无未批准差异、无隐藏阻断、无缺失证据；
- 相关基础任务未处于 REWORK、REOPENED 或 BLOCKED。

## 8. 后续强制规则

从本规范生效起：

1. 所有新文档和任务先引用本基础层；
2. 所有新模块先填写基础声明；
3. 所有新写入口先登记 Change Registry；
4. 所有新外部能力先登记扩展点、Scope 和失败隔离；
5. 所有基础变化先做影响分析和任务重开；
6. 所有完成声明必须包含基础层结论；
7. 基础层未通过时，业务功能不得以“主流程可用”为理由关闭。
