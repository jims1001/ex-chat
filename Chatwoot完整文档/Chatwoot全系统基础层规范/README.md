# Chatwoot 与 webchat 全系统基础层规范

> 本目录是整个系统后续设计、实施、接入、替换、迁移和验收的最高公共基线。任何模块、接口、插件、AI 能力、第三方渠道和后台任务都必须先满足本基础层，再执行自己的业务规则。

## 1. 基础层定位

基础层不是一个集中业务模块，也不拥有客户、会话、消息等业务对象。它由所有模块共同遵守的合同、约束和运行能力组成，统一解决：

- 身份、Account、权限、Feature、套餐和 Scope 如何判断；
- 对象如何标识、版本化、创建、更新、删除和迁移；
- Command、Query、Event 和跨模块流程如何协作且不形成循环；
- API 如何认证、表达字段、分页、错误、幂等、异步状态和版本；
- 数据如何保持唯一所有权、原子一致和完整变更追踪；
- Secret、个人信息、消息内容和导出如何保护；
- 插件、AI Provider、渠道 Provider 和外部系统如何受控接入；
- 故障、重试、限流、积压、容量、恢复和对账如何统一处理。

## 2. 权威性

后续工作按以下顺序判断：

1. 本基础层规范；
2. 已冻结的目标版本、部署形态、适用范围和不违反基础层的批准差异；
3. 模块化架构设计和日志基础层设计；
4. 产品功能与 API 基线；
5. webchat 补齐规范；
6. AI 实施步骤、任务状态和验收证据；
7. 既有系统当前行为。

任何批准差异都不能绕过 Account 隔离、权限、安全、数据所有权、变更记录、不可变审计和零循环依赖规则。

## 3. 强制原则

1. 一个业务能力只有一个权威模块；
2. 一个业务对象只有一个权威数据源；
3. 模块之间只能使用登记的 Command、Query、Event 或 ORC 流程；
4. 禁止读取或修改其他模块的内部存储；
5. 完整依赖图必须无循环；
6. 所有外部入口最终进入同一个权威业务动作；
7. 所有成功数据变化必须与 Local Change Journal 原子提交；
8. 每次实际变化必须有唯一 change_id、对象版本和因果链；
9. 密码、Token、Secret、MFA 信息和完整支付凭证不得进入普通响应、日志、报表或导出；
10. 插件和 Provider 只能使用声明的扩展点、Scope 和最小字段；
11. 超时后先查询结果，不能盲目重复不可逆动作；
12. 投影、索引、缓存、报表和兼容视图不得成为第二权威来源；
13. 异步操作必须有可查询终态、失败明细和补偿规则；
14. 每个模块必须能说明依赖故障、降级、恢复和数据对账方式；
15. 未通过基础层验收的模块不得进入业务完成或全系统完成状态。

## 6. 基础层落地阶段

基础层不新增重复任务编号，使用既有任务完成：

| 关门 | 任务范围 | 结果 |
|---|---|---|
| FND-Design | ARCH-01 至 ARCH-10 | 边界、所有权、无环依赖、合同和扩展点冻结 |
| FND-Scope | BAS-01 至 BAS-12 | 版本、形态、Feature、数据、第三方和差异冻结 |
| FND-Audit | LOG-01 至 LOG-08 | L0 变更追踪、不可变账本和 26 模块写动作覆盖完成 |
| FND-Interface | API-01 至 API-15 | 公共接口、认证、错误、分页、幂等、限流和兼容完成 |
| FND-Data | DATA-01 至 DATA-18 | 对象、默认、唯一、状态、生命周期、映射和对账键完成 |

业务模块可以按依赖逐步进入，但不得违反尚未完成的基础层规则。任何基础规则变化必须重新打开受影响的 ARCH、BAS、LOG、API、DATA、CONS 和 QA 任务。

## 7. 后续使用方式

每个新模块、功能或插件开始前必须：

1. 阅读本目录 00 至 10；
2. 填写 09 分册的模块接入声明；
3. 选择唯一数据所有者和依赖方向；
4. 登记 Command、Query、Event、API 和 Change Registry；
5. 完成身份、权限、敏感字段、幂等和失败策略；
6. 通过基础层验收后再进入功能验收；
7. 变更基础合同后重新评估全部受影响模块。

## 8. 基础层完成定义

- 26 个模块均有完整基础层接入声明；
- 数据所有权唯一，跨模块内部存储访问为 0；
- 依赖图无循环；
- 所有外部写入口能定位到唯一 Command 或 ORC 流程；
- 所有实际数据变化都有 change_id，本地记录与业务数据原子完成；
- 认证、Account、权限、Feature、套餐、Scope 和对象状态联合生效；
- Secret 原值泄露为 0；
- 重复、并发、超时、乱序和恢复结果确定；
- 插件和 Provider 未登记扩展入口为 0；
- 故障、容量、迁移、恢复和对账均有证据。
