# 数据变更记录字段与差异合同

> 日志任务：LOG-02。

## 1. Data Change Record 顶层字段

| 字段 | 必填 | 含义 |
|---|---|---|
| change_id | 是 | 全局唯一变更标识，重复投递保持不变 |
| schema_version | 是 | 变更记录合同版本 |
| source_module | 是 | 产生实际数据变化的权威模块 |
| account_id | 是 | 租户边界；安装级变化使用明确 platform scope |
| object_type | 是 | 权威对象类型 |
| object_id | 是 | 权威对象稳定 ID |
| object_display_id | 否 | 用于展示的业务标识，不替代 object_id |
| object_version_before | 是 | 变化前版本；创建使用 0 或明确不存在 |
| object_version_after | 是 | 变化后版本，必须大于 before |
| action | 是 | create、update、delete、merge 等标准动作 |
| changed_fields | 是 | 实际发生变化的字段路径集合 |
| before | 按动作 | 变化前受控字段或差异摘要 |
| after | 按动作 | 变化后受控字段或差异摘要 |
| diff | 是 | 结构化新增、删除、替换或集合变化 |
| actor_type | 是 | user、contact、platform_app、plugin、bot、automation、system、provider |
| actor_id | 按类型 | 操作主体稳定 ID |
| actor_account_role | 否 | 操作时角色快照 |
| source_type | 是 | account_api、widget、public、platform、callback、automation、migration 等 |
| source_id | 否 | 插件安装、Provider 连接、规则、迁移任务等来源 ID |
| reason | 否 | 人工输入、规则名称或系统原因 |
| request_id | 否 | 对外请求标识 |
| command_id | 是 | 产生变化的模块 Command 标识 |
| event_id | 否 | 对应业务 Event 标识 |
| correlation_id | 是 | 跨模块流程关联标识；单模块动作可等于 command_id |
| causation_id | 否 | 直接触发本次变化的命令或事件 |
| idempotency_key_hash | 否 | 幂等键摘要，不保存敏感原值 |
| occurred_at | 是 | 业务数据实际提交时间 |
| recorded_at | 是 | Local Journal 保存时间 |
| ingested_at | 是 | AUD 接收时间 |
| result | 是 | applied、compensating、compensated 或 corrected |
| data_classification | 是 | public、internal、confidential、restricted |
| retention_class | 是 | 对应保留政策 |
| integrity_hash | 是 | 记录完整性摘要 |
| previous_hash | 是 | 同一分区前一记录摘要，用于防篡改链 |

## 2. 标准动作

| action | 使用场景 | before/after 要求 |
|---|---|---|
| create | 新对象建立 | before=不存在；after=允许记录的初始字段 |
| update | 普通字段变化 | 只记录实际变化字段的前后值 |
| status_change | 状态或生命周期变化 | 状态、相关时间和原因必须联合记录 |
| add_relation | 添加成员、标签、参与者、绑定关系 | 记录新增引用和集合版本 |
| remove_relation | 移除或解绑 | 记录移除引用和原因 |
| replace_set | 整体替换集合 | 记录 added、removed 和未变摘要 |
| merge | Contact 或其他对象合并 | 记录主对象、被合并对象、冲突选择和迁移数量 |
| split | 允许的关系拆分 | 记录来源、目标和迁移范围 |
| archive | 归档但保留历史 | 记录可见性和恢复条件 |
| restore | 从删除或归档恢复 | 记录恢复来源和新版本 |
| soft_delete | 逻辑删除 | 记录删除状态、时间、原因和保留 |
| hard_delete | 物理清理完成 | 不保留被禁止内容，只记录对象摘要和清理证明 |
| redact | 脱敏或匿名化 | 记录字段路径、策略和不可逆标志，不保存被清除原值 |
| migrate | 迁移导致的创建或变化 | 记录 job_id、legacy_id 和映射 |
| compensate | 对已完成动作进行业务补偿 | 引用 original_change_id 和补偿原因 |
| correct_log | 修正此前日志的描述或分类 | 追加记录，不覆盖原记录 |

## 3. Diff 结构

每个字段差异至少包含：

| 字段 | 含义 |
|---|---|
| path | 字段路径 |
| operation | add、remove、replace、set_add、set_remove、redact |
| value_type | string、number、boolean、time、id、object、list、binary_ref |
| before_value | 允许记录时的变化前值 |
| after_value | 允许记录时的变化后值 |
| before_hash | 不允许记录原值时的摘要 |
| after_hash | 不允许记录原值时的摘要 |
| classification | 字段敏感等级 |
| display_policy | full、masked、summary、hash_only、omitted |

不应保存整个对象的无差别完整快照。默认记录实际变化字段；只有创建、合并、迁移基线或法规要求时才保存受控快照。

## 4. 敏感字段策略

| 字段类型 | before/after | 允许记录 |
|---|---|---|
| 密码、MFA Secret、恢复码 | 禁止 | 仅记录“已设置/已轮换/已撤销” |
| Access Token、Refresh Token、API Secret | 禁止 | secret_id、类型、末尾摘要、到期和动作 |
| Provider Token、Plugin Secret | 禁止 | connection/installation ID、Scope 和状态 |
| 支付卡或银行完整信息 | 禁止 | Provider 引用、品牌、末尾摘要和结果 |
| 消息正文 | 默认 summary 或 hash | 按 Account 保留政策决定是否受控保存 |
| 附件 | 不保存文件本体 | asset_id、类型、大小、安全状态和摘要 |
| 邮箱、电话 | masked 或受控 full | 取决于查询权限和 retention_class |
| SAML Certificate | 不保存完整前后值 | 指纹、到期和轮换动作 |
| 自定义字段 | 按字段 data_classification | full、masked、hash_only 或 omitted |
| AI Prompt/Response | 默认摘要或受控内容 | 模型、知识版本、安全结果和内容摘要 |

## 6. 批量和迁移记录

批量操作必须形成两层记录：

1. Batch Audit：请求人、筛选、对象总数、动作、计划和整体终态；
2. Object Change：每个实际发生变化的对象各自生成标准 Data Change Record。

不能只记录“批量更新了1000条”，却无法回答其中某个对象前后发生了什么。未变化、跳过和失败对象进入批次结果，但不伪造 Data Change。

## 7. 合并记录

Contact Merge 等复杂动作至少记录：

- base_object_id、merged_object_ids；
- 冲突字段和选择结果；
- 迁移的 ContactInbox、Conversation、Company、Label、Note 数量；
- 原对象最终状态；
- 主对象 object_version 变化；
- 跨模块关联的 change_id 列表；
- merge process correlation_id；
- 回退是否允许及限制。

## 8. 纠正记录

日志内容发现分类、展示或描述错误时：

1. 原记录保持不变；
2. 新增 action=correct_log；
3. 引用 corrected_change_id；
4. 说明错误字段、纠正值、原因和批准；
5. 查询界面同时显示原记录和纠正链；
6. 完整性摘要链继续追加。

## 9. LOG-02 实施步骤

1. 汇总 26 个模块的权威对象、状态字段、关系字段和删除方式；
2. 为每类对象确定 object_type、稳定 object_id 和版本字段；
3. 冻结 Data Change Record 顶层字段、必填条件、来源和合同版本；
4. 将所有写动作映射到标准 action，不允许模块自行创造同义动作；
5. 为普通字段、集合、关系、合并、删除、脱敏和补偿定义 Diff 表达；
6. 为每个字段登记 data_classification、display_policy 和 retention_class；
7. 为密码、Token、Secret、MFA、支付凭证和受限内容设置强制禁止规则；
8. 冻结 actor_type、source_type、correlation_id 和 causation_id 的传递规则；
9. 为批量、迁移和合并确定批次记录与单对象记录的关联方式；
10. 验证同一变化重复投递时 change_id、payload 和对象版本保持一致；
11. 验证纠正、补偿、脱敏和硬删除只追加新记录，不覆盖历史；
12. 用 Account、Contact、Conversation、Message、Assignment、Assistant 和 Payment 样本验证合同表达能力。
