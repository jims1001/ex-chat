# 敏感信息、隐私、保留、删除与合规

> 日志任务：LOG-06。不可变不等于永久保存所有原始敏感内容。

## 1. 数据分级

| 等级 | 示例 | 日志策略 |
|---|---|---|
| public | 公共文章标题、公开 Portal slug | 可记录必要前后值 |
| internal | Team 名称、普通配置、非敏感状态 | 账号内审计可查看 |
| confidential | 客户邮箱、电话、消息摘要、内部备注 | 加密、遮蔽、受限查询 |
| restricted | Token、Secret、密码、MFA、支付凭证、私钥 | 原值禁止进入日志 |

字段分级由权威模块定义，日志基础层执行统一最低保护。模块不能把 restricted 降级为 internal。

## 2. 最小化原则

- 只记录实际变化字段；
- 只记录审计所需的前后信息；
- 能用 ID、摘要或枚举表达时不保存原文；
- 消息和 AI 内容默认使用摘要、分类和 hash；
- 附件只记录 asset_id 和元数据；
- 错误内容移除请求 Body、Token 和 Secret；
- Provider Payload 不整包写入账本，只保留标准化字段和诊断摘要；
- 导入错误文件和日志分开管理，按更短保留期处理。

## 3. 字段保护方式

| 方式 | 适用 |
|---|---|
| full | public/internal 且确有审计价值 |
| masked | 邮箱、电话、外部账号等需要识别但不需原值 |
| summary | 长文本、消息、AI 内容和大对象 |
| hash_only | 需要确认是否变化但不能保存原值 |
| tokenized | 需要可控关联但不展示原值 |
| encrypted_field | 获批身份可读取的 confidential 字段 |
| omitted | password、Secret、MFA 和完整支付凭证 |

## 4. 保留类别

| 类别 | 典型内容 | 保留规则 |
|---|---|---|
| security_critical | 登录安全、MFA、Token、权限和高风险配置 | 较长保留，严格访问 |
| business_change | 客户、会话、消息、分配、工单和质检变化 | 按 Account 政策和法规 |
| billing_legal | 支付、退款、账单和额度变化 | 按财务和法律期限 |
| plugin_delivery | Webhook、插件和 Provider 投递 | 按诊断和合同期限 |
| ai_governance | 模型、知识版本、工具和安全结果 | 按 AI 治理政策 |
| migration_evidence | 导入、迁移、映射和对账 | 迁移完成后保留批准期限 |
| operational | 健康、性能和一般错误 | 较短保留，可聚合 |
| legal_hold | 调查或法律保留范围 | 暂停普通到期处理 |

具体天数由部署地区、合同和法规决定，不能在基础合同中硬编码为全局唯一期限。

## 5. Account 删除

Account 删除流程对日志分为三类：

1. 必须删除或不可逆脱敏的个人内容；
2. 法律允许保留但必须降低可识别性的审计摘要；
3. 财务、反欺诈或法律保留范围内的受限记录。

处理步骤：

1. TEN/ORC 发出 Account 删除 process；
2. AUD 冻结该 Account 的保留分类和法律状态；
3. 对要求删除的字段追加 redact change；
4. 受加密保护的敏感字段可按范围销毁读取密钥，使原值不可恢复；
5. 保留 object_id 的不可逆替代标识以维持摘要链；
6. 更新 Audit Index，移除不可搜索个人值；
7. 归档和备份进入同一删除计划；
8. 生成 purge/redaction certificate；
9. 不覆盖原 change_id 和摘要链结构；
10. 合规身份可查看处理证明但不能恢复已清除内容。

## 6. Contact 合并和删除

- 合并日志保留旧 contact_id 到主 contact_id 的关系；
- 普通查询默认跳转到主客户时间线；
- 合规查询可以查看合并原因和冲突结果；
- 联系人删除后，日志中的邮箱、电话和消息内容按政策脱敏；
- 会话和消息审计可以保留匿名对象引用；
- 不允许为了审计永久保留已要求删除的完整 PII；
- 后续合法恢复产生新的 restore change，不回写旧日志。

## 7. Secret 和凭证

日志只能记录：

- secret 类型；
- secret_id；
- 创建、轮换、到期、撤销和删除动作；
- Scope；
- Provider 或插件标识；
- 必要末尾摘要或指纹；
- 操作者和时间；
- 结果和失败分类。

禁止记录：完整 Secret、密码、MFA Seed、恢复码、私钥、Access Token、Refresh Token、Cookie 和 Authorization Header。

## 8. 法律保留

| 动作 | 要求 |
|---|---|
| 建立 | 记录批准、范围、原因、起止和负责身份 |
| 应用 | 标记匹配的 Account、对象、时间和 retention_class |
| 查询 | 仅合规身份可见，查询本身被审计 |
| 延长 | 新增变更记录，不覆盖原期限 |
| 解除 | 恢复普通保留计算并记录批准 |
| 到期 | 执行应删除、归档或继续保留的分类流程 |

## 9. 跨地区和数据位置

- 日志分区继承 Account 数据位置要求；
- restricted 字段不得因集中审计跨越禁止区域；
- 平台汇总只能使用允许的匿名指标；
- 跨区域调查需要额外审批和 Access Log；
- Cold Archive 和备份遵循相同位置要求；
- 插件和外部导出不能获得超出原业务授权的数据。

## 10. LOG-06 实施步骤

1. 汇总全部对象和字段，登记 public、internal、confidential、restricted 分级；
2. 为每类字段选择 full、masked、summary、hash_only、tokenized 或 omitted；
3. 建立密码、MFA、恢复码、Token、Secret、证书私钥和完整支付凭证的强制禁止清单；
4. 为消息、附件、客户身份、AI 内容、自定义字段和 Provider 数据确定 Account 级策略；
5. 冻结 operational、business、security、financial、compliance 等保留类别及到期动作；
6. 建立 Account 删除时的冻结、导出、脱敏、摘要保留、索引清理和完成证明流程；
7. 建立 Contact 合并、删除、更正和身份请求与历史变化的关联规则；
8. 建立法律保留的申请、审批、范围、延长、解除和到期记录；
9. 验证日志、索引、归档、备份、导出和临时文件使用相同隐私策略；
10. 验证密钥轮换、凭证撤销和字段脱敏记录生命周期动作但不保存秘密原值；
11. 按数据位置要求验证跨地区写入、复制、查询、导出和灾备；
12. 执行 restricted 原值扫描、过期清理对账和删除后不可恢复验证。
