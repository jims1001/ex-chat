# 告警、对账、故障恢复与运行监控

> 日志任务：LOG-07。基础层不仅保存日志，还必须主动发现“应该有记录但没有记录”的异常。

## 1. 告警分类

| 类别 | 触发示例 | 级别 |
|---|---|---|
| 完整性 | change_id 摘要冲突、摘要链断裂、签名失败 | 紧急 |
| 丢失风险 | Local Journal 积压超过阈值、source_sequence 断层 | 高 |
| 未覆盖写入 | 业务对象版本变化但 Change Registry 无记录 | 紧急 |
| 高风险业务 | 角色提升、权限放宽、MFA 关闭、Token 创建 | 高 |
| 批量破坏 | 大量删除、脱敏、合并、导出或成员移除 | 高 |
| 渠道安全 | Provider 重授权、Scope 变化、回调签名失败 | 高 |
| 插件安全 | 新 Scope、敏感 Query、连续失败、未知版本 | 高 |
| 计费 | 额度异常、重复支付回调、退款和账单差异 | 高 |
| AI | 高风险 Tool、模型变更、保护规则关闭、异常用量 | 中至高 |
| 运行 | AUD 延迟、索引失败、归档失败、磁盘或队列高水位 | 中至高 |

## 2. 高风险变更规则

默认需要告警或增强审计的动作：

- Administrator、Custom Role 和权限集合变化；
- Account、User、Inbox、Provider Connection 删除；
- MFA、SAML、OAuth、IP 白名单和安全策略变化；
- Secret、Token、Certificate 和 Webhook URL 轮换；
- Feature、套餐、额度和安装配置变化；
- 大批量联系人、会话、消息、工单或文章操作；
- 插件安装、Scope 增加、停用和未知发布者；
- AI Tool 执行不可逆外部动作；
- 审计权限、保留、归档、完整性密钥和法律保留变化；
- 查看或导出 restricted 日志。

告警记录必须引用 change_id 或 access_log_id，不能只保存无法复核的文字。

## 4. 完整性对账周期

| 周期 | 对账内容 |
|---|---|
| 实时 | change_id 重复、payload_hash 冲突、签名和 schema |
| 分钟级 | Local pending、ingestion latency、source_sequence gap |
| 小时级 | 模块 committed 与 AUD ingested 数量和分布 |
| 日级 | object_version 连续、摘要链、checkpoint 和索引完整性 |
| 周期性 | 权威对象当前版本与最后 Change 版本抽样或全量 |
| 版本发布前 | Change Registry 与全部写 Command 对照 |
| 迁移后 | 迁移对象、映射、版本、批次和 AUD 对账 |
| 灾备演练 | 备份、恢复、摘要链、补投和索引重建 |

## 5. 故障分级

| 级别 | 情况 | 业务策略 |
|---|---|---|
| F0 | Audit Index 延迟 | Ledger 写入继续，查询显示 indexed_until |
| F1 | Central Ledger 短时不可用 | Local Journal 积压，业务在风险和容量范围内继续 |
| F2 | 积压达到高水位 | 暂停导入、迁移、批量和低优先级写入 |
| F3 | Local Journal 写入失败 | 所有受影响数据写入失败，读取继续 |
| F4 | 摘要链或签名失败 | 隔离分区，停止高风险操作，启动安全调查 |
| F5 | 发现无 Change 的业务数据变化 | 视为严重完整性事件，冻结相关写入口并对账 |

## 6. 恢复流程

1. 确定故障范围、开始时间、模块和 Account；
2. 保护 Local Journal 和 Ledger 原始状态；
3. 修复认证、容量、网络、合同或存储问题；
4. 按 source_sequence 补投；
5. 对重复 change_id 幂等处理；
6. 对版本断层等待缺失记录或建立受控 correction；
7. 重新计算摘要链和 checkpoint，但不覆盖历史记录；
8. 重建 Audit Index；
9. 对账 committed、ingested、版本和对象当前状态；
10. 关闭告警并生成 incident Audit；
11. 重新开放高风险和批量写入；
12. 更新容量和预防规则。

## 7. 无日志变化的修复

发现业务数据已经变化但没有 Change Record 时：

- 不允许伪造原始操作者和发生时间；
- 立即记录 integrity_incident；
- 从请求、业务 Event、对象版本、Provider 回执和 ORC 步骤收集证据；
- 创建 action=correct_log 或 recovered_change；
- 明确 recorded_from_recovery=true；
- 记录已知和未知字段；
- 引用调查和批准；
- 检查相同写入口的全部时间范围；
- 修复 Change Registry 和原子采集后才能恢复入口。

恢复记录不能让系统假装当时已经正常记录。

## 8. 告警抑制和聚合

- 相同根因和分区的积压告警可以聚合；
- 安全、摘要冲突和无日志变化不能自动静默；
- 告警抑制必须有原因、范围、开始、到期和批准；
- 抑制不停止原始日志记录；
- 自动恢复告警仍保留首次、峰值和恢复时间；
- 大批量合法操作使用 batch_id 聚合，但单对象 Change 仍保留。

## 9. 日志基础层自身审计

以下动作必须进入独立高保护范围：

- Change Registry 修改；
- 字段分级和遮蔽策略变化；
- Local Journal 配置和积压上限变化；
- Ledger 分区、保留和归档变化；
- 完整性密钥和 checkpoint 变化；
- Audit 查询权限和导出审批变化；
- 告警阈值、抑制和关闭；
- correction、redaction、purge 和法律保留。

## 10. LOG-07 实施步骤

1. 冻结完整性、丢失风险、未覆盖写入、高风险业务、安全和运行告警目录；
2. 为每项告警确定级别、阈值、Account/模块范围、接收对象和升级时限；
3. 建立 Local pending、ingestion、sequence、object_version、hash、index 和 archive 指标；
4. 配置实时、分钟、小时、日、发布前、迁移后和灾备演练对账；
5. 为 F0 至 F5 建立允许继续、限制写入、冻结入口和恢复的明确策略；
6. 验证集中账本中断、本地积压、高水位、Local Journal 失败和摘要链失败；
7. 执行按 source_sequence 补投、幂等接收、索引重建和恢复后对象版本对账；
8. 演练发现“业务数据已变化但没有 Change”时的隔离、调查和受控恢复；
9. 建立告警聚合、抑制、到期、升级和关闭规则，禁止永久静默高风险事件；
10. 把 Registry、字段分级、保留、密钥、查询权限和告警规则自身纳入高保护审计；
11. 验证运行监控不记录秘密原值，也不成为第二套业务或审计账本；
12. 形成故障开始、影响、修复、补投、对账和恢复开放的完整事件证据。
