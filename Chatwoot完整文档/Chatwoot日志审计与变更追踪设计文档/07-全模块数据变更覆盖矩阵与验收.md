## 2. 全局写动作检查

每个模块必须维护以下登记：

| 项目 | 检查内容 |
|---|---|
| Commands | 所有会改变数据的 Command 列表 |
| Background Jobs | 定时、异步和自动清理写入 |
| Provider Callbacks | 外部回调产生的状态变化 |
| Automation | 规则触发的写入 |
| Plugin Actions | 插件能力调用产生的写入 |
| Bulk Operations | 批次和单对象写入 |
| Imports/Migrations | 迁移写入和映射 |
| Compensation | 补偿和恢复写入 |
| Retention | 归档、脱敏、硬删除和清理 |
| Admin Operations | 安装级和高权限写入 |

任何未在 Change Registry 中出现的写入口视为未覆盖。

## 3. 每个写动作的验收案例

1. 正常变化：业务对象和 Change 同时成功；
2. no_change：输入与当前值相同，不伪造变化；
3. 校验失败：数据不变，只记录失败操作；
4. 权限失败：数据不变，记录安全拒绝；
5. Local Journal 失败：业务变化整体失败；
6. Central Ledger 失败：本地 pending，恢复后补投；
7. 重复 Command：只产生一次业务变化和一个 change_id；
8. 并发 Command：每个成功版本有一条顺序记录；
9. Publisher 重复：AUD 只保存一次；
10. Event 乱序：对象时间线按 object_version 正确；
11. 跨模块流程：correlation_id 连接所有变化；
12. 补偿：原变化保留并新增 compensate；
13. 批量：批次和每个实际变化对象都可查；
14. 删除/脱敏：原值按策略处理且摘要链可验证；
15. 查询/导出：权限、遮蔽和 Access Log 正确。

## 5. 对象版本重放验收

对关键对象执行：

1. 从 create change 开始；
2. 按 object_version 顺序应用允许的 Diff；
3. 处理 merge、redact、archive 和 compensate；
4. 与当前权威对象的可审计字段比较；
5. 差异必须能由允许的派生字段、保留清理或 correction 解释；
6. 无法解释差异视为日志完整性失败。

关键对象包括 Account、Membership、Inbox、Contact、ContactInbox、Conversation、Message、Assignment、AutomationRule、Campaign、Assistant、PluginInstallation、SlaPolicy、Payment 和 MigrationJob。

## 6. 跨入口一致性

同一业务动作分别通过 Account API、Widget/Public、Platform、Provider Callback、Automation、Plugin 和 Migration 进入时：

- 使用同一权威模块；
- 产生同类 action 和 object_version；
- actor_type 和 source_type 能区分入口；
- correlation_id 和 causation_id 完整；
- 敏感字段策略一致；
- 不能因入口不同漏记或记录两次；
- 业务 Event 和 Change Record 可互相定位。

## 7. 发布关门

任一模块发布前必须提供：

- 本版本新增和变化的写 Command；
- Change Registry 差异；
- 新字段 data_classification；
- Diff 和遮蔽策略；
- 新增告警和保留类别；
- 单写动作验收结果；
- Local/Central 故障结果；
- 版本重放和对账结果；
- 未决差异及批准。

没有该证据的模块不能标记发布完成。

## 8. LOG-08 实施步骤

1. 逐个核对 IAM 至 ORC 共 26 个模块的权威对象和全部写入口；
2. 把 Command、后台任务、Provider 回调、自动化、插件、批量、迁移、补偿、保留和管理写入登记到 Registry；
3. 为每个写入口确定 object_type、action、changed_fields、actor、source、敏感等级和保留类别；
4. 为每个写入口执行正常、no_change、校验失败、权限失败和 Local Journal 失败；
5. 执行集中账本中断、重复 Command、并发 Command、重复投递、乱序和恢复补投；
6. 对跨模块流程、批量、迁移、合并、补偿、删除和脱敏执行专项验证；
7. 计算 Registered/Actual、Change/Object Version、Delivered/Committed 和 Ledger/Local 四组覆盖率；
8. 对关键对象从 create 开始重放 Diff，并与当前权威状态比较；
9. 对 Account、Widget/Public、Platform、Callback、Automation、Plugin 和 Migration 入口做同动作对照；
10. 扫描无 change_id 数据变化、序列断层、版本断层、摘要冲突和 restricted 泄露；
11. 为每个模块形成写入口清单、案例结果、对账结果、差异和批准记录；
12. 只有 26 个模块覆盖率均为 100% 且全部零容忍指标为 0，才允许关闭 LOG-08。
