# 模块数据所有权表

> 架构任务：ARCH-02。任何未登记对象不得进入实施。

## 1. 所有权定义

“拥有”表示模块对该对象具有唯一的创建、校验、状态转换、更新和生命周期决定权。其他模块可以保存引用、快照或投影，但不能成为第二个权威来源。

## 2. 主对象所有权

| 模块 | 权威对象 | 可被其他模块保存的内容 | 禁止复制为权威的数据 |
|---|---|---|---|
| IAM | User、Profile、Credential、MFA、Session、ExternalIdentity | user_id、显示名快照、身份状态摘要 | 密码凭证、MFA Secret、Session 状态 |
| TEN | Account、AccountMembership、Role、Team、TeamMembership | account_id、role_id、team_id、名称快照 | 成员有效性、角色权限集合、Team 成员集合 |
| ENT | FeatureCatalog、AccountEntitlement、QuotaAccount、QuotaReservation | feature_key、可用性快照、额度结果 | Feature 最终判断、可用额度余额 |
| SYS | InstallationConfig、VersionSetting、PlatformBanner、InstanceState | 配置版本、公开配置快照 | 敏感配置值、当前生效版本 |
| CHN | Inbox、ChannelConnection、WorkingHours、ProviderHealth、ChannelTemplate | inbox_id、channel_type、能力和状态快照 | Provider Token、健康状态、工作时间规则 |
| CUS | Contact、ContactInbox、Company、LabelDefinition、CustomAttributeDefinition、ContactNote | contact_id、source_id、名称、必要联系信息快照 | 客户合并关系、渠道身份唯一关系、客户主档 |

| RTE | AgentAvailability、QueueEntry、Assignment、AssignmentPolicy、CapacityPolicy | assignee_id、team_id、队列和容量摘要 | 当前分配事实、容量占用、候选计算结果 |
| TKT | Ticket、TicketWorkflow、TicketComment、TicketRelation | ticket_id、status 快照 | 工单状态机、处理记录 |
| QLT | CsatSurvey、CsatResponse、QualityReview、SamplingRule、Appeal、Recheck | score、review_id 摘要 | 原始评分、申诉和复核状态 |

| KB | Portal、Category、Article、KnowledgeDocument、FAQ、Translation | knowledge_id、标题和版本快照 | 知识原文、发布状态、多语言关系 |

| EXT | IntegrationApp、IntegrationHook、PluginInstallation、WebhookEndpoint、WebhookDelivery、DashboardApp、AgentBot | installation_id、状态和能力摘要 | 插件凭证、订阅范围、Delivery 尝试 |
| RPT | SlaPolicy、AppliedSla、MetricDefinition、ReportProjection、ExportJob | SLA 结果和报表结果 | 指标公式、计时状态、聚合事实 |

## 3. 关系对象所有权

| 关系 | 所有者 | 原因 |
|---|---|---|
| User 属于 Account | TEN | 这是账号成员和业务权限关系，不是登录身份本身 |
| User 属于 Team | TEN | Team 是组织主数据；RTE 只读取成员关系 |
| User 属于 Inbox | CHN | Inbox 成员决定渠道可见范围；TEN 提供有效成员校验 |
| Contact 属于 Inbox 的身份 | CUS | ContactInbox 是客户身份合并和唯一规则的一部分 |
| Conversation 属于 Contact/Inbox | CON | 会话创建时固化稳定引用；客户和渠道仍由各自模块管理 |
| Message 属于 Conversation | MSG | 消息生命周期由 MSG 管理；CON 提供会话有效性 |
| Attachment 属于 Message | MSG | 关系由消息拥有，文件本体由 MED 拥有 |
| Conversation 当前分配 | RTE | 分配、队列和容量必须由同一个模块原子决定 |
| Conversation 标签关系 | CON | Label 定义由 CUS 拥有，会话上的使用关系由 CON 拥有 |
| Assistant 绑定 Inbox | AIC | AI 使用策略归 AIC；Inbox 是否有效由 CHN 校验 |
| Plugin 绑定 Inbox | EXT | 安装和授权范围归 EXT；Inbox 主状态归 CHN |
| Ticket 关联 Conversation | TKT | 工单拥有该关联，不改变会话状态 |
| QualityReview 关联 Conversation | QLT | 质检拥有快照和评分，不修改原消息 |

## 4. 状态所有权

| 状态 | 唯一所有者 | 其他模块允许保存 |
|---|---|---|
| 登录会话状态 | IAM | 当前是否有效的短期缓存 |
| Account 状态 | TEN | 状态和版本快照 |
| Feature 可用性 | ENT | 带原因和有效期的判断结果 |
| Inbox 健康 | CHN | connected/warning/disconnected 摘要 |
| Contact 合并状态 | CUS | merged_to 引用快照 |
| Conversation status/priority | CON | 事件版本对应快照 |
| Message delivery status | MSG | 最终状态和错误摘要 |
| 当前 assignee/queue/capacity | RTE | API 通过 RTE Query 聚合；RPT/SRH 可保存可重建投影 |
| Campaign 状态 | OPS | 汇总状态投影 |
| Notification read/delivery | NTF | 未读总数投影 |
| AI Document 索引状态 | AIC | API 可通过 AIC Query 聚合展示；KB 不保存第二状态 |
| Knowledge 发布状态 | KB | AIC 保存索引时使用的知识版本 |
| SLA 计时与 breach | RPT | CON 可展示 SLA 摘要 |
| Payment/Invoice | BIL | TEN/ENT 保存购买结果引用 |
| Import/Migration | MIG | 目标模块保存 source_mapping 引用 |

## 5. 允许的冗余

只有以下冗余允许存在：

- 用于显示的不可编辑名称快照；
- 用于搜索和报表的可重建投影；
- 用于故障隔离的短期缓存；
- 用于审计的事件发生时快照；
- 用于迁移兼容的旧 ID 到新 ID 映射；
- 用于幂等处理的请求和事件收据。

所有允许冗余必须包含：source_module、source_id、source_version、captured_at、refresh_or_rebuild_rule。没有这些来源信息的副本视为第二权威来源。

## 6. 删除和脱敏责任

1. 删除请求先发送给权威所有者；
2. 所有者完成状态变化并发布删除或脱敏事件；
3. 投影、缓存、搜索、报表、AI 索引和插件分别清理自己的副本；
4. AUD 按保留政策保存允许的审计摘要；
5. ORC 跟踪跨模块清理完成情况；
6. 未完成的副本清理进入可追踪补偿，不得把主删除伪装为全部完成。

## 7. ARCH-02 实施步骤

1. 枚举当前全部主对象、关系对象、状态、配置和凭证；
2. 为每项指定一个且仅一个所有者；
3. 标记其他模块中的同名字段是引用、快照、投影还是违规副本；
4. 为允许副本补充来源、版本和重建方式；
5. 删除跨模块直接修改入口；
6. 将跨对象关系归给最能决定其生命周期的模块；
7. 冻结删除、合并、脱敏和解绑责任；
8. 建立数据所有权登记表版本；
9. 对无人所有和多重所有项逐一处理；
10. 所有冲突清零后完成。

## 8. 完成判定

- [ ] 所有凭证都有单独的安全所有者；
- [ ] 搜索、报表、AI 和审计数据明确为投影或快照；
- [ ] 允许冗余均可追溯和重建；
- [ ] 删除、脱敏和合并能够传播到所有副本；
- [ ] 无人所有和多重所有对象均为 0。
