# 无循环依赖矩阵

> 架构任务：ARCH-03。同步调用、事件订阅、共享配置和数据引用都必须进入依赖检查。

## 1. 依赖定义

模块 A 出现以下任一情况，都表示 A 依赖 B：

- A 的业务动作必须同步获得 B 的结果；
- A 订阅 B 的事件才能维护自己的业务状态或投影；
- A 使用 B 拥有的对象、配置或能力合同；
- A 的启动、升级或正常运行必须等待 B；
- A 在失败恢复时必须调用 B 才能完成补偿。

仅仅在事件中保存 B 的稳定 ID，不代表 B 反向依赖 A。

## 4. 消除反向依赖的方法

| 发现的问题 | 禁止做法 | 目标做法 |
|---|---|---|
| CON 想知道自动化执行结果 | CON 调用 AUT 并等待 | AUT 订阅会话事件；执行后发布独立结果，CON 不依赖 |
| MSG 想发送通知 | MSG 直接调用 NTF | MSG 发布 message.created；NTF 独立消费 |
| CUS 想更新搜索 | CUS 修改搜索索引 | CUS 发布 contact.updated；SRH 重建投影 |
| CHN 想创建会话 | CHN 直接写 CON | API/ORC 接收 Provider 入站并调用 CUS、CON、MSG |
| RTE 分配后更新会话 | RTE 修改 CON 存储 | RTE 发布 assignment.changed；CON 展示层组合或维护只读快照 |
| BIL 购买后启用 Feature | ENT 查询 BIL 每次支付，或 BIL 与 ENT 互相订阅 | BIL 发布 payment.completed；ORC 以幂等 Command 更新 ENT 权益 |
| AIC 需要知识内容 | KB 反向推送 AIC 内部 | AIC 使用 KB Query 并记录版本；KB 发布 knowledge.changed |
| 插件需要业务数据 | EXT 直接读取各模块 | 插件使用能力网关和授权 Query |

## 5. 事件环也属于循环

以下模式即使没有同步调用，也属于禁止循环：

- A 发布事件触发 B，B 的默认动作又无条件触发 A 的同类事件；
- 两条 Automation Rule 互相修改对方监听字段；
- CON 和 RTE 对 assignee 都进行权威更新并互相同步；
- MSG 和 Provider Adapter 对发送状态都尝试纠正对方；
- ENT 和 BIL 对额度余额都进行双向覆盖。

事件循环必须通过唯一所有者、事件来源、因果标识、递归深度和幂等键消除。

## 6. 无环检查步骤

1. 收集所有同步调用；
2. 收集所有事件订阅和动作回调；
3. 收集共享配置、共享存储和启动依赖；
4. 将每个依赖记录为“消费模块 → 提供模块”；
5. 按层级检查低层是否指向高层；
6. 对同层依赖执行拓扑排序；
7. 查找长度为 2 的直接互相依赖；
8. 查找长度大于 2 的间接环；
9. 对事件触发链执行相同检查；
10. 用 ORC、事件、只读投影或所有权调整消除环；
11. 重复检查直到拓扑排序包含全部模块；
12. 保存依赖图版本和检查结果。
