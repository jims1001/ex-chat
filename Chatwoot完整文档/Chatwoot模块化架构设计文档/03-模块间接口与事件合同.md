# 模块间接口与事件合同

> 架构任务：ARCH-04。模块之间除本分册定义的合同外，不允许通过共享存储、内部对象或隐式副作用协作。

## 1. 合同类型

| 类型 | 用途 | 方向 | 是否改变状态 | 返回结果 |
|---|---|---|---|---|
| Command | 请求权威模块执行一个业务动作 | 调用方 → 所有者 | 可以 | 接受、拒绝、冲突或异步任务标识 |
| Query | 读取权威数据或稳定摘要 | 调用方 → 所有者 | 不可以 | 当前数据、分页、未找到或无权 |
| Event | 通知已经发生且已保存的事实 | 所有者 → 订阅方 | 发布者状态已完成 | 不等待订阅者反向修改 |
| Process Signal | 通过 L0 通用回复合同报告流程步骤完成、失败或需要人工处理，由 ORC 消费 | 模块发布 → ORC 消费 | 只改变流程状态 | 不要求 ORC 在线才能完成模块自身事务 |
| Capability Call | 插件或扩展通过授权能力执行受限动作 | EXT/API → 所有者 | 取决于能力 | 标准 Command 或 Query 结果 |

## 2. 公共合同封装

### 2.1 Command 必备字段

| 字段 | 作用 |
|---|---|
| command_id | 唯一命令标识 |
| command_type | 动作名称和合同版本 |
| account_id | 租户边界 |
| actor | 身份类型、主体 ID 和授权来源 |
| target | 目标对象类型、ID 和期望版本 |
| input | 仅包含该动作允许的字段 |
| idempotency_key | 重复提交去重 |
| correlation_id | 关联完整业务流程 |
| causation_id | 指向触发该命令的事件或命令 |
| requested_at | 请求时间 |
| timeout_policy | 超时后查询或补偿规则 |

### 2.2 Query 必备字段

| 字段 | 作用 |
|---|---|
| query_type | 查询名称和版本 |
| account_id | 数据范围 |
| actor | 权限判断主体 |
| filter | 筛选条件 |
| sort | 稳定排序 |
| page/cursor | 分页位置 |
| fields | 允许返回的字段集合或视图 |
| consistency | 当前值、允许延迟投影或历史快照 |
| requested_at | 查询时间 |

### 2.3 Event 必备字段

| 字段 | 作用 |
|---|---|
| event_id | 全局唯一事件标识 |
| event_type | 事实名称 |
| event_version | Payload 合同版本 |
| source_module | 唯一发布模块 |
| account_id | 租户边界 |
| aggregate_type | 权威对象类型 |
| aggregate_id | 权威对象 ID |
| aggregate_version | 对象变化后的版本 |
| occurred_at | 业务事实发生时间 |
| published_at | 事件可被消费时间 |
| actor | 引发变化的主体 |
| correlation_id | 跨模块流程标识 |
| causation_id | 直接原因 |
| changed_fields | 发生变化的字段名称 |
| payload | 订阅方允许获得的事实快照 |
| data_classification | 数据敏感等级 |

## 4. Command 规则

- 一个 Command 只能有一个权威接收模块；
- 接收模块必须重新验证 Account、权限、对象状态和 Feature；
- 调用方的页面校验不能替代接收模块校验；
- 对重复 command_id 或 idempotency_key 返回同一业务结果；
- Command 成功表示权威状态已完成或已形成可查询异步任务；
- 不得用 Event 表达“请执行一个动作”；
- 需要多个模块完成的动作必须由 ORC 拆成多个 Command；
- Command 超时后必须通过 Query 确认结果，不能直接重复不可逆动作。

## 5. Query 规则

- Query 不产生业务副作用；
- 权威查询和投影查询必须明确区分；
- 聚合查询由 API/ORC 或专门读模型组合，不要求模块共享存储；
- Query 返回字段必须标明来源模块；
- 可延迟字段必须返回数据版本或更新时间；
- 无权、未找到和 Feature 不可用必须保持可区分；
- 大列表必须分页，排序字段必须稳定；
- 任何敏感字段默认不返回。

## 6. Event 规则

- Event 只发布已完成事实；
- 发布者不关心订阅者数量，也不等待订阅者修改自己；
- 订阅者按 event_id 幂等消费；
- 同一对象使用 aggregate_version 识别旧事件和乱序；
- Event 只能由权威所有者发布；
- 删除、合并、脱敏和权限变化必须发布专用事实；
- Payload 只包含订阅所需最小数据，不传递完整敏感对象；
- 新字段只能追加，删除或改变语义必须提高 event_version；
- 订阅失败进入独立重试，不回滚发布者业务事实。

## 7. 错误合同

| 错误类型 | 含义 | 重试原则 |
|---|---|---|
| authentication_failed | 身份无效 | 修复身份后重试 |
| permission_denied | 无权 | 不自动重试 |
| resource_not_found | 资源不存在或不可见 | 不自动重试 |
| validation_failed | 字段或组合错误 | 修改输入后重试 |
| state_conflict | 对象版本或状态冲突 | 重新 Query 后决定 |
| feature_unavailable | Feature、套餐或配置不允许 | 条件变化后重试 |
| quota_exceeded | 额度不足 | 额度恢复后重试 |
| dependency_unavailable | 必需模块暂时不可用 | 延迟且有上限重试 |
| rate_limited | 请求超出限制 | 按 retry_after 重试 |
| result_unknown | 响应超时但结果未知 | 先查询，不直接重复 |
| permanent_external_failure | 外部永久拒绝 | 不自动重试 |

## 8. 版本和兼容

- Command、Query 和 Event 各自独立版本；
- 合同版本不能等同于模块版本；
- 兼容期内提供旧版本转换，但只进入同一权威业务动作；
- 同一事件不能在不提高版本的情况下改变字段含义；
- 使用方必须容忍新增字段和未知非终态枚举；
- 旧版本停止前必须确认所有使用方迁移完成；
- 版本变化必须更新依赖矩阵、插件合同和对外接口映射。
