# 插件扩展点设计

> 架构任务：ARCH-05。插件是受控扩展，不是进入核心模块的后门。

## 1. 插件体系目标

插件必须可以独立安装、授权、启用、暂停、升级和卸载。插件失败只能影响自己提供的能力，不得破坏客户、会话、消息和分配等核心事实。

## 2. 插件对象归属

| 对象 | 所有模块 | 说明 |
|---|---|---|
| Plugin Catalog | EXT | 插件名称、版本、说明和能力声明 |
| Plugin Installation | EXT | Account 安装实例、状态和授权范围 |
| Plugin Secret | EXT | 加密保存，普通 Query 不回显 |
| Capability Grant | EXT | 插件可以使用的公开 Command、Query 和 Event |
| Plugin Subscription | EXT | 订阅事件和筛选范围 |
| Plugin Invocation | EXT | 调用、超时、结果和重试记录 |
| Plugin Private Data | 插件自身 | 不能与核心对象共用权威表；必须以 account_id 隔离 |
| Core Business Object | 对应领域模块 | 插件只能保存 ID 或快照，不能成为所有者 |

## 3. 标准扩展点

| 扩展点 | 提供能力 | 对接模块 | 允许输出 | 禁止行为 |
|---|---|---|---|---|
| Channel Adapter | 新消息渠道的授权、入站、出站、状态和健康 | CHN、MSG、ORC | 标准渠道事件和 Provider 结果 | 自建客户、会话或消息权威对象 |
| AI Provider Adapter | 模型目录、生成、Embedding、审核和用量 | AIC | 标准模型结果和用量 | 直接读取全部 Account 数据 |
| Knowledge Source | 从外部空间同步文档和变更 | KB、AIC | Knowledge Document 和版本 | 绕过知识发布权限 |
| Automation Condition | 提供新的只读条件字段和操作符 | AUT | 布尔匹配结果和解释 | 修改业务对象 |
| Automation Action | 通过授权 Command 执行新动作 | AUT、ORC、目标模块 | 动作结果和补偿标识 | 直接写目标存储或无限递归 |
| Notification Channel | 新的通知投递通道 | NTF | 接受、送达、失败和失效结果 | 修改 Notification 已读状态 |
| Integration Connector | CRM、协作、订单、工单等外部连接 | EXT、ORC | 受限 Query/Command 和外部引用 | 批量读取未授权数据 |
| Custom Tool | AI 或人工触发的外部业务动作 | AIC、EXT、ORC | 结构化结果和审计摘要 | 未经确认执行高风险不可逆动作 |
| Import Source | 从外部系统读取并转换迁移数据 | MIG | 标准导入记录和错误 | 直接插入目标模块内部存储 |
| Message Content Handler | 支持新的消息内容或媒体表现 | MSG、MED、CHN | 标准 content_type 和附件引用 | 改变既有消息状态语义 |
| Authentication Provider | 新的外部身份验证方式 | IAM | 标准身份断言 | 自行决定 Account 业务权限 |
| Report Exporter | 将已授权报表结果导出到目标系统 | RPT、EXT | 文件或外部任务结果 | 重新计算权威指标 |

## 4. 插件清单字段

| 字段组 | 必须声明 |
|---|---|
| 身份 | plugin_id、name、publisher、version、contract_version |
| 兼容 | min_system_version、max_system_version、required_features |
| 权限 | required_scopes、optional_scopes、data_classes |
| 能力 | provided_capabilities、commands、queries、subscriptions |
| 入口 | configuration_schema、callback、health、support_url |
| 资源 | timeout、concurrency、rate_limit、payload_size |
| 生命周期 | install、activate、pause、upgrade、rollback、uninstall |
| 安全 | signature、secret_fields、allowed_domains、network_policy |
| 数据 | private_data_policy、retention、export、deletion |

## 5. 权限模型

插件调用必须同时满足：

1. 插件版本受支持；
2. 安装实例属于当前 Account；
3. 安装状态为 active；
4. Account Feature 和套餐允许；
5. 操作主体具备对应业务权限；
6. 插件已获得所需 Scope；
7. 目标 Inbox、Team 或对象在授权范围内；
8. 数据敏感等级允许向该插件提供；
9. 请求未超过限流、并发和额度；
10. 高风险动作已完成必要确认。

不能因为插件使用平台身份而跳过 Account、角色或对象权限。

## 6. 插件事件订阅

- 插件只能订阅清单声明且安装时授权的事件；
- 事件必须经过字段最小化和敏感信息过滤；
- 每次投递包含 installation_id、event_id、event_version 和签名；
- 插件按 event_id 幂等处理；
- 投递超时和失败由 EXT 独立重试；
- 连续失败达到阈值后暂停订阅并通知；
- 插件恢复后只补发保留窗口内事件；
- 插件卸载后立即停止新事件并按政策清理私有数据。

## 7. 插件调用隔离

| 隔离项 | 要求 |
|---|---|
| 时间 | 每类调用有超时和总耗时上限 |
| 并发 | 每 Account、安装实例和能力分别限制 |
| 重试 | 仅重试暂时错误，不重试永久拒绝 |
| 幂等 | 不可逆动作必须有 invocation_id 和业务去重键 |
| 网络 | 只允许声明域名和协议 |
| 数据 | 只传递该动作所需最小字段 |
| 凭证 | 密钥由 EXT 管理，业务模块不保存插件密钥 |
| 故障 | 插件失败不回滚已成功的核心业务事实 |
| 审计 | 安装、授权、调用、配置、暂停和卸载全部可追踪 |

## 8. 插件生命周期

### 8.1 安装

1. 验证插件签名、发布者和版本；
2. 检查系统版本、Feature 和配置；
3. 展示必需与可选 Scope；
4. 完成外部授权和回调验证；
5. 创建 installation，初始为 inactive；
6. 执行连接和权限测试；
7. 启用事件与能力；
8. 真实业务闭环通过后进入 active。

### 8.2 升级

1. 比较合同、权限、配置和数据迁移变化；
2. 新增 Scope 必须重新确认；
3. 在独立安装实例验证；
4. 灰度部分 Account；
5. 观察失败率和业务差异；
6. 完成后切换版本；
7. 保留允许期限内回退能力。

### 8.3 停用与卸载

1. 停止新调用和事件；
2. 等待或取消运行中的 Invocation；
3. 撤销第三方授权和密钥；
4. 导出或清理插件私有数据；
5. 保留必要审计和外部引用；
6. 验证核心业务仍能运行；
7. 到期后移除兼容合同。

## 9. 插件降级规则

- Channel Adapter 不可用：对应 Inbox 进入 warning/disconnected，其他 Inbox 正常；
- AI Provider 不可用：切换回退模型或转人工；
- Notification Channel 不可用：保留站内通知并记录外部投递失败；
- Integration Connector 不可用：核心会话继续，外部动作进入失败或待补偿；
- Automation Action 不可用：该动作失败，规则按 failure_policy 继续或停止；
- Knowledge Source 不可用：保留最后成功版本并标记过期；
- Report Exporter 不可用：报表结果仍可查询，只影响目标导出。

## 10. ARCH-05 完成判定

- [ ] 所有扩展能力进入标准扩展点之一；
- [ ] 插件没有直接访问核心模块内部存储；
- [ ] 清单、Scope、敏感等级、限流和审计字段完整；
- [ ] 安装、升级、回退、停用和卸载流程完整；
- [ ] 插件事件和动作具备签名、幂等、超时和失败隔离；
- [ ] 插件关闭后核心客服仍可运行；
- [ ] 高风险插件动作有明确确认和补偿；
- [ ] 未登记的私有扩展入口为 0。
