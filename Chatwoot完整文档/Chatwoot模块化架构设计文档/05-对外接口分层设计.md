# 对外接口分层设计

> 架构任务：ARCH-06。所有外部调用必须先经过访问层，再进入模块公开合同，不能直接触达内部数据或领域状态。

## 1. 分层目标

对外接口同时服务工作台、网站聊天、自建客户界面、多租户平台、第三方回调、插件和实时客户端。它们可以使用不同身份和字段视图，但最终必须进入同一业务 Command 和 Query，不能形成多套互相冲突的业务实现。

## 2. 对外接口层级

| 层级 | 名称 | 责任 | 不允许承担 |
|---:|---|---|---|
| E1 | 入口与传输 | 域名、协议、请求大小、基础限流、连接管理 | 业务权限和对象状态转换 |
| E2 | 身份与客户端类型 | 识别 Account、Widget、Public、Platform、Callback、Plugin、Realtime 身份 | 替代领域权限 |
| E3 | 合同与版本 | 路径、方法、字段、分页、错误、幂等和兼容转换 | 保存业务对象 |
| E4 | 应用授权 | 联合 Account、Role、Inbox、Feature、套餐、Scope 和对象范围 | 复制对象所有者规则 |
| E5 | 应用组合 | 调用一个 Command/Query 或启动 ORC 流程；组合查询视图 | 跨模块共享事务 |
| E6 | 领域模块 | 执行唯一业务规则和生命周期 | 识别页面或客户端表现 |
| E7 | 事件与投影 | 发布事实，更新实时、Webhook、报表、搜索和审计 | 反向改变已完成事实 |

## 3. 接口族边界

| 接口族 | 主要身份 | 数据范围 | 允许用途 | 禁止用途 |
|---|---|---|---|---|
| Account API | Account 成员身份 | 成员有权访问的 Account、Inbox、Team 和对象 | 工作台和账号业务管理 | 安装级管理、冒充客户 |
| Widget API | Widget 会话身份 | 一个网站 Inbox、一个 Contact 及其允许会话 | 网站聊天 | 管理成员、读取其他客户 |
| Public API | Inbox 与客户公开身份 | 指定 Inbox 下当前客户资源 | 自建客户界面 | Account 管理和跨客户查询 |
| Platform API | Platform App 身份 | 平台应用获准管理的 Account、User 和关系 | 多租户控制面 | 直接读取客服消息，除非有明确 Scope |
| Admin API | 安装管理身份 | 安装实例和允许的全局资源 | 配置、版本、平台管理和诊断 | 绕过 Account 业务审计 |
| Plugin Capability API | 插件安装身份 + 操作主体 | 清单和 Scope 授权范围 | 调用公开能力 | 读取模块内部存储 |
| Provider Callback | Provider 验签身份 | 对应连接和 Provider 事件 | 入站消息、状态、支付和授权结果 | 任意业务查询 |
| Webhook Delivery | 系统签名 | 订阅允许的最小事件字段 | 向外通知业务事实 | 接收外部 Command |
| Realtime | pubsub 或账号订阅身份 | 当前客户或成员可见事件 | 即时更新和游标确认 | 作为唯一事实来源或直接写业务状态 |

## 4. API 模块责任

API 模块拥有：

- 外部凭证和客户端类型识别；
- API 合同版本和路径到应用动作的映射；
- 请求字段解析、基本格式校验和响应封装；
- idempotency receipt；
- 客户端、凭证、Account 和入口级限流；
- 旧字段、旧路径和旧枚举的兼容转换；
- 外部请求追踪和 correlation_id；
- 对外错误映射；
- 公开字段视图和敏感字段过滤。

API 模块不拥有：

- Account、Contact、Conversation、Message 等对象；
- 会话状态、消息发送、客户合并或分配规则；
- Provider Token 和插件 Secret；
- 报表指标计算；
- AI 模型选择；
- 跨模块业务补偿。

## 5. 请求处理顺序

1. E1 检查协议、来源、大小和基础频率；
2. E2 验证身份、签名、Token 或 Widget/Public 会话；
3. E3 选择合同版本并解析 Path、Query、Header 和 Body；
4. E4 计算 Account、Role、Inbox、Feature、套餐、Scope 和对象范围；
5. 检查幂等收据和重复请求；
6. 单模块动作进入该模块 Command；
7. 跨模块动作启动 ORC 流程；
8. Query 按权威或投影视图读取；
9. 将模块错误映射为接口错误；
10. 返回完成结果或可查询异步任务；
11. 业务 Event 进入实时、Webhook、报表、搜索和审计；
12. 超时后通过 request_id/correlation_id 查询，不盲目重试。

## 6. 聚合接口规则

一个会话详情可能需要 CON、CUS、CHN、RTE、MSG、RPT 等模块信息。聚合时必须：

- 标明每组字段的权威来源；
- 以 conversation_id、contact_id、inbox_id 等稳定引用组合；
- 为允许延迟的投影返回更新时间或版本；
- 任一可选模块不可用时，返回明确的部分不可用信息；
- 不在 API 模块保存第二份权威对象；
- 不为减少调用而建立无法重建的私有综合表；
- 写操作仍拆回各所有者的 Command。

## 7. Provider Callback 分层

1. 入口按 Provider 和路径找到连接；
2. 验证签名、时间窗、challenge 和来源；
3. 保存 Callback Receipt，按外部 event_id 去重；
4. 适配器将 Provider Payload 转换为标准入站事实或状态结果；
5. API/ORC 根据类型调用 CUS、CON、MSG、CHN、BIL 等权威模块；
6. 尽快向 Provider 返回接收结果；
7. 后续失败通过内部任务补偿，不要求 Provider 长时间等待；
8. 未知字段安全保存诊断摘要，不破坏整个批次；
9. 回调不得携带可直接修改任意 Account 的内部 ID。

## 8. 版本设计

| 变化 | 版本处理 |
|---|---|
| 新增可选响应字段 | 当前版本兼容追加 |
| 新增可选请求字段 | 当前版本兼容追加并有默认行为 |
| 删除字段 | 新主版本；旧版进入弃用期 |
| 改变字段语义或单位 | 新主版本 |
| 新增枚举 | 使用方必须能处理 unknown；必要时提高次版本 |
| 改变身份或权限范围 | 新合同并重新授权 |
| 改变幂等或副作用 | 新主版本和迁移说明 |
| Provider 特有变化 | 适配器版本变化，对外公共合同尽量保持 |

## 9. 对外错误分层

| 层级 | 典型错误 |
|---|---|
| E1 | 请求过大、协议不支持、基础限流 |
| E2 | Token、签名、Session 或客户端身份错误 |
| E3 | 路径、版本、字段、分页或格式错误 |
| E4 | Account、Role、Inbox、Feature、套餐、Scope 或对象权限错误 |
| E5 | 流程冲突、依赖不可用、结果未知 |
| E6 | 业务状态冲突、唯一约束、Provider 永久失败 |
| E7 | 副作用延迟、投影过期、部分投递失败 |

不能把所有错误都转换成一个通用失败，否则外部使用方无法安全重试。

## 10. ARCH-06 完成判定

- [ ] 九类接口族的身份和范围明确；
- [ ] 所有外部写入映射到唯一 Command 或 ORC 流程；
- [ ] API 模块不拥有任何领域对象；
- [ ] 聚合接口字段可以追溯到所有者；
- [ ] Provider Callback 有验签、去重、转换和补偿；
- [ ] 版本、幂等、限流、错误和敏感字段规则完整；
- [ ] 旧入口与新入口进入同一业务动作；
- [ ] 外部入口直接访问内部存储的数量为 0。
