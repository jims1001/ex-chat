# 模块独立拆分与独立运行验收

> 架构任务：ARCH-08。每个模块必须具备独立运行条件，即使当前与其他模块统一部署。

## 1. 独立的含义

模块独立不表示完全没有依赖，而是：

- 依赖全部通过明确合同；
- 不共享权威存储；
- 不要求和其他模块同时提交一个事务；
- 可以单独启动、停止、扩缩和升级；
- 依赖不可用时有明确降级或失败；
- 提取为独立运行单元时不改变业务语义；
- 使用方不需要了解模块内部结构。

## 2. 每个模块必须提供的运行合同

| 类别 | 必备内容 |
|---|---|
| 身份 | module_id、module_version、contract_versions |
| 能力 | 提供的 Command、Query、Event、Feature 和限制 |
| 依赖 | 必需、可选、启动时和运行时依赖 |
| 配置 | 配置键、默认、敏感、作用范围和生效方式 |
| 数据 | 权威对象、存储边界、保留、备份和恢复 |
| 事件 | 发布、订阅、幂等、顺序和重放规则 |
| 运行 | 健康、就绪、维护、容量、扩缩和任务状态 |
| 故障 | 超时、重试、隔离、降级和人工恢复 |
| 版本 | 升级、兼容、数据迁移和回退 |
| 观察 | 业务指标、错误、追踪、审计和告警 |

## 3. 独立存储验收

- 模块只写自己拥有的对象；
- 其他模块 ID 作为普通稳定引用，不要求跨模块约束；
- 引用有效性在 Command 时通过 Query、签名引用或事件投影确认；
- 不存在跨模块联表才能完成的权威写入；
- 不存在跨模块必须同步提交的共享事务；
- 本模块的数据升级可以单独执行；
- 备份和恢复不会覆盖其他模块数据；
- 恢复后可以通过事件重建投影；
- 删除请求和副本清理有独立进度。

## 4. 独立启停矩阵

| 模块 | 停止时核心行为 | 恢复要求 |
|---|---|---|
| IAM | 新登录和身份验证受限；有效短期会话按策略处理 | 会话和撤销状态一致 |
| TEN | 新的账号权限判断不可用时拒绝敏感写入 | 成员和角色版本恢复 |
| ENT | 使用最后有效短期能力快照或保守拒绝高成本动作 | 额度和 Feature 重新对账 |
| CHN | 受影响 Inbox 停止外部收发，内部历史可读 | 健康、Token 和回调补偿 |
| CUS | 新客户和客户修改暂停；既有会话按最小快照展示 | 身份去重后再恢复入站 |
| MED | 新附件暂停，纯文本消息仍可运行 | 补传和孤立引用清理 |
| CON | 不能创建或改变会话；历史消息不应被删除 | 状态和事件版本检查 |
| MSG | 消息收发暂停；其他管理功能可用 | Provider 回执补读和幂等恢复 |
| RTE | 自动分配暂停，允许按策略人工领取或保持排队 | 重算队列和容量 |
| TKT | 工单入口不可用，客服会话继续 | 关联事件补读 |
| QLT | 评价和质检暂停，客服会话继续 | 补收允许窗口内结果 |
| AUT | 自动化暂停，手工操作继续 | 从事件游标继续且不重复 |
| OPS | Macro/Campaign 暂停，普通回复继续 | 恢复计划和逐目标状态 |
| NTF | 外部通知暂停，核心业务继续 | 投递保留窗口内补偿 |
| KB | 帮助中心受限，既有已缓存公开内容按策略 | 索引和发布版本同步 |
| AIC | AI 降级或转人工，人工客服继续 | 模型、额度和知识版本检查 |
| EXT | 插件和 Webhook 暂停，核心业务继续 | 事件保留窗口和授权检查 |
| RPT | 报表和 SLA 投影延迟，核心业务继续 | 事件补读和指标重算 |
| SRH | 搜索不可用，按明确筛选列表降级 | 索引检查点重建 |
| API | 外部入口不可用；内部模块不应因此停止 | 幂等收据和限流状态恢复 |
| RTM | 即时更新停止，客户端使用 REST 补读 | 游标恢复和重复事件处理 |
| MIG | 导入迁移暂停，在线业务继续 | 从检查点恢复 |
| BIL | 新购买暂停；现有权益按策略保持 | 支付回调补读和对账 |
| AUD | Local Capture 不可用时拒绝所有数据写入；Central Ledger 不可用时本地积压并按水位逐级限制 | 补投、摘要链验证和完整对账 |
| SYS | 安装管理入口不可用，Account 业务继续 | 配置版本和缓存一致 |
| ORC | 新跨模块流程暂停，运行流程保持可恢复 | 步骤版本和结果查询后继续 |

## 5. 独立扩缩验收

- 模块容量指标只与自身负载有关；
- 增加模块实例不要求修改其他模块存储；
- 多实例处理 Command 时幂等和对象版本有效；
- Event 消费可以分区，但同一对象的顺序规则明确；
- 定时任务和扫描任务不会被多实例重复执行；
- 扩缩期间连接、会话和异步任务不会丢失；
- 一个高负载模块不会耗尽其他模块的全部资源；
- 限流可以按模块、Account 和能力独立设置。

## 6. 独立升级验收

1. 新版本声明支持的合同版本；
2. 先验证新旧版本读取当前数据；
3. 数据变化使用向前兼容阶段；
4. 灰度部分请求或 Account；
5. 新旧实例并存时业务语义一致；
6. Event 发布版本不会随机变化；
7. 失败时回退不依赖恢复其他模块；
8. 回退后新产生数据仍可解释；
9. 完成后再移除旧合同和旧字段。

## 7. 模块提取验收

将模块从统一部署中独立出来前，必须通过：

- 内部调用全部替换为公开合同；
- 内部存储没有其他模块直接访问；
- 配置和 Secret 已独立归属；
- 权威数据迁移可重复、可对账、可回退；
- Command、Query 和 Event 地址变化对使用方透明；
- 运行中任务在切换前完成、迁移或安全重启；
- 双运行期间只有一个主写者；
- Event 不重复发布；
- 旧入口停止后没有残留使用方；
- 故障时可以切回且不丢切换后的业务事实。

## 8. 单模块验收案例

每个模块至少执行：

1. 无依赖的配置和合同检查；
2. 必需依赖正常时完整功能；
3. 一个必需依赖超时；
4. 一个可选依赖不可用；
5. 完全相同 Command 重复；
6. 同一对象并发 Command；
7. Event 重复、乱序和重放；
8. 模块运行中停止并恢复；
9. 多实例扩缩；
10. 版本升级和回退；
11. 备份恢复和投影重建；
12. Account 隔离和敏感字段验证。

## 9. 提取优先级

| 优先级 | 推荐模块 | 原因 |
|---|---|---|
| 第一组 | MED、NTF、SRH、RPT、AUD | 副作用或投影型，容易验证失败隔离 |
| 第二组 | EXT、AIC、KB、MIG、BIL | 外部依赖明显，适合独立扩缩和安全隔离 |
| 第三组 | RTE、TKT、QLT、AUT、OPS、RTM | 业务边界明确，但需要事件和流程完整 |
| 第四组 | CHN、CUS、CON、MSG | 客服核心，需先完成合同、迁移和高可靠验证 |
| 控制面 | IAM、TEN、ENT、SYS、API、ORC | 影响范围大，应在前述边界稳定后提取 |

优先级不是强制部署顺序，但任何模块都必须达到相同的独立性标准。
