# 重复功能与重复数据检查

> 架构任务：ARCH-09。目标不是消除所有副本，而是消除多个权威来源、重复规则和无法重建的数据。

## 1. 重复分类

| 类型 | 定义 | 处理原则 |
|---|---|---|
| 功能重复 | 两个模块都能决定同一业务动作 | 保留一个所有者，其他改为调用合同 |
| 规则重复 | 同一校验、状态转换或权限判断在多个模块分别维护 | 下沉到权威模块或统一能力判定 |
| 对象重复 | 同一业务实体在多个模块都可独立创建和更新 | 确定主对象，其他改为引用或投影 |
| 状态重复 | 两个模块都认为自己拥有最终状态 | 指定唯一状态所有者，其他只保存版本快照 |
| 数据双写 | 一个请求直接修改两个模块的权威数据 | 由 ORC 分步 Command 和补偿 |
| 投影重复 | 搜索、报表、缓存保存可重建副本 | 允许，但必须登记来源和重建 |
| 文案重复 | 多处显示相同名称或摘要 | 允许快照，但不得用于业务判断 |
| 历史兼容重复 | 新旧 ID、字段或入口并存 | 限时允许，必须指向同一业务动作和退役时间 |

## 2. 高风险重复清单

| 业务概念 | 容易重复的位置 | 唯一所有者 | 其他模块处理 |
|---|---|---|---|
| 登录用户 | IAM、TEN、SYS | IAM | TEN 只保存 membership 和 user_id |
| Account 权限 | TEN、API、各业务模块 | TEN 定义；业务模块最终校验 | API 只做前置组合，不能替代所有者 |
| Feature 和额度 | ENT、BIL、AIC、OPS | ENT | BIL 发布购买事实，使用方提交用量 |
| Inbox 状态 | CHN、MSG、API、EXT | CHN | 其他保存短期健康摘要 |
| 客户渠道身份 | CUS、CHN、MSG | CUS | CHN/MSG 只传 source_id |
| 当前会话状态 | CON、RTE、AUT、API | CON | 其他通过 Command 改变或保存投影 |
| 当前分配 | CON、RTE、NTF | RTE | CON/API 聚合显示，不能反向写 |
| 消息发送状态 | MSG、CHN Adapter、EXT | MSG | Adapter 报告 Provider 结果 |
| 媒体资源 | MED、MSG、KB、AIC | MED | 其他保存 asset_id |
| 工作时间 | CHN、RTE、RPT | CHN | RTE/RPT 读取版本化规则或快照 |
| 标签定义 | CUS、CON、AUT | CUS | CON 保存使用关系，AUT 只引用 label_id |
| CSAT | QLT、RPT、CON | QLT | RPT 聚合，CON 展示摘要 |
| SLA | RPT、CON、AUT | RPT | CON 展示，AUT 订阅 breach 事件 |
| 知识原文 | KB、AIC、SRH | KB | AIC/SRH 保存索引和版本引用 |
| AI 用量 | AIC、ENT、BIL、RPT | AIC 产生事实，ENT 拥有额度余额 | BIL/RPT 消费事实，不重算余额 |
| Webhook Delivery | EXT、AUT、API | EXT | AUT 只触发配置的 Webhook 能力 |
| 通知未读 | NTF、CON、API | NTF | API 聚合，CON 不保存通知未读数 |
| 数据变更与审计历史 | AUD、各模块 Local Journal 和运行日志 | AUD 的集中不可变账本 | Local Journal 只负责待投递和恢复，运行日志不替代审计，均不能成为第二永久账本 |
| 搜索结果 | SRH、各模块列表 | SRH 仅为搜索投影 | 详情必须回到权威 Query |
| 迁移映射 | MIG、各目标模块 | MIG | 目标只保存必要 source reference |

## 3. 功能重复检查步骤

1. 从功能总表提取每个用户可执行动作；
2. 为动作指定一个主责模块和 Command；
3. 搜索所有其他模块中同义动作；
4. 判断是入口别名、流程步骤、投影动作还是违规重复；
5. 入口别名统一进入同一 Command；
6. 流程步骤交给 ORC；
7. 投影动作改为 Event 消费；
8. 违规重复移除或进入限时兼容；
9. 记录替换、迁移和回归范围；
10. 对相同动作从不同入口执行结果对账。

## 4. 数据重复检查步骤

1. 列出每个模块保存的对象和字段；
2. 按业务含义归并同义名称；
3. 对每项标记 authoritative、reference、snapshot、projection、cache 或 legacy；
4. 检查是否存在两个 authoritative；
5. 检查副本是否带 source_id、source_version 和更新时间；
6. 检查副本能否从 Event 或 Query 重建；
7. 检查副本是否被错误用于业务写入判断；
8. 检查删除、合并和权限变化能否传播；
9. 检查新旧字段兼容是否有退役时间；
10. 双权威、不可重建副本和永久 legacy 必须清零。

## 5. 允许副本的登记格式

| 字段 | 内容 |
|---|---|
| copy_id | 副本登记编号 |
| holder_module | 持有模块 |
| source_module | 权威模块 |
| source_object | 权威对象 |
| copied_fields | 复制字段及用途 |
| source_version | 最近应用的对象版本 |
| refresh | Event、Query、周期重建或一次性快照 |
| max_staleness | 最大允许延迟 |
| write_protection | 如何保证副本不可成为权威写入口 |
| deletion | 删除、脱敏和合并传播规则 |
| rebuild | 完整重建方式 |
| owner | 维护责任模块 |

## 6. 禁止的“公共模块”膨胀

以下内容不能因为多个模块都需要而放入公共协议层：

- 会话状态转换；
- 统一客户查重规则；
- 消息 Provider 状态映射；
- 分配候选算法；
- 权限和 Feature 完整业务判断；
- 自动化动作执行；
- SLA 指标公式；
- AI 模型回退；
- 插件授权生命周期。

这些能力必须由对应权威模块通过合同提供。公共协议层只能保留无业务语义的类型和封装。

## 7. 合理复用与错误复用

| 情况 | 判断 |
|---|---|
| 多个入口调用同一个 Command | 合理复用 |
| 多个模块分别实现同一状态转换 | 功能重复 |
| 报表和搜索保存事件投影 | 允许冗余 |
| 两个模块都能更新同一客户邮箱 | 数据双权威 |
| 统一错误、ID 和时间协议 | 合理公共能力 |
| 把所有业务工具集中到 shared/service | 公共模块膨胀 |
| Adapter 转换 Provider 字段 | 合理隔离 |
| Adapter 自己创建核心 Message | 越界重复 |

## 8. 检查频率

- 新模块设计时；
- 新增业务对象或状态时；
- 新增插件扩展点时；
- 增加对外接口版本时；
- 拆分或合并模块时；
- 数据迁移前后；
- 发现跨模块直接写入时；
- 每次系统主版本关门前。

## 9. ARCH-09 完成判定

- [ ] 所有业务动作只有一个主责 Command；
- [ ] 所有对象和状态只有一个 authoritative；
- [ ] 所有允许副本均已登记来源、版本和重建方式；
- [ ] 跨模块双写为 0；
- [ ] 使用投影反向修改权威数据的入口为 0；
- [ ] 永久未退役 legacy 副本为 0；
- [ ] 公共协议层没有领域规则；
- [ ] 功能重复和数据重复未解释项为 0。
