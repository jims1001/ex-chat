## Query contract

POST `/contracts/queries/ops.canned_response.preview.v1` uses the existing authenticated allowlisted module-caller transport. Strict envelope decoding uses precise JSON numbers and rejects unknown fields. Actor is a canonical positive decimal User with auth_source `module`. Query must validate, account ID must fit positive signed 64-bit, consistency is `strong`, sort is exactly `["id"]`, page is `"1"`, and cursor is empty. Fields are exactly `["id","account_id","short_code","object_version","resolved_content"]` in that order. Filter has exactly `id` and `variables`: id is a canonical positive JSON integer within signed 64-bit (not a string, float or exponent); variables is a non-null JSON object with valid variable names and string values, including empty strings. No coercion, expressions, nested objects, defaults, auto-fetch or target changes. Validation applies to decoded JSON strings: the existing Go JSON codec repairs invalid UTF-8 bytes and unpaired surrogate escapes to U+FFFD before validation. Direct invocation rejects invalid UTF-8 strings.

Every invocation checks current TEN account membership through the same helper as canned-response reads and management. No membership caching or receipt path. Missing, revoked or mismatched membership denies access; missing or failed TEN dependency fails closed. Only after admission, read the same-account source through existing `ReadBounded(detail_versioned)`: content and object version are obtained in one bounded SQL projection. Missing, foreign or deleted records return 404. Legacy version 0 can be previewed and remains unmodifiable by runtime management. Negative/corrupt or over-bound stored data fails closed as 503.

Response data contains exactly id, account_id, short_code, object_version and resolved_content. Integer identity and version remain exact on the wire, including odd values above 2^53. This is a point-in-time source snapshot, not a send permit or a reservation: changes/deletion or TEN revocation after admission are not locked out. Any future send must independently validate all current MSG/CON/channel permissions and state.

## Minimal grammar and visible errors

Placeholders are exactly `{{name}}`, where name matches ASCII `[A-Za-z_][A-Za-z0-9_]*`, case-sensitive. No whitespace trimming, dotted lookup, nested syntax, filters, expressions, escaping, or recursive interpolation. Single braces and all other text are literal. Any `{{` or `}}` delimiter not forming an exact placeholder is malformed, including orphan closes, nested opens, empty names, whitespace names, invalid characters or unclosed opens. There is no template escape syntax in v1; literal delimiter text can be supplied as a variable value. Unicode text and values are preserved exactly. Replacement strings are appended as literal text and never scanned again. Extra valid variables are harmless and allowed.

Rendering stops at the first error in source order, so diagnostics are deterministic and bounded. For example, `{{{name}}}` is malformed; `{{name}}}` resolves the variable then leaves one literal closing brace; `{name}` is literal; `{{name}}{{name}}` repeats substitution. Malformed template or missing variable returns HTTP 400 `validation_failed` with a stable, visible reason and the zero-based UTF-8 byte offset in the stored source; no partial resolved content is returned. Errors do not echo source content, variable values, or arbitrarily large names. An empty supplied string resolves successfully; an absent key fails. HTML-like text remains ordinary text: no HTML evaluation, escaping/unescaping or sanitization semantics beyond normal JSON serialization. Consumers must display resolved_content as text, never innerHTML.

## Resource and cancellation bounds

Reuse the existing 1 MiB canned-response read engineering budget. Existing configured HTTP request size remains authoritative. Additionally, direct query invocation validates aggregate decoded variable-name plus value bytes at at most 1 MiB with overflow-safe arithmetic. No new stored-content business limit or CRUD validation is added. Rendering performs a single linear source scan, checking context at entry, at regular bounded scan intervals (at most 4096 source bytes), before large append operations, and at completion. Variable-name validation also checks context at bounded byte intervals; a single JSON encoding is bounded by the already-limited data (at most roughly sixfold JSON escape growth), with context checked immediately before and after encoding. Never allocate output beyond 1 MiB decoded bytes; reject expansion before append. Marshal the complete five-field response data and require its actual encoded size (including JSON escape expansion) to be at most 1 MiB. This bound is on response data; the unchanged common transport adds its correlation envelope. Bounded read, renderer, and final checks propagate cancellation; transport keeps its existing configured timeout.
