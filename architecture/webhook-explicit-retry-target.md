# Webhook 显式重试目标（第62批重建）

这是从已持久化第61批重新实现的版本，不是找回丢失的旧第62批提交。原始历史保留；验证必须来自当前源码的全新执行。

## 边界与顺序

1. 现有 V1 路由仍先校验认证、账户成员及原有权限规则（settings_manage 自定义权限或既有 RoleAgent 回退）。
2. 带 `:id` 的请求必须解析为本机 uint 可表示的正十进制 ID；非法、零、负数和溢出返回400。无 ID 路由仍用服务参数0表示旧选择方式。
3. 服务不可用返回503，不制造投递成功。
4. 正 ID 仅查询 EXT 存储中相同 account_id 与 id 的投递。缺失或跨账户返回404；其他目标读取错误返回通用500，包括已填充实体后报告错误的情况。
5. 失败时不退回最新投递、不创建 manual.retry 记录、不修改尝试计数/状态，也不发出 HTTP。正确目标才进入原有发送流程。

## 兼容与明确非目标

有服务时，无 ID 路由选择最新账户投递；没有投递而有 webhook 时保留原 manual.retry 创建方式。已有成功响应字段、签名、事件、payload 和发送结果处理保持不变。

本批不修改后续 webhook secret 读取、发送后保存错误处理、持久 claim、未知发送结果、并发重试、取消、补偿或幂等策略。目标读取成功也不保证后续持久化成功。

## 新验证义务

普通/race 测试使用隔离 SQLite EXT 表、真实 HTTP 路由及无服务 handler。原生 PostgreSQL 复用相同业务断言，覆盖真实缺表和读取后故障。完整快照、写调用计数和合成 HTTP 调用数共同验证没有误重试与提前副作用。新增29条原生路径必须逐条执行通过，不能复用历史批次计数作为证明。
